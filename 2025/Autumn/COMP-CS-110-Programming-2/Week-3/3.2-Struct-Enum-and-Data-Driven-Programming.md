## Struct - Custom Data Types

### Record Types Concept

Struct allows you to group different data types into a single custom type. It's like a primitive version of classes - there's no function interface, but all fields can be accessed directly.
```cpp
struct Product {
    string product_name;
    double price;
};

// Usage
Product item = {"soap", 1.23};
item.price = 0.9 * item.price;  // 10% discount
cout << item.product_name << ": " << item.price << endl;
```

### TypeScript Comparison
```typescript
// TypeScript interface (similar concept)
interface Product {
    product_name: string;
    price: number;
}

const item: Product = {
    product_name: "soap",
    price: 1.23
};

item.price = 0.9 * item.price;
```

## Why Struct Over Vector?
```cpp
struct Person {
    string forename;
    string surname;
    string address;
    string email;
};
```

Even though all fields are strings, using a struct is better than `vector<string>` because:

- ✅ **Named fields** instead of numeric indices
- ✅ **Clear semantics** - each field has meaning
- ✅ **Type safety** - prevents mixing up field order

**Rule:** Don't store semantically different data in vectors just because they share the same type.

**Bad example:**
```cpp
// ❌ Unclear and error-prone
vector<string> person = {"John", "Doe", "123 Main St", "john@example.com"};
cout << person[2];  // What is index 2? Address? Email?
```

**Good example:**
```cpp
// ✅ Clear and safe
Person person = {"John", "Doe", "123 Main St", "john@example.com"};
cout << person.address;  // Obvious what this is
```

## Enum Class - Restricted Value Sets

### Basic Enumeration

Sometimes variables should only accept specific values. Enum class provides type-safe way to define limited value sets.
```cpp
enum class Book_status { ON_THE_SHELF, BORROWED, RESERVED, LOST };

Book_status status = Book_status::ON_THE_SHELF;
```

### Benefits Over Constants
```cpp
// ❌ Poor approach - allows any integer
const int RED = 0;
const int YELLOW = 1;
const int GREEN = 2;

int light = RED;
light = 999;  // Oops! Invalid but compiles

// ✅ Better approach - only defined values allowed
enum class TrafficLight { RED, YELLOW, GREEN };

TrafficLight light = TrafficLight::RED;
// light = 999;  // ❌ Compile error!
```

### TypeScript Comparison
```typescript
// TypeScript enum
enum BookStatus {
    ON_THE_SHELF = "on_shelf",
    BORROWED = "borrowed",
    RESERVED = "reserved",
    LOST = "lost"
}

// Or union types (more common in modern TypeScript)
type TrafficLight = "red" | "yellow" | "green";
```

## Enum Iteration and Conversion

### Automatic Numbering

C++ automatically assigns integer values starting from zero:
```cpp
enum class Weekday { MON, TUE, WED, THU, FRI, SAT, SUN };
// MON = 0, TUE = 1, ..., SUN = 6
```

### Type Conversion with static_cast
```cpp
const int DAYS_IN_A_WEEK = static_cast<int>(Weekday::SUN) + 1;

Weekday next_weekday(Weekday day) {
    return static_cast<Weekday>((static_cast<int>(day) + 1) % DAYS_IN_A_WEEK);
}
```

The modulo operator (`%`) ensures cyclic behavior: after `SUN` comes `MON` again.

### Iteration Patterns
```cpp
// Traditional loop with enum
for (Weekday day = Weekday::MON; day <= Weekday::SUN; day = next_weekday(day)) {
    cout << "Day: " << static_cast<int>(day) << endl;
    if (day == Weekday::SUN) break;
}

// Range-based for with specific values
for (Weekday day: { Weekday::WED, Weekday::MON, Weekday::FRI }) {
    cout << "Selected day: " << static_cast<int>(day) << endl;
}
```

## Data-Driven Programming

### The Philosophy

Data-driven programming replaces repetitive control structures (long if-else chains) with data structures. Instead of writing code, you define data that describes the behavior.

### Problem: Repetitive Control Logic
```cpp
// ❌ Version 1: Command-heavy approach
PostalAbbr name_to_abbreviation(const string& name) {
    if (name == "Alabama") {
        return PostalAbbr::AL;
    } else if (name == "Alaska") {
        return PostalAbbr::AK;
    } else if (name == "Arizona") {
        return PostalAbbr::AZ;
    }
    // ... 47 more states
    else {
        return PostalAbbr::ERROR_CODE;
    }
}
```

### Solution: Data-Driven Approach
```cpp
// ✅ Version 2: Data-driven approach
struct StateInfo {
    string name;
    PostalAbbr abbreviation;
};

const vector<StateInfo> STATES = {
    { "Alabama", PostalAbbr::AL },
    { "Alaska", PostalAbbr::AK },
    { "Arizona", PostalAbbr::AZ },
    // ... rest of states
};

PostalAbbr name_to_abbreviation(const string& name) {
    for (auto state : STATES) {
        if (name == state.name) {
            return state.abbreviation;
        }
    }
    return PostalAbbr::ERROR_CODE;
}
```

### TypeScript Example
```typescript
// Similar approach in TypeScript
interface StateInfo {
    name: string;
    abbreviation: string;
}

const STATES: StateInfo[] = [
    { name: "Alabama", abbreviation: "AL" },
    { name: "Alaska", abbreviation: "AK" },
    // ...
];

function nameToAbbreviation(name: string): string | null {
    const state = STATES.find(s => s.name === name);
    return state?.abbreviation || null;
}

// Or using Map for O(1) lookup
const STATE_MAP = new Map([
    ["Alabama", "AL"],
    ["Alaska", "AK"],
    // ...
]);
```

## Benefits of Data-Driven Programming

### Key Advantages

- ✅ **Shorter code** while maintaining clarity
- ✅ **Fewer errors** - less duplication means fewer bugs
- ✅ **Easier maintenance** - changes in one place
- ✅ **Simpler expansion** - add data, not code

### When to Apply

Look for these patterns that suggest data-driven solutions:

- Long if-else or switch statements
- Repetitive conditional logic
- Code that frequently needs new cases added
- Business rules that change often

### Recognition Signs
```cpp
// ❌ This pattern suggests data-driven approach
if (status == "pending") { /* ... */ }
else if (status == "approved") { /* ... */ }
else if (status == "rejected") { /* ... */ }
else if (status == "cancelled") { /* ... */ }
// ... many more cases
```

**Better approach:** Define status configurations in data structure and use generic processing logic.

## Practical Implementation Strategy

### Design Process

1. Identify repetitive patterns in conditional logic
2. Extract variable data from the conditions
3. Create struct to hold the varying data
4. Replace conditionals with data lookup
5. Use simple loop for processing

### Example: Discount System
```cpp
// Data-driven discount rules
struct DiscountRule {
    string customer_type;
    double min_amount;
    double discount_rate;
};

const vector<DiscountRule> DISCOUNT_RULES = {
    { "regular", 1000, 0.05 },
    { "premium", 500, 0.10 },
    { "vip", 0, 0.20 }
};

double calculate_discount(const string& customer_type, double amount) {
    for (auto rule : DISCOUNT_RULES) {
        if (rule.customer_type == customer_type && amount >= rule.min_amount) {
            return rule.discount_rate;
        }
    }
    return 0.0;
}
```

## Combining Struct and Enum

Structs and enums work great together:
```cpp
enum class Priority { LOW, MEDIUM, HIGH, CRITICAL };

struct Task {
    string description;
    Priority priority;
    bool completed;
};

vector<Task> tasks = {
    { "Fix bug", Priority::CRITICAL, false },
    { "Write docs", Priority::MEDIUM, false },
    { "Refactor code", Priority::LOW, false }
};

// Filter by priority
for (const auto& task : tasks) {
    if (task.priority == Priority::CRITICAL && !task.completed) {
        cout << "URGENT: " << task.description << endl;
    }
}
```

## Summary

- **Struct groups related data** - like interfaces in TypeScript
- **Enum class restricts values** - type-safe constants
- **Named fields beat indices** - clarity over vectors
- **Data-driven beats if-else chains** - maintainability and scalability
- **Combine struct + enum** - powerful data modeling
- **Extract patterns to data** - reduce code duplication

Data-driven programming transforms complex control logic into simple data definitions, making code more maintainable and reducing the likelihood of errors.
