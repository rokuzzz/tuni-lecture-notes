## The Integer Overflow Problem

### Factorial Example - Same Logic, Different Results

**TypeScript version:**
```typescript
function main(): void {
    const number = parseInt(prompt("Input a number: ") || "0");
    
    if (number < 0) {
        console.log("Must be non-negative!");
    } else {
        let result = 1;
        for (let i = 1; i <= number; i++) {
            result = result * i;
        }
        console.log("Factorial is:", result);
    }
}
```

**C++ version:**
```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "Input a number: ";
    int number = 0;
    cin >> number;
    
    if (number < 0) {
        cout << "Must be non-negative!" << endl;
    } else {
        int result = 1;
        while (number > 0) {
            result = result * number;
            --number;
        }
        cout << "Factorial is: " << result << endl;
    }
}
```

### The Problem: Different Results

**Input:** 17

**Python/TypeScript:** 355687428096000 ✅ Correct  
**C++:** -288522240 ❌ Wrong (negative!)

## Understanding Integer Overflow

### Why This Happens

**Python/TypeScript:**
- Unlimited or very large integer size
- Can handle huge numbers

**C++:**
- Fixed 32-bit integers (usually)
- Range: **-2,147,483,648 to 2,147,483,647**
- When exceeded → wraps around to negative!

### Car Odometer Analogy

Think of integer overflow like a car's odometer:
```
999999 km → 000000 km (rolls back to zero)
```

Similarly in C++:
```
2,147,483,647 + 1 → -2,147,483,648 (wraps to minimum)
```

The number doesn't just stop at the maximum - it wraps around to the minimum value and continues counting from there!

## C++ Integer Types

### Integer Type Comparison Table

| Type                | Typical Size | Range (32-bit systems)              |
|---------------------|--------------|-------------------------------------|
| `int`               | 4 bytes      | -2,147,483,648 to 2,147,483,647     |
| `unsigned int`      | 4 bytes      | 0 to 4,294,967,295                  |
| `short int`         | 2 bytes      | -32,768 to 32,767                   |
| `long int`          | 4-8 bytes    | At least -2,147,483,648 to 2,147,483,647 |
| `long long int`     | 8 bytes      | -9,223,372,036,854,775,808 to 9,223,372,036,854,775,807 |

### Usage Examples
```cpp
int temperature = -10;              // Can be negative
unsigned int age = 25;              // Always positive
long int big_number = 3000000000L;  // Large numbers
```

### TypeScript Comparison
```typescript
// All numbers are the same type
let temperature: number = -10;

// For extremely large numbers:

```

## When to Use Different Types

### Use `int` when:
- Values are in the range -2 billion to +2 billion
- Negative values are possible
- Standard choice for most programs

### Use `unsigned int` when:
- Values will never be negative
- Need to represent values up to 4 billion
- Examples: population counts, array sizes, IDs

### Use `long long int` when:
- Need to handle very large numbers
- Working with calculations that could overflow `int`
- Examples: factorials, large scientific calculations

## Overflow Demonstration
```cpp
#include <iostream>
using namespace std;

int main() {
    int max_int = 2147483647;
    cout << "Maximum int: " << max_int << endl;
    cout << "Max + 1: " << max_int + 1 << endl;  // Wraps to -2147483648!
    
    unsigned int max_uint = 4294967295;
    cout << "Maximum unsigned int: " << max_uint << endl;
    cout << "Max + 1: " << max_uint + 1 << endl;  // Wraps to 0!
}
```

**Output:**
```
Maximum int: 2147483647
Max + 1: -2147483648
Maximum unsigned int: 4294967295
Max + 1: 0
```

## Safe Factorial Implementation

To avoid overflow for larger factorials, use `long long int`:
```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "Input a number: ";
    int number = 0;
    cin >> number;
    
    if (number < 0) {
        cout << "Must be non-negative!" << endl;
    } else {
        long long int result = 1;  // Use long long instead of int
        for (int i = 1; i <= number; i++) {
            result = result * i;
        }
        cout << "Factorial is: " << result << endl;
    }
}
```

This works correctly for factorial up to 20! Still overflows after that, but gives correct results for more values.

## Checking for Overflow

### Before Multiplication
```cpp
long long int result = 1;
for (int i = 1; i <= number; i++) {
    // Check if multiplication would overflow
    if (result > LLONG_MAX / i) {
        cout << "Warning: Overflow would occur!" << endl;
        break;
    }
    result = result * i;
}
```

### Using Limits
```cpp
#include <limits>
#include <iostream>
using namespace std;

int main() {
    cout << "int max: " << numeric_limits<int>::max() << endl;
    cout << "int min: " << numeric_limits<int>::min() << endl;
    cout << "unsigned int max: " << numeric_limits<unsigned int>::max() << endl;
    cout << "long long max: " << numeric_limits<long long>::max() << endl;
}
```

## Key Takeaways

1. **C++ integers have fixed size** - can overflow without warning
2. **Overflow gives wrong results** - no error message by default!
3. **Choose appropriate types** - consider maximum values you need
4. **TypeScript is safer** - much larger range before problems occur
5. **Always test with large inputs** - catch overflow bugs early

## Best Practices
```cpp
// For normal use:
int count = 0;

// For always-positive values:
unsigned int population = 50000;

// For large calculations:
long long int factorial_result = 1;

// Check limits when needed:
#include <limits>
if (value > numeric_limits<int>::max()) {
    // Handle overflow case
}
```

## Summary

Integer overflow is a silent killer in C++ programs. Unlike TypeScript which handles large numbers automatically, C++ requires you to:

- Understand the range of your data types
- Choose appropriate types for your data
- Test with boundary values
- Consider overflow in calculations
- Use larger types (`long long int`) when needed

The key is **awareness** - once you know overflow can happen, you can design your programs to avoid it.
