## Reference Semantics vs Value Semantics

### TypeScript's Hybrid Approach

TypeScript uses different semantics depending on the data type.

**Objects use reference semantics:**
```typescript
const storage = { value: 42 };
const a = storage;
const b = a;           // Both reference same object

a.value = 100;
console.log(b.value);  // Prints: 100
```

**Primitives use value semantics:**
```typescript
let x = 42;
let y = x;             // Creates copy

y = 100;
console.log(x, y);     // Prints: 42 100
```

This mixed approach means objects behave like references while primitives behave like values.

### C++ Value Semantics

C++ uses **value semantics by default**. The assignment operator creates separate copies of data:
```cpp
int a = 42;
int b = a;      // Creates a copy of a's value
int c = 42;     // Creates another separate copy
```

Each variable has its own memory cell containing its own copy of the value. This mechanism, where data is copied during initialization and assignment, is called **value semantics**.

## Memory Cell Concept

In C++, a variable represents the **name given to a specific memory cell**, not just a name tied to a data element.

Key points:
- The variable's memory location remains fixed
- The contents can change
- Assignment and initialization replace the existing information in that memory cell with new data
- The term "variable" comes from the fact that the **contents** of the memory cell may vary during program execution

## Practical Example: Complex Data Types

### TypeScript Array Behavior
```typescript
function main(): void {
    const storage1 = [3, 9, 27, 81, 243];
    const storage2 = storage1;    // Both reference same array
    
    storage2[3] = 0;              // Modifies the shared array
    console.log(storage1[3], storage2[3]);  // Prints: 0 0
}

main();
```

Both `storage1` and `storage2` are names for the same array. Changes made through either name affect the same underlying data.

### C++ Deque Behavior
```cpp
#include <iostream>
#include <deque>
using namespace std;

int main() {
    deque<int> storage1 = {3, 9, 27, 81, 243};
    deque<int> storage2;
    
    storage2 = storage1;   // Copying storage1 to storage2
    storage2.at(3) = 0;    // Modifies only the copy
    
    cout << storage1.at(3) << " " << storage2.at(3) << endl;  // Prints: 81 0
}
```

The assignment `storage2 = storage1` creates a **complete copy** of the deque structure. Modifying the copy leaves the original unchanged.

**Why the difference:** TypeScript prints `0 0` while C++ prints `81 0`. In C++, assignment creates independent copies, so changes to one container don't affect the other.

## Template Syntax

When creating containers in C++, you specify the element type in angle brackets:
```cpp
deque<int>     // deque containing integers
deque<string>  // deque containing strings
vector<double> // vector containing doubles
```

This is similar to TypeScript's generic types:
```typescript
Array<number>     // array of numbers
Array<string>     // array of strings
Map<string, int>  // map from string to number
```

## C++ References

### Creating References

C++ provides references as an alternative to value semantics. You create a reference by placing `&` between the data type and variable name:
```cpp
target_type& reference_name = target_variable;
```

**Important rules:**
- References must be initialized when declared
- References cannot be reassigned to refer to different variables

### Reference Example
```cpp
#include <iostream>
#include <deque>
using namespace std;

int main() {
    deque<int> storage1 = {3, 9, 27, 81, 243};
    deque<int>& storage2 = storage1;  // storage2 references storage1
    
    storage2[3] = 0;                  // Modifies storage1 through reference
    
    cout << storage1[3] << " " << storage2[3] << endl;  // Prints: 0 0
}
```

This implementation behaves like the TypeScript version, printing `0 0`. The reference `storage2` is an **alias** for `storage1` - they refer to the same memory location.

### Reference Operator Placement

The reference operator `&` can be positioned in different ways:
```cpp
int integer = 42;

int& reference1 = integer;   // Recommended style
int &reference2 = integer;   // Alternative placement
int & reference3 = integer;  // Another alternative
```

**Best practice:** Attach the `&` to the data type, as the reference property logically belongs with the type declaration.

## Key Differences Summary

### Value Semantics (C++ Default)

- ✅ Each variable has its own memory cell
- ✅ Assignment creates independent copies
- ✅ Changes to one variable don't affect others
- ✅ Safe from unintended side effects
- ❌ Memory usage increases with copies
- ❌ Copying large objects can be slow

### Reference Semantics (TypeScript Objects, C++ References)

- ✅ Multiple names can refer to the same data
- ✅ More memory efficient
- ✅ No copying overhead
- ❌ Changes through one name affect all references
- ❌ Requires careful management to avoid unintended modifications

## When References Are Useful

References become particularly valuable as **function parameters**. They allow functions to:
- Work with original data instead of copies
- Avoid the performance cost of copying large objects
- Modify the caller's data when needed

We'll explore this in detail in the next lecture on [parameter passing](2.3-Parameter-Passing.md).

| Feature              | C++ Value           | C++ Reference      | TypeScript Primitive | TypeScript Object |
|---------------------|---------------------|--------------------|--------------------|-------------------|
| **Creates copy**    | Yes                 | No                 | Yes                | No                |
| **Can reassign**    | Yes                 | No                 | Yes                | Yes (to new object) |
| **Memory usage**    | One per variable    | Shared             | One per variable   | Shared            |
| **Modification**    | Independent         | Affects original   | Independent        | Affects original  |
| **Syntax**          | `type name`         | `type& name`       | `let/const`        | `let/const`       |

## Summary

- **C++ uses value semantics by default** - assignment creates copies
- **References provide reference semantics** - multiple names for same data
- **TypeScript mixes both** - primitives are values, objects are references
- **References must be initialized** - cannot change what they refer to
- **Use `&` to create references** - attached to the type in declaration
- **Memory efficiency** - references avoid copying large objects
- **Function parameters** - references particularly useful here (next lecture)
