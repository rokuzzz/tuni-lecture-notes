## Function Syntax Comparison

### TypeScript Optional Static Typing

**With explicit types (static):**
```typescript
function middleValue(
    number1: number, number2: number, number3: number
): number {
    if ((number2 <= number1 && number1 <= number3) ||
        (number3 <= number1 && number1 <= number2)) {
        return number1;
    } else if ((number1 <= number2 && number2 <= number3) ||
               (number3 <= number2 && number2 <= number1)) {
        return number2;
    } else {
        return number3;
    }
}

function main(): void {
    console.log(middleValue(4, 5, 1));
}

main();
```

**Without types (dynamic):**
```typescript
function middleValue(number1, number2, number3) {
    if ((number2 <= number1 && number1 <= number3) ||
        (number3 <= number1 && number1 <= number2)) {
        return number1;
    } else if ((number1 <= number2 && number2 <= number3) ||
               (number3 <= number2 && number2 <= number1)) {
        return number2;
    } else {
        return number3;
    }
}
```

### C++ Static Typing

**Always static:**
```cpp
int middle_value(int number1, int number2, int number3) {
    if ((number2 <= number1 and number1 <= number3) or
        (number3 <= number1 and number1 <= number2)) {
        return number1;
    } else if ((number1 <= number2 and number2 <= number3) or
               (number3 <= number2 and number2 <= number1)) {
        return number2;
    } else {
        return number3;
    }
}

int main() {
    cout << middle_value(4, 5, 1) << endl;
}
```

## Key Differences

**TypeScript:**
- Allows you to choose between dynamic and static typing
- Types are optional (in plain JavaScript)
- Type checking happens at compile time (TypeScript) or runtime (JavaScript)

**C++:**
- Always requires explicit declaration of:
  - Parameter types for each function parameter
  - Return value type for the function
- All types must be known at compile time
- No runtime type flexibility

## Function Call Syntax

The actual function call syntax is identical across languages:
```
function_name(comma_separated_parameters)
```

## Relational Operator Chaining

**Python allows chained comparisons:**
```python
if a <= b <= c:  # Checks both a <= b AND b <= c
```

**Both TypeScript and C++ require separate comparisons:**
```typescript
if (a <= b && b <= c) {  // TypeScript
```
```cpp
if (a <= b && b <= c) {  // C++
// Note: 'and' is equivalent to '&&' in C++
```

## Function Declaration vs Definition

### Complete Definition Before Use
```cpp
double average(double number1, double number2) {
    return (number1 + number2) / 2;
}

int main() {
    cout << average(2.0, 5.0) << endl;
}
```

This works because the function is fully defined before `main()` tries to use it.

### Forward Declaration

When you need to call a function before defining it:
```cpp
// Forward declaration
double average(double number1, double number2);

int main() {
    cout << average(2.0, 5.0) << endl;
}

// Definition
double average(double number1, double number2) {
    return (number1 + number2) / 2;
}
```

**Declaration syntax:**
```cpp
return_value_type function_name(parameter_types);
```

The declaration provides enough information for the compiler to verify correct function calls. The actual function body must be defined elsewhere in the program.

## Void Functions (Subroutines)

### Functions That Don't Return Values
```cpp
void print_multiplication_table(int number) {
    if (number <= 0) {
        cout << "Error: only positive numbers are valid!" << endl;
        return;  // Early exit
    }
    
    int multiplier = 1;
    while (multiplier <= 9) {
        cout << multiplier * number << endl;
        ++multiplier;
    }
    // Automatic return at end of function
}
```

**Key characteristics:**
- Use `void` as the return type
- `return` statement is optional
- Can use `return;` for early exit without a value
- Function automatically returns when execution reaches the end

## Function Overloading

### Creating Multiple Functions with Same Name
```cpp
double square_of_the_sum(double a, double b) {
    return (a + b) * (a + b);
}

int square_of_the_sum(int a, int b) {
    return (a + b) * (a + b);
}

int main() {
    cout << square_of_the_sum(1.2, 3.4) << endl;  // Calls double version
    cout << square_of_the_sum(3, 4) << endl;      // Calls int version
}
```

**Requirements for overloading:**
- Functions must have the same name
- Functions must differ in:
  - Parameter types, OR
  - Number of parameters
- Compiler determines which version to call based on the arguments provided

**TypeScript comparison:**
```typescript
// TypeScript doesn't have true overloading
// Uses union types or optional parameters instead
function squareOfSum(a: number, b: number): number {
    return (a + b) * (a + b);
}
```

## Default Parameters

### Alternative to Overloading
```cpp
void print_value(int value, unsigned int indent = 0);
```

**Rules for default parameters:**
- Default parameters must appear at the end of the parameter list
- All parameters after the first default parameter must also have defaults

**Valid function calls:**
```cpp
print_value(1);      // Uses default indent = 0
print_value(2, 4);   // Uses indent = 4
print_value(3, 0);   // Explicitly sets indent = 0
```

**TypeScript comparison:**
```typescript
function printValue(value: number, indent: number = 0): void {
    // Implementation
}

// Same usage pattern
printValue(1);      // indent = 0
printValue(2, 4);   // indent = 4
```

## The main Function

### Special Properties

**Return type requirements:**
```cpp
int main() {
    // Function body
    return EXIT_SUCCESS;  // Explicit return
}
```

**Standard return values:**
- `EXIT_SUCCESS` (value 0) - indicates successful execution
- `EXIT_FAILURE` (value 1) - indicates error occurred
- These constants are defined in `<cstdlib>`

**Automatic return behavior:** If no return statement is provided, the compiler automatically returns `EXIT_SUCCESS`.

### Best Practices
```cpp
#include <cstdlib>

int main() {
    if (some_error) {
        return EXIT_FAILURE;
    }
    
    // Normal execution
    return EXIT_SUCCESS;
}
```

**Why use named constants:**
- Use `EXIT_SUCCESS` and `EXIT_FAILURE` instead of magic numbers (0, 1)
- Only use these constants as return values from `main` function
- The behavior of these constants differs in other contexts

## Static vs Dynamic Typing Impact

### TypeScript Flexibility
```typescript
function process(param: number | string): void {
    if (typeof param === 'number') {
        // Handle number
    } else {
        // Handle string
    }
}
```

### C++ Type Constraints

C++ requires compile-time type knowledge, preventing runtime type checking. Alternative approaches include:
- Function overloading for different types
- Templates (covered in advanced courses)
- Function templates (covered in advanced courses)

**Example with overloading:**
```cpp
void process(int param) {
    // Handle integer
}

void process(string param) {
    // Handle string
}
```

## Function Header Components

A complete function header consists of:
```cpp
return_type function_name(parameter_type parameter_name, ...)
```

**Example breakdown:**
```cpp
double calculate_average(double first_number, double second_number)
//  ^          ^                ^           ^            ^          ^
// return   function         param       param        param      param
// type      name            type        name         type       name
```

This explicit typing allows the compiler to:
- Perform type checking
- Optimize function calls at compile time
- Detect errors before the program runs

## Summary

- **C++ always requires explicit types** - no optional typing like TypeScript
- **Function overloading** - same name, different parameters (C++ feature)
- **Default parameters** - provide default values for optional parameters
- **Forward declarations** - allow calling functions before definition
- **`void` functions** - don't return values, can exit early with `return;`
- **`main()` is special** - entry point, returns int, auto-returns `EXIT_SUCCESS`
- **Static typing** - all types known at compile time, no runtime type flexibility
