## Formal vs Actual Parameters

### Terminology

**Actual parameters** are the values or variables passed when calling a function.

**Formal parameters** are the variable names defined in the function header that receive the actual parameters.
```cpp
void doubleNumber(int value) {    // 'value' is the formal parameter
    value = value * 2;
}

int main() {
    int x = 5;
    doubleNumber(x);              // 'x' is the actual parameter
    doubleNumber(10);             // '10' is the actual parameter
}
```

Formal parameters help access the actual parameters or their values within the function body.

## Value Parameters (Default Behavior)

### How Value Parameters Work

By default, C++ function parameters use [value semantics](2.2-Values-and-References.md). The formal parameter becomes a new variable initialized with a copy of the actual parameter's value.. The formal parameter becomes a new variable initialized with a copy of the actual parameter's value.
```cpp
void value_parameter_function(int number) {
    number = 2 * number;    // Only changes the copy
}

int main() {
    int variable = 7;
    cout << variable << endl;           // Prints 7
    value_parameter_function(variable);
    cout << variable << endl;           // Prints 7 again
}
```

**Key characteristics:**
- The formal parameter is a **separate variable** from the actual parameter
- Changes to the formal parameter do **not** affect the actual parameter
- Safe from unintended side effects
- Involves copying data (potentially expensive for large objects)

### TypeScript Comparison

TypeScript behaves similarly with primitives:
```typescript
function valueParameterFunction(number: number): void {
    number = 2 * number;    // Only changes the copy
}

let variable = 7;
console.log(variable);           // Prints 7
valueParameterFunction(variable);
console.log(variable);           // Prints 7
```

## Reference Parameters

### Creating Reference Parameters

Add the `&` symbol after the data type in the formal parameter declaration to create a [reference parameter](2.2-Values-and-References.md):
```cpp
void reference_parameter_function(int& number) {
    number = 2 * number;    // Changes the original variable
}

int main() {
    int variable = 7;
    cout << variable << endl;                // Prints 7
    reference_parameter_function(variable);
    cout << variable << endl;                // Prints 14
}
```

**Key characteristics:**
- The formal parameter is an **alias** for the actual parameter
- Changes to the formal parameter **directly affect** the actual parameter
- No copying involved - more efficient for large objects
- Allows functions to modify caller's data

### Reference Parameter Restrictions

References cannot refer to literals because literals are not variables:
```cpp
void reference_parameter_function(int& number) {
    number = 2 * number;
}

int main() {
    reference_parameter_function(7);    // ❌ ERROR: cannot reference literal
    
    int x = 7;
    reference_parameter_function(x);    // ✅ OK: referencing a variable
}
```

**Why this restriction:** A literal like `7` doesn't have a memory location that can be modified. References need a variable they can refer to.

## Constant Parameters

### Purpose of Constant Parameters

Use `const` when you want to prevent modification of a parameter within the function:
```cpp
void constant_parameter_function(const string& word) {
    cout << word << endl;           // ✅ OK: reading the parameter
    string local_word = word;       // ✅ OK: copying to local variable
    word = "new word";              // ❌ ERROR: cannot modify const parameter
}
```

### Why Combine const with References

The combination `const&` provides both efficiency and safety:

**Efficiency:** No copying of large objects (reference benefit)  
**Safety:** Cannot accidentally modify the original data (const benefit)
```cpp
// ❌ Inefficient: copies entire vector
void process_data(vector<int> data) {
    // Work with copy
}

// ⚠️ Efficient but unsafe: can modify original
void process_data(vector<int>& data) {
    // Work with original, can modify it
}

// ✅ Efficient and safe: no copying, no modification
void process_data(const vector<int>& data) {
    // Work with original, cannot modify it
}
```

### When to Use Constant References

**Use for large objects you only need to read:**
- Strings longer than a few characters
- Containers (vector, deque, etc.)
- Custom classes with multiple data members

**Don't use with primitive types:**
```cpp
// ❌ Unnecessary for small types
void bad_example(const int& number) { ... }

// ✅ Better for primitive types
void good_example(int number) { ... }
```

The overhead of a reference is similar to copying a primitive type, so `const` references provide no benefit for `int`, `char`, `bool`, etc.

## Parameter Passing Guidelines

### Choosing the Right Parameter Type

**Value parameters:** Use for primitive types and when you need a local copy
```cpp
void calculate(int value) { ... }
double square(double x) { return x * x; }
```

**Reference parameters:** Use when the function needs to modify the caller's variable
```cpp
void increment(int& value) { ++value; }

void swap(int& a, int& b) { 
    int temp = a; 
    a = b; 
    b = temp; 
}
```

**Constant reference parameters:** Use for large objects you only need to read
```cpp
void print_vector(const vector<int>& data) { ... }
void process_string(const string& text) { ... }
```

### Decision Flow Chart
```
Is it a primitive type (int, char, bool, double)?
├─ YES → Use value parameter (type name)
└─ NO → Is it a large object (string, vector, deque)?
    ├─ YES → Does function need to modify it?
    │   ├─ YES → Use reference parameter (type& name)
    │   └─ NO → Use const reference (const type& name)
    └─ NO → Use value parameter
```

## Performance Considerations

For large data structures, the choice of parameter type significantly affects performance:
```cpp
// ❌ Slow: copies entire vector every call
int sum_slow(vector<int> numbers) {
    int total = 0;
    for (int num : numbers) {
        total += num;
    }
    return total;
}

// ✅ Fast: works with original data
int sum_fast(const vector<int>& numbers) {
    int total = 0;
    for (int num : numbers) {
        total += num;
    }
    return total;
}
```

The constant reference version avoids the potentially expensive copy operation while maintaining the safety of not modifying the original data.

## Comparison with TypeScript

### TypeScript Parameter Behavior

TypeScript behaves differently depending on data types:
```typescript
// Primitives - always copied (value semantics)
function modifyNumber(x: number): void {
    x = x * 2;  // Doesn't affect original
}

// Objects - references passed (but cannot change reference itself)
function modifyArray(arr: number[]): void {
    arr[0] = 999;  // DOES affect original array
    arr = [];      // Doesn't affect original reference
}
```

### C++ Explicit Control

C++ gives explicit control over parameter passing:
```cpp
void modify_copy(vector<int> vec) { ... }        // Copy
void modify_original(vector<int>& vec) { ... }   // Reference
void read_only(const vector<int>& vec) { ... }   // Const reference
```

## Summary of Parameter Types

| Parameter Type | Syntax | When to Use | Can Modify? | Performance |
|---------------|--------|-------------|-------------|-------------|
| **Value** | `type name` | Primitives, need local copy | No (only copy) | Fast for small types |
| **Reference** | `type& name` | Need to modify original | Yes | Fast (no copy) |
| **Const Reference** | `const type& name` | Large objects, read-only | No | Fast (no copy) |

## Common Patterns

### Swap Function
```cpp
void swap(int& a, int& b) {
    int temp = a;
    a = b;
    b = temp;
}
```

### Read-Only Processing
```cpp
void print_all(const vector<string>& items) {
    for (const string& item : items) {
        cout << item << endl;
    }
}
```

### Modify and Return
```cpp
void double_all(vector<int>& numbers) {
    for (int& num : numbers) {
        num *= 2;
    }
}
```

## Key Takeaways

1. **Default is value** - parameters are copied by default
2. **Use `&` for references** - allow modification of original
3. **Use `const&` for efficiency** - read-only access without copying
4. **Primitives use values** - copying is cheap for small types
5. **Large objects use const&** - avoid expensive copies
6. **TypeScript is implicit** - C++ gives explicit control
7. **References can't bind to literals** - need actual variables
8. **Choose based on intent** - modification needs, performance, safety
