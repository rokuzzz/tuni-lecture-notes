
Amortized Analysis, Vector Growth Strategy, Performance Optimization

---

## 1. Vector Memory Management Problem

### The Challenge

**Problem:** `std::vector` stores elements in a **contiguous memory block**

**Question:** What happens when we need more space?

---

## 2. Two Approaches to Growth

### ❌ Attempt 1: Add Exactly What You Need (Naive)

**Strategy:** When full, allocate space for exactly 1 more element

```
N=1:  [1]
N=2:  [1][2]          ← Copied 1 element
N=3:  [1][2][3]       ← Copied 2 elements
N=4:  [1][2][3][4]    ← Copied 3 elements
N=5:  [1][2][3][4][5] ← Copied 4 elements
```

**Total copies for N insertions:**

```
0 + 1 + 2 + 3 + ... + (N-1) = N(N-1)/2 ≈ O(N²)
```

**Cost per insertion:** O(N²) / N = **O(N)** ❌ Too slow!

---

### ✅ Attempt 2: Double the Size (Smart)

**Strategy:** When full, allocate **twice as much space**

```
N=1:  [1]
N=2:  [1][2]                    ← Copied 1 element
N=3:  [1][2][3][ ]              ← Copied 2 elements
N=4:  [1][2][3][4]              
N=5:  [1][2][3][4][5][ ][ ][ ]  ← Copied 4 elements
N=6:  [1][2][3][4][5][6][ ][ ]
N=7:  [1][2][3][4][5][6][7][ ]
N=8:  [1][2][3][4][5][6][7][8]
```

**Key insight:** Empty spaces remain unused, but reallocation happens **rarely**!

**Reallocations happen at:** N = 1, 2, 4, 8, 16, 32, ...

**Total copies for N insertions:**

```
1 + 2 + 4 + 8 + ... + N = 2N - 1 ≈ O(N)
```

**Cost per insertion:** O(N) / N = **O(1)** ✅ Constant time!

---

## 3. Amortized Performance

### Definition

**Amortized complexity** counts the **average performance** of a sequence of operations

**Key idea:** Expensive operations are rare, so we can "spread" their cost over many cheap operations

---

### Analogy: Buying a Car

```
Cost: 50,000€
Use:  10 years
Average cost per year: 5,000€/year
```

Even though buying is expensive, the **amortized cost** per year is reasonable!

---

### Vector push_back Example

**Individual operations:**

- Most `push_back()` operations: **O(1)** (just add element)
- Rare `push_back()` operations: **O(N)** (need to reallocate and copy)

**But:** Expensive operations get rarer and rarer!

**Amortized complexity:** **O(1)** on average ✅

## 4. std::vector Memory Management Functions

### Key Functions

**1. `vec.reserve(n)`**

- Reserves memory for **at least** n elements
- **Does NOT** add elements (size unchanged)
- Use when you know final size in advance

```cpp
vector<int> vec;
vec.reserve(1000);  // Pre-allocate space
// Now 1000 push_back() calls won't reallocate!
```

---

**2. `vec.capacity()`**

- Returns **maximum** number of elements without reallocation
- May be larger than `vec.size()`

```cpp
vector<int> vec;
vec.push_back(1);
cout << vec.size();     // 1 (actual elements)
cout << vec.capacity(); // Could be 1, 2, or more
```

---

**3. `vec.shrink_to_fit()`**

- Moves elements to memory block of exact size
- Frees unused space
- Useful after many deletions

```cpp
vector<int> vec(1000);  // capacity = 1000
vec.erase(...);         // size = 100, capacity still 1000
vec.shrink_to_fit();    // capacity = 100
```

---

**4. `vec.erase()` — Important Note!**

⚠️ **`vec.erase()` does NOT free memory!**

```cpp
vector<int> vec{1, 2, 3, 4, 5};
cout << vec.capacity();  // 5
vec.erase(vec.begin() + 2);  // Remove element 3
cout << vec.size();      // 4 ✅
cout << vec.capacity();  // 5 ❌ Still allocated!
```

**To actually free memory:** Use `shrink_to_fit()`

## 5. Two Levels of Optimization

### Level 1: Algorithm Design (Asymptotic Performance)

**Focus:** Choose the **asymptotically best** algorithm

**Example:**

- Bubble sort: O(n²) ❌
- Merge sort: O(n log n) ✅

**This matters most for large N!**

---

### Level 2: Implementation (Constant Factors)

**Focus:** Make code as **efficient as possible**

**Example:**

- Both are O(n), but one is 10x faster!

**Important:** Optimization affects the **constant coefficient**

- From: `Time = 10n`
- To: `Time = 1n`
- **Still O(n)**, but 10x faster! 🚀

---

## 6. Improving Asymptotic Performance

### Strategy 1: Choose the Best Algorithm

**Example: Searching**

```cpp
// ❌ Linear search: O(n)
bool linear_search(vector<int>& vec, int target) {
    for (int x : vec) {
        if (x == target) return true;
    }
    return false;
}

// ✅ Binary search: O(log n)
bool binary_search(vector<int>& vec, int target) {
    // Assumes vec is sorted!
    int left = 0, right = vec.size() - 1;
    while (left <= right) {
        int mid = (left + right) / 2;
        if (vec[mid] == target) return true;
        if (vec[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return false;
}
```

**For N=1,000,000:**

- Linear: 1,000,000 comparisons
- Binary: ~20 comparisons ✅

---

### Strategy 2: Avoid Unnecessary Work

**Example: Only compute what's needed**

```cpp
// ❌ Bad: Sorts everything even if we only need first 10
vector<int> get_top_10(vector<int>& vec) {
    sort(vec.begin(), vec.end());  // O(n log n)
    return vector<int>(vec.begin(), vec.begin() + 10);
}

// ✅ Good: Only partially sort
vector<int> get_top_10(vector<int>& vec) {
    nth_element(vec.begin(), vec.begin() + 10, vec.end());  // O(n)
    return vector<int>(vec.begin(), vec.begin() + 10);
}
```

---

### Strategy 3: Use Right Container for the Job

**Container Performance Table:**

|Operation|vector|list|unordered_map|map|
|---|---|---|---|---|
|Access by index|O(1) ✅|O(n) ❌|N/A|N/A|
|Insert at end|O(1) ✅|O(1) ✅|O(1) ✅|O(log n)|
|Search|O(n)|O(n)|O(1) ✅|O(log n)|
|Insert anywhere|O(n)|O(1) ✅|O(1) ✅|O(log n)|

---

**Example: Frequent searches**

```cpp
// ❌ Bad: Linear search every time
vector<int> data;
bool exists(int x) {
    return find(data.begin(), data.end(), x) != data.end();  // O(n)
}

// ✅ Good: Hash table lookup
unordered_set<int> data;
bool exists(int x) {
    return data.count(x) > 0;  // O(1) average
}
```

## 7. Optimizing Implementation (Constant Factors)

### Tip 1: Avoid Repeated Calculations

**❌ Bad: Calculating the same thing repeatedly**

```cpp
for (int i = 0; i < vec.size(); i++) {      // ❌ size() called every iteration!
    for (int j = 0; j < vec.size(); j++) {  // ❌ size() called even more!
        // ...
    }
}
```

**✅ Good: Store the result**

```cpp
int n = vec.size();  // ✅ Calculate once!
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        // ...
    }
}
```

**Why it matters:** Even though `size()` is O(1), calling it millions of times adds up!

---

### Tip 2: Cache Intermediate Results (Memoization)

**❌ Bad: Recalculating Fibonacci**

```cpp
int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);  // ❌ Exponential time!
}
```

**✅ Good: Remember previous results**

```cpp
unordered_map<int, int> memo;

int fib(int n) {
    if (n <= 1) return n;
    if (memo.count(n)) return memo[n];  // ✅ Already calculated!
    
    memo[n] = fib(n-1) + fib(n-2);
    return memo[n];
}
```

**Performance:**

- Without memoization: O(2ⁿ) — exponential! ❌
- With memoization: O(n) — linear! ✅

---

### Tip 3: Use References to Avoid Copying

**❌ Bad: Copying large objects**

```cpp
void process(vector<int> data) {  // ❌ Copies entire vector!
    // ...
}

vector<int> big_vector(1000000);
process(big_vector);  // Copies 1 million integers!
```

**✅ Good: Pass by reference**

```cpp
void process(const vector<int>& data) {  // ✅ No copy!
    // ...
}

vector<int> big_vector(1000000);
process(big_vector);  // Just passes a reference!
```

**Cost difference:**

- Copy: O(n) time, O(n) memory
- Reference: O(1) time, O(1) memory ✅

---

### Tip 4: Use Pointers When Appropriate

**❌ Bad: Looking up objects repeatedly**

```cpp
struct Node {
    int id;
    string name;
    vector<int> data;
};

unordered_map<int, Node> nodes;

void process() {
    for (int i = 0; i < 1000; i++) {
        cout << nodes[42].name;  // ❌ Hash lookup every time!
    }
}
```

**✅ Good: Store pointer to result**

```cpp
void process() {
    Node* node = &nodes[42];  // ✅ One lookup!
    for (int i = 0; i < 1000; i++) {
        cout << node->name;   // Fast pointer dereference
    }
}
```

---

### Tip 5: Share Data vs. Copying

**❌ Bad: Creating copies of large data**

```cpp
class Image {
    vector<vector<int>> pixels;  // Huge!
public:
    Image crop(int x, int y, int w, int h) {
        Image result;
        // ❌ Copying pixels...
        return result;
    }
};
```

**✅ Good: Use shared_ptr to avoid copies**

```cpp
class Image {
    shared_ptr<vector<vector<int>>> pixels;  // Shared!
public:
    Image crop(int x, int y, int w, int h) {
        Image result;
        result.pixels = pixels;  // ✅ Just copy pointer!
        return result;
    }
};
```

---

### Tip 6: Do Small Things Alongside Larger Operations

**Principle:** If you're already doing O(n) work, adding O(1) work per iteration is free!

**Example: Count while sorting**

```cpp
// ❌ Two passes
sort(vec.begin(), vec.end());     // O(n log n)
int count = 0;
for (int x : vec) {               // O(n)
    if (x > 0) count++;
}

// ✅ One pass (sort + count)
int count = 0;
sort(vec.begin(), vec.end());     // O(n log n)
// Count during iteration you'd do anyway
for (int x : vec) {
    if (x > 0) count++;           // No extra cost!
}
```

**Even better:**

```cpp
// Count while building the vector
int count = 0;
for (int x : input) {
    vec.push_back(x);
    if (x > 0) count++;  // "Free" extra work!
}
sort(vec.begin(), vec.end());
```

## Key Takeaways

### Design Phase

1. **Algorithm choice matters most** — O(n log n) beats optimized O(n²)
2. **Avoid unnecessary work** — only compute what's needed
3. **Choose right containers** — match data structure to operations

### Implementation Phase

4. **Avoid redundant calculations** — store results when possible
5. **Use references** — avoid expensive copies
6. **Cache intermediate results** — memoization for repeated computations
7. **reserve() for vectors** — when size is known
8. **Profile before optimizing** — find real bottlenecks

### Remember

- **Premature optimization is the root of all evil** — Donald Knuth
- **Make it work, make it right, make it fast** — in that order!
- **Measure, don't guess** — use profilers and timing tests
