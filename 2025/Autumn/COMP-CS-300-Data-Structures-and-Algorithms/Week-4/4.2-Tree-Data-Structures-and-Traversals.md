## 1. Background

### Why Learn Tree Data Structures?

**Problem:** STL (C++ Standard Template Library) does **not** have a 'tree' container.

**Solution:** Learn to implement your own tree structures!

**Use case:** Trees are ideal for storing **hierarchical data**.

### Real-World Example: University Structure
```
         University
        /          \
    Faculty of     Faculty of
    Engineering      Science
      /  |  \        /  |  \  \
  Civil Mech Chem  IT Chem Bio Physics Geology
```

### Tree Terminology Review

- **Node** — element in the tree
- **Edge** — connection between nodes
- **Root** — top node (no parent)
- **Children** — nodes directly below a node
- **Parent** — node directly above
- **Leaf (external node)** — node with no children
- **Internal node** — node with children
- **Subtree** — tree formed by a node and all its descendants

## 2. Data Structure Implementation

### Key Assumptions

1. All trees are **rooted trees**
2. Children are ordered **left to right**
   - Leftmost child = first child
   - Rightmost child = last child

### Node Structure: Pseudocode

**For General Tree:**
```
Node.key         = unique identifier
Node.parent      = pointer to parent (NIL if root)
Node.children    = all children of Node
Node.children[i] = pointer to i-th child (NIL if doesn't exist)
```

**For Binary Tree:**
```
Node.key    = unique identifier
Node.parent = pointer to parent (NIL if root)
Node.left   = pointer to left child (NIL if doesn't exist)
Node.right  = pointer to right child (NIL if doesn't exist)
```

**Root node** is accessed via `root`.

---

### C++ Implementation

#### General Tree Node
```cpp
struct Node {
    // key = unique identifier for the node
    int key;
    
    // name = name we give to the node
    std::string name;
    
    // children = pointers to the children of the node
    std::vector<Node*> children;
    
    // parent = pointer to the parent of the node
    Node* parent;
};
```

#### Binary Tree Node
```cpp
struct Node {
    // key = unique identifier for the node
    int key;
    
    // name = name we give to the node
    std::string name;
    
    // leftChild = pointer to the left child
    Node* leftChild;
    
    // rightChild = pointer to the right child
    Node* rightChild;
    
    // parent = pointer to the parent of the node
    Node* parent;
};
```

---

### Important Implementation Notes

**1. nullptr means node doesn't exist**
```cpp
if (node->leftChild == nullptr) {
    // No left child exists
}
```

**2. Individual nodes accessed by key**
```cpp
// Find node with key = 5
Node* target = findNodeByKey(5);
```

**3. Container choice matters**
- For **many children:** `std::vector<Node*>` may be inefficient
- Consider: `std::unordered_set<Node*>` for large numbers of children

**4. Store all nodes in a container**
```cpp
std::unordered_map<int, Node> allNodes;
```

### Understanding Pointers in Trees

#### Why Pointers? (Critical Concept)

**Problem without pointers:**
```cpp
struct Node {
    int key;
    Node parent;    // ❌ ERROR! Infinite recursion!
};
```
- To create Node, need parent of type Node
- To create parent, need ITS parent of type Node
- **Infinite loop!**

**Solution with pointers:**
```cpp
struct Node {
    int key;
    Node* parent;   // ✅ Pointer has fixed size!
};
```
- Pointer always same size (8 bytes on 64-bit)
- Doesn't matter what it points to!

#### NIL in Different Languages

| Language | Notation |
|----------|----------|
| Pseudocode | `NIL` |
| C++ | `nullptr` |
| Java | `null` |
| Python | `None` |

## 3. Tree Traversals

### What is a Traversal?

**Definition:** Visiting **every node** in a data structure **exactly once**.

**Array traversal example:**
```
[4, 6, 2, 1, 8, 5, 3, 9, 7]
 ↑ → → → → → → → → (visit each element once)
```

### Three Types of Tree Traversal

1. **Preorder** — Parent first, then children
2. **Postorder** — Children first, then parent
3. **Inorder** — Left, parent, right (binary trees only!)

---

## Preorder Traversal

### Rule: Parent → Children (left to right)

### Algorithm (Pseudocode)
```
PRETRAVERSAL(node)
    input: node is some rooted tree node
    if node ≠ NIL then
        ▷ perform some operation using node    // PARENT FIRST
        forEach child in node.children
            PRETRAVERSAL(child)                // THEN CHILDREN
        end
    end
end
```

### C++ Implementation
```cpp
void PRETRAVERSAL(Node* node) {
    if (node != nullptr) {
        cout << node->key << " ";           // Visit parent
        for (Node* child : node->children) {
            PRETRAVERSAL(child);            // Visit children
        }
    }
}
```

### Example

**Tree:**

```
		  8
	 ┌────┼────┬────┐
	 9    3    7    2
	┌┴┐            ┌┴┐
	4 5            6 1
				   │
                   0
```

**Execution trace:**
```
PRETRAVERSAL(8)
    Output: 8
    PRETRAVERSAL(9)
        Output: 9
        PRETRAVERSAL(4) → Output: 4
        PRETRAVERSAL(5) → Output: 5
    PRETRAVERSAL(3) → Output: 3
    PRETRAVERSAL(7) → Output: 7
    PRETRAVERSAL(2)
        Output: 2
        PRETRAVERSAL(6)
            Output: 6
            PRETRAVERSAL(0) → Output: 0
        PRETRAVERSAL(1) → Output: 1
```

**Result:** `8, 9, 4, 5, 3, 7, 2, 6, 0, 1`

### When to Use Preorder

✅ **Use when:** Parent information should be available to children

**Examples:**
- Copying a directory structure (create parent folder first)
- Printing hierarchical data with indentation
- Prefix expression evaluation

---

## Postorder Traversal

### Rule: Children (left to right) → Parent

### Algorithm (Pseudocode)
```
POSTTRAVERSAL(node)
    input: node is some rooted tree node
    if node ≠ NIL then
        forEach child in node.children
            POSTTRAVERSAL(child)            // CHILDREN FIRST
        end
        ▷ perform some operation using node  // THEN PARENT
    end
end
```

### C++ Implementation
```cpp
void POSTTRAVERSAL(Node* node) {
    if (node != nullptr) {
        for (Node* child : node->children) {
            POSTTRAVERSAL(child);           // Visit children first
        }
        cout << node->key << " ";           // Then visit parent
    }
}
```

### Example

**Same tree:**
```
		  8
	 ┌────┼────┬────┐
	 9    3    7    2
	┌┴┐            ┌┴┐
	4 5            6 1
				   │
                   0
```

**Execution trace:**
```
POSTTRAVERSAL(8)
    POSTTRAVERSAL(9)
        POSTTRAVERSAL(4) → Output: 4
        POSTTRAVERSAL(5) → Output: 5
        Output: 9
    POSTTRAVERSAL(3) → Output: 3
    POSTTRAVERSAL(7) → Output: 7
    POSTTRAVERSAL(2)
        POSTTRAVERSAL(6)
            POSTTRAVERSAL(0) → Output: 0
            Output: 6
        POSTTRAVERSAL(1) → Output: 1
        Output: 2
    Output: 8
```

**Result:** `4, 5, 9, 3, 7, 0, 6, 1, 2, 8`

### When to Use Postorder

✅ **Use when:** Children information should be available to parent

**Examples:**
- Calculating directory sizes (need sizes of all subdirectories first)
- Deleting a tree (delete children before parent)
- Postfix expression evaluation

---

## Inorder Traversal

### ⚠️ ONLY FOR BINARY TREES!

### Rule: Left subtree → Parent → Right subtree

### Algorithm (Pseudocode)
```
INTRAVERSAL(node)
    input: node is some rooted tree node
    if node ≠ NIL then
        INTRAVERSAL(node.left)              // LEFT FIRST
        ▷ perform some operation using node  // THEN PARENT
        INTRAVERSAL(node.right)             // THEN RIGHT
    end
end
```

### C++ Implementation
```cpp
void INTRAVERSAL(Node* node) {
    if (node != nullptr) {
        INTRAVERSAL(node->leftChild);      // Visit left
        cout << node->key << " ";          // Visit parent
        INTRAVERSAL(node->rightChild);     // Visit right
    }
}
```

### Example

**Simple binary tree:**
```
     5
    / \
   3   8
  /   / \
 1   6   9
```

**Execution trace:**
```
INTRAVERSAL(5)
    INTRAVERSAL(3)              // Left subtree
        INTRAVERSAL(1) → Output: 1
        Output: 3
    Output: 5
    INTRAVERSAL(8)              // Right subtree
        INTRAVERSAL(6) → Output: 6
        Output: 8
        INTRAVERSAL(9) → Output: 9
```

**Result:** `1, 3, 5, 6, 8, 9` ✅ **(Sorted order!)**

### When to Use Inorder

✅ **Use when:** Need to process binary search tree in sorted order

**Examples:**
- Printing binary search tree elements in ascending order
- Validating binary search tree property
- Converting tree to sorted array

## Comparison Summary

| Traversal | Order | Works On | Use Case |
|-----------|-------|----------|----------|
| **Preorder** | Parent → Children | Any tree | Parent info needed by children |
| **Postorder** | Children → Parent | Any tree | Children info needed by parent |
| **Inorder** | Left → Parent → Right | **Binary trees only** | Get sorted order from BST |

### Visual Summary

**Same tree, different orders:**
```
		  8
	 ┌────┼────┬────┐
	 9    3    7    2
	┌┴┐            ┌┴┐
	4 5            6 1
				   │
                   0
```

- **Preorder:**  `8, 9, 4, 5, 3, 7, 2, 6, 0, 1` (Root first)
- **Postorder:** `4, 5, 9, 3, 7, 0, 6, 1, 2, 8` (Root last)

## Key Implementation Details

### Why Check `if node ≠ NIL`?

**Purpose:** Base case for recursion

**Without check:**
```cpp
void PRETRAVERSAL(Node* node) {
    cout << node->key;              // ❌ CRASH if node == nullptr!
    PRETRAVERSAL(node->leftChild);  // ❌ Infinite recursion!
}
```

**With check:**
```cpp
void PRETRAVERSAL(Node* node) {
    if (node != nullptr) {          // ✅ Safe!
        cout << node->key;
        PRETRAVERSAL(node->leftChild);  // Will stop at nullptr
    }
}
```

**What happens:**
- When reach leaf node's child (nullptr), function returns immediately
- Prevents accessing `nullptr->key` (segmentation fault!)
- Natural stopping point for recursion

## Recursion Mechanics

### Stack Frames in Preorder

**Example tree:**
```
   5
  / \
 3   8
```

**Call stack:**
```
PRETRAVERSAL(5)
    Output: 5
    ├─ PRETRAVERSAL(3)
    │    Output: 3
    │    ├─ PRETRAVERSAL(nullptr)  ← returns immediately
    │    └─ PRETRAVERSAL(nullptr)  ← returns immediately
    └─ PRETRAVERSAL(8)
         Output: 8
         ├─ PRETRAVERSAL(nullptr)  ← returns immediately
         └─ PRETRAVERSAL(nullptr)  ← returns immediately

Result: 5, 3, 8
```

## Practice Patterns

### Pattern Recognition

**Given output, identify traversal type:**

Tree:
```
     A
    / \
   B   C
  /   / \
 D   E   F
```

- `A, B, D, C, E, F` → **Preorder** (parent first)
- `D, B, E, F, C, A` → **Postorder** (parent last)
- `D, B, A, E, C, F` → **Inorder** (left, parent, right)

## Quick Reference

### Traversal Templates

**Preorder:**
```
Visit node
For each child: recurse
```

**Postorder:**
```
For each child: recurse
Visit node
```

**Inorder (binary only):**
```
Recurse left
Visit node
Recurse right
```

### Memory Aid

- **PRE**order = **PRE**fix = Parent **PRE**cedes children
- **POST**order = **POST**fix = Parent comes **POST** children
- **IN**order = Value comes **IN** between left and right

## Key Takeaways

1. **Trees need pointers** — fixed size, prevents infinite recursion
2. **nullptr check essential** — base case for recursion
3. **Three traversal types:**
   - Preorder: parent → children (any tree)
   - Postorder: children → parent (any tree)
   - Inorder: left → parent → right (binary only!)
4. **All traversals are recursive** — natural fit for tree structure
5. **Order matters** — same tree, different orders, different results
6. **Use case determines traversal:**
   - Need parent info first? → Preorder
   - Need children info first? → Postorder
   - Need sorted order (BST)? → Inorder
