## Core Concepts

### What is Asymptotic Analysis?

**Goal:** Describe how **running time f(n)** depends on **input size n** when n becomes **large**.

**Key Idea:** Ignore constants and low-order terms, focus on **fastest growing term**.

### Example:

```
f(n) = 2n + 100

For large n:
- Constant +100 becomes insignificant
- Coefficient 2 doesn't matter asymptotically

Fastest growing term: n

Result: f(n) "behaves like" n
```

### Why "Asymptotic"?

We care about behavior as **n → ∞** (large inputs), not small values like n = 1, 2, 3.

### Running Time Function f(n)

Count of **simple operations** from start to finish:

- Arithmetic: `+`, `-`, `*`, `/`
- Comparisons: `<`, `>`, `==`
- Assignments: `x = 5`
- Array access: `arr[i]`
- One loop iteration

## Big-O (O) - Upper Bound

### Definition

**f(n) ∈ O(g(n))** means:

> "There exist constants c₁ > 0 and n₀ > 0 such that:
> 
> **f(n) ≤ c₁ · g(n)** for all n > n₀"

### What This Actually Means

**f(n) grows NO FASTER than g(n)** (with some constant multiplier)

After some point n₀, the function f(n) always stays below c₁·g(n).

### Practical Understanding

**Big-O = Worst Case Upper Bound**

"Algorithm runs **no worse** than O(g(n))"

### Example

```
f(n) = 2n + 100

To show f(n) ∈ O(n):

Need: 2n + 100 ≤ c₁ · n for n > n₀

Choose: c₁ = 3, n₀ = 100

Check:
2n + 100 ≤ 3n
100 ≤ n  ✅ (true for n > 100)

Therefore: f(n) ∈ O(n)
```

### Key Principle

**Smallest upper bound = most information**

```
f(n) = 2n + 100

All correct:
- f(n) ∈ O(n²)  ✅ (but weak)
- f(n) ∈ O(n log n)  ✅ (better)
- f(n) ∈ O(n)  ✅ (BEST - tightest bound)
```

### Common O( ) Classes

| Class      | Name         | Example                              |
| ---------- | ------------ | ------------------------------------ |
| O(1)       | Constant     | Array access: `arr[5]`               |
| O(log n)   | Logarithmic  | Binary search                        |
| O(n)       | Linear       | Single loop through array            |
| O(n log n) | Linearithmic | MergeSort, QuickSort (average)       |
| O(n²)      | Quadratic    | Nested loops, Insertion Sort (worst) |
| O(2ⁿ)      | Exponential  | Recursive Fibonacci (naive)          |

**Order (fastest → slowest):**

```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
```

## Big-Omega (Ω) - Lower Bound

### Definition

**f(n) ∈ Ω(g(n))** means:

> "There exist constants c₂ > 0 and n₀ > 0 such that:
> 
> **f(n) ≥ c₂ · g(n)** for all n > n₀"

### What This Actually Means

**f(n) grows NO SLOWER than g(n)** (with some constant divisor)

After some point n₀, the function f(n) always stays above c₂·g(n).

### Practical Understanding

**Big-Omega = Best Case Lower Bound**

"Algorithm runs **no faster** than Ω(g(n))"

### Example

```
f(n) = 2n + 100

To show f(n) ∈ Ω(n):

Need: 2n + 100 ≥ c₂ · n for n > n₀

Choose: c₂ = 2, n₀ = 0

Check:
2n + 100 ≥ 2n  ✅ (always true, +100 only increases!)

Therefore: f(n) ∈ Ω(n)
```

### Key Principle

**Largest lower bound = most information**

```
f(n) = 2n + 100

All correct:
- f(n) ∈ Ω(1)  ✅ (but weak)
- f(n) ∈ Ω(√n)  ✅ (better)
- f(n) ∈ Ω(n)  ✅ (BEST - tightest bound)
```

### Big-Omega Order (opposite of Big-O!)

```
Ω(n²) ⊂ Ω(n log n) ⊂ Ω(n) ⊂ Ω(log n) ⊂ Ω(1)
```

**Why opposite?** Lower bounds get stronger as functions get bigger!

---

## Big-Theta (Θ) - Tight Bound

### Definition

**f(n) ∈ Θ(g(n))** means:

> "There exist constants c₁, c₂, n₀ > 0 such that:
> 
> **c₂ · g(n) ≤ f(n) ≤ c₁ · g(n)** for all n > n₀"

### What This Actually Means

**f(n) grows EXACTLY like g(n)** (sandwiched between two boundaries)

After some point n₀, the function f(n) is always between c₂·g(n) and c₁·g(n).

### Alternative Definition

```
If f(n) ∈ O(g(n)) AND f(n) ∈ Ω(g(n))
Then f(n) ∈ Θ(g(n))
```

**Big-Theta = Big-O AND Big-Omega with the SAME function!**

### Practical Understanding

**Big-Theta = Exact Asymptotic Behavior**

"Algorithm grows **exactly like** Θ(g(n))"

### Example

```
f(n) = 2n + 100

We showed:
- f(n) ∈ O(n)  ✅ (upper bound)
- f(n) ∈ Ω(n)  ✅ (lower bound)

Therefore:
f(n) ∈ Θ(n)  ✅ (tight bound - MOST PRECISE)
```

### Why Big-Theta is Best

**Most informative** - tells you exactly how function grows!

```
QuickSort (best case):
- O(n log n)  ✅ (won't be worse)
- Ω(n log n)  ✅ (won't be better)
- Θ(n log n)  ✅ (EXACT behavior)
```

## Best/Worst/Average Case

### CRITICAL DISTINCTION

**Cases ≠ Notations!**

|Concept|What It Is|About|
|---|---|---|
|**Best/Worst/Average**|Input characteristics|Which data causes this behavior|
|**O/Ω/Θ**|Asymptotic bounds|How to describe growth rate|

### You Can Use ALL Notations for ANY Case!

**Example: QuickSort**

**Worst Case:**

- Input: Array in reverse order
- Time: f_worst(n) = n²
- Can say:
    - f_worst(n) ∈ O(n²) ✅
    - f_worst(n) ∈ Ω(n²) ✅
    - f_worst(n) ∈ Θ(n²) ✅ (most precise)

**Best Case:**

- Input: Pivot always in middle
- Time: f_best(n) = n log n
- Can say:
    - f_best(n) ∈ O(n log n) ✅
    - f_best(n) ∈ Ω(n log n) ✅
    - f_best(n) ∈ Θ(n log n) ✅ (most precise)

### Definitions

**Best Case:**

> Input data for which asymptotic growth of f(n) is **smallest**

**Worst Case:**

> Input data for which asymptotic growth of f(n) is **largest**

**Average Case:**

> Expected asymptotic growth over all possible inputs (requires probability)

### Common Usage (Informal)

In practice, people often say:

```
"QuickSort is O(n²)"
```

They **mean**: "QuickSort's **worst case** is O(n²)"

**Formally correct:** "QuickSort's worst case running time is Θ(n²)"

## How to Analyze Code

### Step 1: Identify Simple Operations

Count:

- Arithmetic: `+`, `-`, `*`, `/`
- Comparisons: `<`, `>`, `==`
- Assignments: `x = 5`
- Array access: `arr[i]`
- Loop iterations

### Step 2: Count Loop Iterations

**Single Loop:**

```cpp
for (int i = 0; i < n; i++) {
    doSomething();  // O(1)
}
// Total: n × O(1) = O(n)
```

**Nested Loops:**

```cpp
for (int i = 0; i < n; i++) {          // n times
    for (int j = 0; j < n; j++) {      // n times
        doSomething();  // O(1)
    }
}
// Total: n × n × O(1) = O(n²)
```

**Sequential Loops (NOT nested):**

```cpp
for (int i = 0; i < n; i++) {
    doSomething();
}
for (int j = 0; j < n; j++) {
    doSomethingElse();
}
// Total: n + n = 2n = O(n)  (NOT O(n²)!)
```

### Step 3: Identify Logarithmic Patterns

**Key Sign:** Variable multiplied/divided by constant

```cpp
// O(log n)
int i = 1;
while (i < n) {
    doSomething();
    i *= 2;  // ← multiply by 2
}

// Also O(log n)
int i = n;
while (i > 1) {
    doSomething();
    i /= 2;  // ← divide by 2
}
```

**Why log?**

```
i = 1, 2, 4, 8, 16, ..., n
i = 2⁰, 2¹, 2², 2³, 2⁴, ..., 2^k

When stops? When 2^k ≈ n
Therefore: k ≈ log₂(n)
```

### Step 4: Find Fastest Growing Term

```
f(n) = 5n² + 3n + 100

Fastest growing: 5n² → n²

Result: f(n) ∈ Θ(n²)
```

### Common Mistakes

**Mistake 1: Thinking n/2 iterations = O(log n)**

```cpp
// This is O(n), NOT O(log n)!
for (int i = 0; i < n/2; i++) {
    doSomething();
}
// n/2 = O(n) (constants ignored)
```

**Mistake 2: Confusing sequential and nested**

```cpp
// Sequential: O(n)
for (int i = 0; i < n; i++) { }
for (int j = 0; j < n; j++) { }

// Nested: O(n²)
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) { }
}
```

## MergeSort & QuickSort Analysis

### MergeSort

**Algorithm:**

```
MERGESORT(A, L, R):
    if L < R:
        M = (L + R) / 2
        MERGESORT(A, L, M)      // Left half
        MERGESORT(A, M+1, R)    // Right half
        MERGE(A, L, M, R)       // O(n) operations
```

**Key Insight:**

MergeSort recursively divides the array in half until single elements remain, then merges sorted halves back together.

- **Tree depth (levels):** log₂(n) - we halve the array each level
- **Work per level:** O(n) - we merge all n elements at each level
- **Total work:** Work per level × Number of levels = O(n) × log₂(n) = O(n log n)

**How levels work:**

- Level 0: 1 array of n elements → 1 merge of n elements
- Level 1: 2 arrays of n/2 elements → 2 merges of n/2 = n elements total
- Level 2: 4 arrays of n/4 elements → 4 merges of n/4 = n elements total
- ...
- Level log n: n arrays of 1 element → n merges of 1 = n elements total

At every level, we do O(n) work, and there are log₂(n) levels.

**Analysis:**

- **Levels:** log₂(n) (halving each time)
- **Work per level:** O(n) (merging all elements)
- **Total:** O(n) × log₂(n) = **O(n log n)**

**Complexity:**

```
Best Case:    Θ(n log n)
Worst Case:   Θ(n log n)
Average Case: Θ(n log n)
```

**Always the same!** MergeSort is **predictable**.

---

### QuickSort

**Algorithm:**

```
QUICKSORT(A, L, R):
    if L < R:
        k = PARTITION(A, L, R)   // O(n) operations
        QUICKSORT(A, L, k-1)      // Left part
        QUICKSORT(A, k+1, R)      // Right part
```

**Key Insight:** Performance depends on **pivot location**!

**Best Case (Pivot Always in Middle):**

When the pivot is always in the middle, QuickSort behaves like MergeSort:

- **Tree depth:** log₂(n) levels (halving each time)
- **Work per level:** O(n) (partitioning all elements)
- **Total:** O(n) × log₂(n) = **Θ(n log n)**

Each level processes all n elements through partitioning, and there are log₂(n) levels.

**Worst Case (Pivot Always Smallest/Largest):**

When pivot is always at an extreme (smallest or largest), the array is divided very unevenly:

- **Tree depth:** n levels (only reducing by 1 each time)
- **Work:** n + (n-1) + (n-2) + ... + 1 = n(n+1)/2
- **Total:** **Θ(n²)**

This happens when the array is already sorted (or reverse sorted) and we pick the last element as pivot.

**Example Worst Case Input:**

```
Array in reverse order: [5, 4, 3, 2, 1]
With last-element pivot → always smallest
```

**Complexity:**

```
Best Case:    Θ(n log n)  (pivot in middle)
Worst Case:   Θ(n²)       (pivot at extreme)
Average Case: Θ(n log n)  (random pivots)
```

---

### Comparison

|Feature|MergeSort|QuickSort|
|---|---|---|
|**Best**|Θ(n log n)|Θ(n log n)|
|**Worst**|Θ(n log n)|Θ(n²)|
|**Average**|Θ(n log n)|Θ(n log n)|
|**Space**|O(n) (needs Temp)|O(1) (in-place)|
|**Stable**|Yes|No|
|**Predictable**|Yes (always same)|No (depends on pivot)|

**Practical Note:** QuickSort usually faster in practice (better cache locality), but needs good pivot selection.

## Common Patterns Cheat Sheet

### Basic Patterns

|Code Pattern|Complexity|Recognition|
|---|---|---|
|**Constant operations**|O(1)|Single statements|
|**One loop to n**|O(n)|`for (i = 0; i < n)`|
|**Two nested loops to n**|O(n²)|`for (i) for (j)`|
|**Three nested loops**|O(n³)|`for (i) for (j) for (k)`|
|**Sequential loops**|O(n)|Loop 1 + Loop 2 (not nested)|

### Logarithmic Patterns

|Code Pattern|Complexity|Recognition|
|---|---|---|
|**Multiply/divide by constant**|O(log n)|`i *= 2` or `i /= 2`|
|**Binary search**|O(log n)|Discard half each time|
|**Tree height**|O(log n)|Balanced binary tree|

### Advanced Patterns

|Algorithm|Complexity|Recognition|
|---|---|---|
|**MergeSort**|O(n log n)|Divide + merge all|
|**QuickSort (avg)**|O(n log n)|Divide + partition|
|**QuickSort (worst)**|O(n²)|Bad pivot choice|
|**Binary Search**|O(log n)|Halving search space|
|**Linear Search**|O(n)|Check every element|
|**Insertion Sort (worst)**|O(n²)|Nested loop, all shifts|
|**Insertion Sort (best)**|O(n)|Already sorted|

## Quick Reference: When to Use Which

### Big-O (O)

Use when you want to say:

- "Algorithm runs **at most** this fast"
- "Worst case is **no worse** than..."
- **Upper bound**

### Big-Omega (Ω)

Use when you want to say:

- "Algorithm runs **at least** this fast"
- "Best case is **no better** than..."
- **Lower bound**

### Big-Theta (Θ)

Use when you want to say:

- "Algorithm runs **exactly** like this"
- "Growth rate is **precisely**..."
- **Tight bound** (most informative!)

## Practical Examples

### Example 1: Simple Search

```cpp
int linearSearch(int arr[], int n, int key) {
    for (int i = 0; i < n; i++) {       // n iterations
        if (arr[i] == key) return i;    // O(1)
    }
    return -1;
}
```

**Analysis:**

- **Best Case:** Key is first element
    
    - Iterations: 1
    - f_best(n) = c (constant)
    - Result: Θ(1)
- **Worst Case:** Key not in array or last
    
    - Iterations: n
    - f_worst(n) = c·n
    - Result: Θ(n)
- **Average Case:** Key somewhere in middle
    
    - Expected iterations: n/2
    - f_avg(n) = c·n/2 = O(n)
    - Result: Θ(n)

---

### Example 2: Binary Search

```cpp
int binarySearch(int arr[], int n, int key) {
    int left = 0, right = n - 1;
    
    while (left <= right) {              // log n iterations
        int mid = (left + right) / 2;
        
        if (arr[mid] == key) return mid;
        if (arr[mid] < key)
            left = mid + 1;              // Discard left half
        else
            right = mid - 1;             // Discard right half
    }
    return -1;
}
```

**Analysis:**

- **Best Case:** Key is middle element
    
    - Iterations: 1
    - Result: Θ(1)
- **Worst Case:** Key not found or at extremes
    
    - Iterations: log₂(n)
    - Result: Θ(log n)
- **Average Case:** Key somewhere
    
    - Expected: log₂(n)
    - Result: Θ(log n)

**Table (Worst Case):**

|n|Iterations|
|---|---|
|4|2|
|8|3|
|16|4|
|1000|10|

---

### Example 3: Nested Loop with Dependency

```cpp
void example(int n) {
    for (int i = 0; i < n; i++) {
        for (int j = i; j < n; j++) {     // Inner depends on i!
            doSomething();                 // O(1)
        }
    }
}
```

**Analysis:**

```
i = 0: j runs from 0 to n   → n iterations
i = 1: j runs from 1 to n   → n-1 iterations
i = 2: j runs from 2 to n   → n-2 iterations
...
i = n-1: j runs from n-1 to n → 1 iteration

Total: n + (n-1) + (n-2) + ... + 1 = n(n+1)/2 ≈ n²/2
```

**Result:** Θ(n²)

_Note:_ Still quadratic, but with constant factor 1/2 compared to full nested loop.

---

### Example 4: Logarithmic with Inner Loop

```cpp
void example(int n) {
    for (int i = 1; i < n; i *= 2) {      // log n iterations
        for (int j = 0; j < n; j++) {     // n iterations
            doSomething();
        }
    }
}
```

**Analysis:**

- Outer loop: log n iterations (i doubles)
- Inner loop: n iterations (independent of i)
- Total: log n × n = **O(n log n)**

## Final Tips for Exams

### Analysis Strategy

1. **Identify input size:** What is n?
2. **Count operations per line**
3. **Count loop iterations** (watch for dependencies!)
4. **Find fastest growing term**
5. **State result with proper notation**

### Common Exam Questions

**"What is the complexity?"** → Give **Θ** if possible (most precise), otherwise **O** (worst case)

**"Prove f(n) ∈ O(g(n))"** → Find c₁ and n₀ such that f(n) ≤ c₁·g(n) for n > n₀

**"Best case vs worst case?"** → Describe **input** that causes each, give Θ for each case

**"Analyze this algorithm"** → Count operations line by line, sum up, find dominant term

### Memory Aids

**O = Oh no! (Overhead/Upper limit)**

- "It won't be **worse** than this"

**Ω = Omega is big (Foundation/Lower limit)**

- "It won't be **better** than this"

**Θ = Theta is exact (Tight/Both bounds)**

- "It's **exactly** like this"

## Key Takeaways

### Most Important Points

1. **Big-O/Omega/Theta describe growth rates, NOT cases**
    
    - Cases = input characteristics (best/worst/average)
    - Notations = how to bound growth (upper/lower/tight)
2. **For ANY case, you can use ALL three notations**
    
    - Worst case can be O, Ω, and Θ
    - Best case can be O, Ω, and Θ
    - Θ is always most informative
3. **Fastest growing term dominates**
    
    - f(n) = 5n² + 3n + 100 → Θ(n²)
    - Constants and lower terms don't matter asymptotically
4. **Pattern recognition is key**
    
    - One loop → O(n)
    - Nested loops → O(n²)
    - Halving/doubling → O(log n)
    - Divide and merge → O(n log n)
5. **MergeSort is predictable, QuickSort is not**
    
    - MergeSort: Always Θ(n log n)
    - QuickSort: Θ(n log n) average, Θ(n²) worst

### What to Remember

**For quick analysis:** Just find the fastest growing term and that's your answer!

**For formal proof:** Show the constants c and n₀ exist (but in practice, not needed).

**For exam:** Be able to analyze code, identify cases, and use correct notation.
