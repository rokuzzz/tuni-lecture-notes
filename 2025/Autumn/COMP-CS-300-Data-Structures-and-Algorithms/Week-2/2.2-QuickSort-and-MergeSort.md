# Sorting Algorithms: QuickSort & MergeSort

## Overview

Both **QuickSort** and **MergeSort** are divide-and-conquer sorting algorithms that recursively break down problems into smaller subproblems. However, they differ fundamentally in where the main work happens.

| Aspect                | QuickSort                   | MergeSort                   |
| --------------------- | --------------------------- | --------------------------- |
| **Main work**         | DIVIDE (partitioning)       | COMBINE (merging)           |
| **Division**          | By pivot value (unbalanced) | Strictly in half (balanced) |
| **Extra space**       | O(1) - in-place             | O(n) - needs Temp array     |
| **Stability**         | Not stable                  | Stable                      |
| **Worst case**        | O(n²) - bad pivot           | O(n log n) - always         |
| **Best case**         | O(n log n)                  | O(n log n)                  |
| **Sensitive to data** | Yes (pivot choice matters)  | No (always same complexity) |

---

## QuickSort

### Core Idea

**QuickSort selects a pivot element, places it in its correct position, and recursively sorts the parts to the left and right of it.**

### Divide & Conquer Structure

1. **DIVIDE:** Partition array around pivot (main work happens here)
2. **CONQUER:** Recursively sort left and right subarrays
3. **COMBINE:** Not needed! Pivot is already in place, parts are independent

### Key Concepts

#### Pivot

- An element from the array used for partitioning
- In our slides: **last element** `A[R]` is chosen as pivot
- Can be: first, middle, random element (implementation choice)

#### Partitioning

Process of rearranging elements so that:

- **Left of pivot:** all elements ≤ pivot
- **Right of pivot:** all elements > pivot
- **Pivot is in its correct final position**

**Example:**

```
Before: [10, 4, 2, 6, 9, 3, 8, 5]  (pivot = 5)
After:  [4, 2, 3, 5, 9, 10, 8, 6]
                  ↑
        correct position (index 4)
```

### The PARTITION Algorithm

```
PARTITION(A, L, R)
  α = A[R]           // pivot = last element
  cut = L - 1        // boundary between small and large elements
  
  for j = L to R-1
    if A[j] ≤ α then
      cut = cut + 1
      swap A[cut] and A[j]
    end
  end
  
  k = cut + 1
  swap A[k] and A[R]  // put pivot in correct position
  return k
```

**Variables:**

- **α (alpha):** pivot value
- **cut:** dividing line between elements ≤ α and elements > α
- **j:** current element being examined

**Invariant:**

- `A[L..cut]` contains elements ≤ α
- `A[cut+1..j-1]` contains elements > α
- `A[R]` is the pivot (until final swap)

### PARTITION Example

**Array:** `[10, 4, 2, 6, 9, 3, 8, 5]`

|j|A[j]|A[j] ≤ 5?|Action|cut|Array after swap|
|---|---|---|---|---|---|
|1|10|No|Skip|0|`[10, 4, 2, 6, 9, 3, 8, 5]`|
|2|4|Yes|cut=1, swap(A[1],A[2])|1|`[4, 10, 2, 6, 9, 3, 8, 5]`|
|3|2|Yes|cut=2, swap(A[2],A[3])|2|`[4, 2, 10, 6, 9, 3, 8, 5]`|
|4|6|No|Skip|2|`[4, 2, 10, 6, 9, 3, 8, 5]`|
|5|9|No|Skip|2|`[4, 2, 10, 6, 9, 3, 8, 5]`|
|6|3|Yes|cut=3, swap(A[3],A[6])|3|`[4, 2, 3, 6, 9, 10, 8, 5]`|
|7|8|No|Skip|3|`[4, 2, 3, 6, 9, 10, 8, 5]`|

**Final swap:** `k = 4`, swap `A[4]` and `A[8]` → `[4, 2, 3, 5, 9, 10, 8, 6]`

**Return:** `k = 4` (pivot's final position)

### The QUICKSORT Algorithm

```
QUICKSORT(A, L, R)
  if L < R then
    k = PARTITION(A, L, R)    // Divide array
    QUICKSORT(A, L, k-1)       // Sort left part
    QUICKSORT(A, k+1, R)       // Sort right part
  end
```

### QuickSort Example

**Array:** `[10, 4, 2, 6, 9, 3, 8, 5]`

```
QUICKSORT(A, 1, 8)
  PARTITION → k=4, A = [4, 2, 3, 5, 9, 10, 8, 6]
  
  QUICKSORT(A, 1, 3)  // [4, 2, 3]
    PARTITION → k=2, A = [2, 3, 4, 5, 9, 10, 8, 6]
    QUICKSORT(A, 1, 1)  // [2] - base case
    QUICKSORT(A, 3, 3)  // [4] - base case
  
  QUICKSORT(A, 5, 8)  // [9, 10, 8, 6]
    PARTITION → k=5, A = [2, 3, 4, 5, 6, 10, 8, 9]
    QUICKSORT(A, 6, 8)  // [10, 8, 9]
      PARTITION → k=7, A = [2, 3, 4, 5, 6, 8, 9, 10]
      ...

Result: [2, 3, 4, 5, 6, 8, 9, 10] ✅
```

### QuickSort Properties

**Advantages:**

- In-place sorting (no extra space)
- Fast average case: O(n log n)
- Cache-friendly (works on contiguous memory)

**Disadvantages:**

- Worst case O(n²) if pivot is always smallest/largest
- Not stable (equal elements may swap order)
- Performance depends on pivot choice

**Optimization:** Use random pivot or median-of-three to avoid worst case

## MergeSort

### Core Idea

**MergeSort recursively divides the array in half until single elements remain, then merges sorted halves back together.**

### Divide & Conquer Structure

1. **DIVIDE:** Split array strictly in half (simple, no work)
2. **CONQUER:** Recursively sort both halves
3. **COMBINE:** Merge two sorted halves (main work happens here)

### Key Concepts

#### Merging

Combining two **already sorted** arrays into one sorted array.

**Example:**

```
P = [2, 4, 6, 10]  (sorted)
Q = [3, 5, 8, 9]   (sorted)

Result: [2, 3, 4, 5, 6, 8, 9, 10]
```

**Process:**

1. Compare first elements of P and Q
2. Take the smaller one, add to result
3. Move pointer in that array
4. Repeat until one array is empty
5. Copy remaining elements from non-empty array

### The MERGE Algorithm

```
MERGE(A, L, M, R)
  // A[L..M] and A[M+1..R] are sorted
  // Temp[1..n] is temporary work array
  
  // Copy A to Temp
  for i from L to R
    Temp[i] = A[i]
  end
  
  iL = L           // position in left subarray
  iR = M + 1       // position in right subarray
  iA = L           // position in result array A
  
  // Compare and merge
  while iL ≤ M and iR ≤ R
    if Temp[iL] ≤ Temp[iR] then
      A[iA] = Temp[iL]
      iL = iL + 1
    else
      A[iA] = Temp[iR]
      iR = iR + 1
    end
    iA = iA + 1
  end
  
  // Copy remainder from left part
  if iL > M then
    copy Temp[iR..R] to A[iA..R]
  else
    copy Temp[iL..M] to A[iA..R]
  end
end
```

### MERGE Example Step-by-Step

**Array:** `A = [2, 4, 6, 10, 3, 5, 8, 9]` (merge `[2,4,6,10]` and `[3,5,8,9]`)

|Iteration|iL|iR|iA|Comparison|Action|Array A|
|---|---|---|---|--:|---|---|
|0|1|5|1|2 < 3|Take 2 from left|`[2, 4, 6, 10, 3, 5, 8, 9]`|
|1|2|5|2|4 > 3|Take 3 from right|`[2, 3, 6, 10, 3, 5, 8, 9]`|
|2|2|6|3|4 < 5|Take 4 from left|`[2, 3, 4, 10, 3, 5, 8, 9]`|
|3|3|6|4|6 > 5|Take 5 from right|`[2, 3, 4, 5, 3, 5, 8, 9]`|
|4|3|7|5|6 < 8|Take 6 from left|`[2, 3, 4, 5, 6, 5, 8, 9]`|
|5|4|7|6|10 > 8|Take 8 from right|`[2, 3, 4, 5, 6, 8, 8, 9]`|
|6|4|8|7|10 > 9|Take 9 from right|`[2, 3, 4, 5, 6, 8, 9, 9]`|
|End|4|9|8|Right empty|Copy remainder [10]|`[2, 3, 4, 5, 6, 8, 9, 10]` ✅|

### The MERGESORT Algorithm

```
MERGESORT(A, L, R)
  if L < R then
    M = ⌊(L + R)/2⌋           // Find middle
    MERGESORT(A, L, M)        // Sort left half
    MERGESORT(A, M+1, R)      // Sort right half
    MERGE(A, L, M, R)         // Merge sorted halves
  end
```

### MergeSort Example

**Array:** `[10, 4, 2, 6]`

```
                [10, 4, 2, 6]
                      |
          ┌───────────┴───────────┐
          |                       |
      [10, 4]                 [2, 6]
          |                       |
     ┌────┴────┐             ┌────┴────┐
     |         |             |         |
   [10]      [4]           [2]       [6]
     |         |             |         |
     └────┬────┘             └────┬────┘
          |                       |
      [4, 10]                 [2, 6]
          |                       |
          └───────────┬───────────┘
                      |
                [2, 4, 6, 10] ✅
```

**Step-by-step execution:**

|Step|Action|Array State|
|---|---|---|
|1|MERGESORT(A, 1, 4) starts|`[10, 4, 2, 6]`|
|2|MERGESORT(A, 1, 2)|`[10, 4, 2, 6]`|
|3|MERGESORT(A, 1, 1) - base case|`[10, 4, 2, 6]`|
|4|MERGESORT(A, 2, 2) - base case|`[10, 4, 2, 6]`|
|5|MERGE(A, 1, 1, 2)|`[4, 10, 2, 6]`|
|6|MERGESORT(A, 3, 4)|`[4, 10, 2, 6]`|
|7|MERGESORT(A, 3, 3) - base case|`[4, 10, 2, 6]`|
|8|MERGESORT(A, 4, 4) - base case|`[4, 10, 2, 6]`|
|9|MERGE(A, 3, 3, 4)|`[4, 10, 2, 6]`|
|10|MERGE(A, 1, 2, 4)|`[2, 4, 6, 10]` ✅|

### Why Do We Need Temp Array?

**Problem:** If we try to merge directly in array A, we overwrite elements that we still need to compare.

**Example of failure without Temp:**

```
A = [4, 10, 2, 6]
     ↑      ↑
     iL     iR

Compare 4 and 2 → take 2
Write A[0] = 2 → ⚠️ OVERWRITES 4! We lost it!
```

**Solution:** Use temporary array Temp to build result, then copy back to A.

### Three Pointers in MERGE

- **iL:** current position in LEFT part
- **iR:** current position in RIGHT part
- **iA:** current position where we write in result

All three move during the merge process.

### Why Copy Remainder?

When one part is exhausted, the other part may still have elements. Since both parts are already sorted, all remaining elements are larger than everything already merged.

**Safe to just copy them to the end!**

```
Left: [2, 4, 6, 10]
                ↑ iL (10 remains)
Right: [3, 5, 8, 9]
                   ↑ (empty)

Result so far: [2, 3, 4, 5, 6, 8, 9, _]

Remaining 10 is guaranteed to be largest → just copy it!
```

### MergeSort Properties

**Advantages:**

- Guaranteed O(n log n) - always predictable
- Stable sort (preserves order of equal elements)
- Good for linked lists (no random access needed)
- Parallelizable (independent subproblems)

**Disadvantages:**

- Requires O(n) extra space for Temp array
- Slower than QuickSort in practice (more copying)
- Not in-place

## Comparison Summary

### When Work Happens

**QuickSort:**

- Heavy work in **DIVIDE** (partitioning)
- Light work in CONQUER (just recursive calls)
- No COMBINE needed

**MergeSort:**

- Light work in DIVIDE (just find middle)
- Light work in CONQUER (just recursive calls)
- Heavy work in **COMBINE** (merging)

### Division Strategy

**QuickSort:**

```
[10, 4, 2, 6, 9, 3, 8, 5]  (pivot = 5)
             ↓
[4, 2, 3] [5] [9, 10, 8, 6]
  (3)      (1)    (4)         ⚠️ Unbalanced!
```

**MergeSort:**

```
[10, 4, 2, 6, 9, 3, 8, 5]
         ↓
[10, 4, 2, 6] [9, 3, 8, 5]
    (4)           (4)        ✅ Always balanced!
```

### Space Complexity

|Algorithm|Space|Reason|
|---|---|---|
|QuickSort|O(log n)|Recursion stack only|
|MergeSort|O(n)|Temp array + recursion stack|

### Time Complexity

|Case|QuickSort|MergeSort|
|---|---|---|
|**Best**|O(n log n)|O(n log n)|
|**Average**|O(n log n)|O(n log n)|
|**Worst**|O(n²)|O(n log n)|

### Stability

**Stable sort:** preserves relative order of equal elements

```
Input: [3a, 2, 3b, 1]

Stable:   [1, 2, 3a, 3b]  ✅ (3a before 3b preserved)
Unstable: [1, 2, 3b, 3a]  ❌ (order changed)
```

- **QuickSort:** Not stable (swaps can change order)
- **MergeSort:** Stable (merge preserves order when equal)

## Practical Considerations

### When to Use QuickSort

- Need in-place sorting (limited memory)
- Average case is important (and you can randomize pivot)
- Working with arrays (cache-friendly)
- Don't need stable sort

### When to Use MergeSort

- Need guaranteed O(n log n) performance
- Need stable sort
- Working with linked lists
- Can afford O(n) extra space
- Parallelization is important

### Hybrid Approaches

Many real-world implementations use combinations:

**Introsort (C++ std::sort):**

- Start with QuickSort
- Switch to HeapSort if recursion too deep (avoid O(n²))
- Use InsertionSort for small subarrays

**Timsort (Python sorted()):**

- Based on MergeSort
- Optimized for real-world data with runs of sorted elements
- Uses InsertionSort for small runs

## Key Takeaways

### QuickSort

1. Pivot determines division (can be unbalanced)
2. Main work in PARTITION (DIVIDE phase)
3. In-place, but not stable
4. Fast average case, but O(n²) worst case
5. No COMBINE step needed

### MergeSort

1. Always divides exactly in half (balanced)
2. Main work in MERGE (COMBINE phase)
3. Requires extra space, but stable
4. Always O(n log n) - predictable
5. One Temp array reused for all merges

### Both

- Divide & Conquer algorithms
- O(n log n) average time complexity
- Recursive implementations
- Much faster than O(n²) algorithms like Bubble/Selection Sort
