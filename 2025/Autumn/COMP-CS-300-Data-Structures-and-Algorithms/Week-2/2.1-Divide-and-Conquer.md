# Divide and Conquer: Design Principle

## What is Divide and Conquer?

**Divide and Conquer (D&C)** is an algorithm design strategy that breaks down a problem into smaller subproblems, solves them, and combines their solutions.

---

## The Three Phases

Every D&C algorithm follows this pattern:

1. **DIVIDE** - Split the problem into multiple independent subproblems (usually of roughly equal size)
2. **CONQUER** - Solve each subproblem recursively (or directly if small enough)
3. **COMBINE** - Merge the solutions of subproblems into a solution for the original problem

**Base Case:** D&C continues dividing until subproblems are small enough to have a simple, direct solution (analogous to the base case in recursion).

---

## Divide and Conquer vs Recursion

**Key distinction:** D&C is a design principle, recursion is an implementation technique.

### Key Differences

|Aspect|Recursion|Divide and Conquer|
|---|---|---|
|**Definition**|Function calls itself|Algorithm design strategy|
|**Structure**|Can be linear (chain)|Must be branching (tree)|
|**Subproblems**|May have just 1|Has ≥2 independent subproblems|
|**Combine phase**|Not required|**Required**|

### Can Exist Independently

- **D&C without recursion:** Iterative MergeSort
- **Recursion without D&C:** Factorial, countdown

### Example: Factorial (Recursion, NOT D&C)

Factorial is recursive but **NOT** divide and conquer:

```cpp
int factorial(int n) {
    if (n == 0) return 1;
    return n * factorial(n - 1);
}
```

**Why not D&C?**

- Only creates **1 subproblem** (n-1), not multiple independent ones
- No COMBINE step - just multiplies by n
- Linear chain structure: `factorial(5) → 5 * factorial(4) → 4 * factorial(3) → ...`

This demonstrates that **recursion ≠ divide and conquer**.

## Application: Tiling a Grid with L-Trominoes

### Problem Statement

**Given:**

- A 2ⁿ × 2ⁿ grid of squares
- Exactly one square is already filled
- Unlimited supply of L-shaped trominoes (3 squares in L-shape)

**Goal:** Fill the entire grid with trominoes (no overlaps, no gaps)

### Base Case (n=1)

For a 2×2 grid with one filled square, the solution is trivial: place one tromino to fill the remaining 3 squares.

### Recursive Case (n>1)

**Key insight:** When we divide a 2ⁿ × 2ⁿ grid into four 2ⁿ⁻¹ × 2ⁿ⁻¹ quadrants, only **ONE** quadrant contains the pre-filled square. The other three are empty.

**Challenge:** Our recursive function expects EVERY quadrant to have exactly one filled square.

**Solution:** Place one L-tromino at the center of the grid, filling one square in each of the three empty quadrants.

### The D&C Algorithm

```
TROMINOFILL(n, loc)
  if n == 1 then
    place a tromino to fill the empty squares
  else
    divide grid into four 2^(n-1) × 2^(n-1) quadrants
    place one tromino at center (fills 3 empty quadrants)
    for each quadrant
      TROMINOFILL(quadrant, location_of_filled_square)
    end
  end
```

### Why Place Central Tromino BEFORE Recursion?

**Unusual order:** DIVIDE → **COMBINE** → CONQUER (not the typical DIVIDE → CONQUER → COMBINE)

**Why?** Each recursive call expects a quadrant with exactly one filled square. The central tromino **creates this precondition** for the three initially-empty quadrants.

**Order of operations:**

1. **DIVIDE:** Split into 4 quadrants
2. **COMBINE:** Place central tromino (prepares subproblems)
3. **CONQUER:** Recursively fill each quadrant

**Typical D&C:** Combine happens _after_ solving subproblems (like MergeSort)  
**Tiling problem:** Combine happens _before_ to prepare subproblems for recursion

---

## Why Use Divide and Conquer?

Reasons to choose D&C:

1. **Nature of the problem** - Some problems naturally decompose into independent subproblems
2. **Efficiency** - Can lead to better asymptotic complexity (e.g., O(n log n) vs O(n²))
3. **Data structure design** - Some structures are intentionally D&C-friendly (trees, arrays)
4. **Parallelization** - Independent subproblems can be solved in parallel

---

## D&C-Friendly Data Structures

### Array

**D&C operations:**

- **MergeSort:** divide array, sort halves, merge
- **QuickSort:** partition around pivot, sort subarrays

**Divide-only operations (no combine):**

- **Binary Search:** divide array, search one half only

**Limitations:**

- Cannot use D&C for inserting/deleting elements (array is fixed-size)

### Binary Search Tree (BST)

**Why D&C-friendly:** Both left and right subtrees of a node are themselves BSTs

**D&C operations:**

- **Inorder traversal:** traverse left, visit node, traverse right → produces sorted list
- **Computing height:** `height = 1 + max(height(left), height(right))`

**Divide-only operations (no combine):**

- Inserting element: choose left or right subtree
- Deleting element: locate in left or right subtree
- Searching: follow left or right path
