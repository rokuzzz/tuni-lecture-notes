## What is a Heap?

A **heap** is a **binary tree** with three special properties that make it useful for priority queues and sorting.

### The Three Heap Properties

**Property 1: Parent-Child Ordering (MAX-HEAP)**

- Parent's key ≥ children's keys
- **Max-heap**: Largest element at root
- **Min-heap**: Smallest element at root (parent ≤ children)

**Property 2: Complete Except Last Level**

- All levels fully filled, except possibly the last
- Maximum number of nodes at each depth

**Property 3: Left-Aligned Bottom Level**

- At deepest level, missing nodes must be on the **right**
- No "holes" in the middle

### Heap Parameters

```
n       = number of nodes in heap
n_leaf  = number of leaves = ⌈n/2⌉
h       = height of heap

Relationship:  2^h ≤ n < 2^(h+1)
Therefore:     h = ⌊log₂(n)⌋
```

### Important Notes

1. Property 1 defines a **max-heap**. In a **min-heap**, the parent's key is at most as large as its children's keys.
    
2. Given a set of keys, there may be **several different binary trees** that satisfy the heap properties. Hence a heap is **not unique**.
    
3. For each node, **both its right subtree and its left subtree are heaps** (suitable for recursion).
    
4. In a max-heap, the **maximum key is always at the root** (O(1) access).

## Heap Algorithms

### Four Core Operations

|Algorithm|Purpose|Complexity|
|---|---|---|
|**HEAP-INSERT**|Add new element|O(log n)|
|**HEAPIFY**|Fix one violation|O(log n)|
|**BUILD-HEAP**|Create heap from scratch|**O(n)**|
|**HEAP-EXTRACT-MAX**|Remove root|O(log n)|

### Algorithm Assumptions

The following are always available:

- `node.parent` = pointer to parent of node or NIL if node is heapRoot
- `node.left` = pointer to left child of node or NIL if there is no left child
- `node.right` = pointer to right child of node or NIL if there is no right child
- `node.key` = key value associated with node
- `heapRoot` = root node of heap (represents entire heap)
- `height` = the height of the heap

## HEAP-INSERT

### What It Does

Adds a new element to an existing heap while maintaining heap properties.

### Algorithm Strategy

1. Insert element as **rightmost leaf** at deepest level
2. **Percolate UP** (bubble up) by swapping with parent if larger
3. Stop when parent ≥ new element or reach root

### Pseudocode

```
HEAP-INSERT(heapRoot, node)
  input: heap root and new node to add
  
  // Step 1: Find insertion position
  if depth is not full then
    insert node as rightmost leaf at current depth
  else
    insert node as leftmost leaf at next depth
  end
  
  // Step 2: Percolate up (bubble up)
  while (node ≠ heapRoot and node.key > node.parent.key)
    SWAP(node, node.parent)
  end
```

**NOTE:** In a SWAP, a node retains its key, but its pointers are updated.

### Visual Example

**Start:** Heap with 6 nodes, insert **95**

```
Step 1: Insert as rightmost leaf
       79
      /  \
    42   75
   / \   / \
  32 19 15  95  ← New node

Step 2: Compare 95 with parent 75
       79
      /  \
    42   95      ← Swapped!
   / \   / \
  32 19 15  75

Step 3: Compare 95 with parent 79
       95         ← Swapped!
      /  \
    42   79
   / \   / \
  32 19 15  75

Done! 95 is now at root (largest element)
```

### Why O(log n)?

- **Worst case:** New element becomes root
- **Path length:** Height of tree = ⌊log₂(n)⌋
- **Operations:** At most h swaps
- **Therefore:** O(h) = O(log n)

## HEAPIFY

### What It Does

Fixes heap property for a subtree where **only the root** might violate the ordering (children's subtrees are already valid heaps).

### Algorithm Strategy

1. Compare root with **both children**
2. Find **largest** of the three
3. If root is not largest, **swap** with larger child
4. **Recursively** fix the affected subtree
5. Stop when root is largest or reach leaf

### Pseudocode

```
HEAPIFY(heapRoot, node1)
  input: heap root and node that may violate property
  
  node2 = NIL
  while (node1 ≠ node2)
    node2 = node1
    L = node1.left,  R = node1.right
    
    // Find largest of node1, L, R
    if (L exists and L.key > node2.key) then
      node2 = L
    end
    if (R exists and R.key > node2.key) then
      node2 = R
    end
    
    // Swap if needed
    if (node1 ≠ node2) then
      SWAP(node1, node2)
    end
  end
```

### Key Insight: Compare with BOTH Children

**Why not just left or right?**

We need to swap with the **larger** child to maintain heap property!

**Example:**

```
       2  ← Too small!
      / \
    14   11

If we only checked left:
  Swap with 14 → [14, 2, 11]
  But now 2 < 11 → Still broken!

Correct approach:
  Compare 2 with max(14, 11) = 14
  Swap with 14 → [14, 2, 11] ✓
```

### Visual Example

**Start:** Node 2 violates heap property

```
Step 1: Original tree
       2  ← Problem!
      / \
    14   11
   / \   / \
  7   8  5   3

Step 2: Compare 2 with children (14, 11)
        Largest = 14, swap 2 ↔ 14
       14
      / \
    2    11
   / \   / \
  7   8  5   3

Step 3: Compare 2 with children (7, 8)
        Largest = 8, swap 2 ↔ 8
       14
      / \
    8    11
   / \   / \
  7   2  5   3

Step 4: Node 2 is now a leaf → Done!
```

### Why O(log n)?

- **Worst case:** Element sinks to bottom
- **Path length:** Height of tree = ⌊log₂(n)⌋
- **Therefore:** O(h) = O(log n)

## BUILD-HEAP

### What It Does

Converts an arbitrary binary tree into a valid heap.

### Algorithm Strategy

1. Start from **bottom-up** (leaves to root)
2. Call HEAPIFY on **internal nodes only** (leaves already valid)
3. Process nodes at depth h-1, h-2, ..., 0
4. Each HEAPIFY fixes one subtree

### Pseudocode

```
BUILD-HEAP(heapRoot)
  input: binary tree with heap shape (Properties 2 & 3)
  output: valid heap (adds Property 1)
  
  for i from height-1 down to 0
    forEach internal node at depth i (right to left)
      HEAPIFY(heapRoot, node)
    end
  end
```

### Visual Example

**Start:** Tree with correct shape but wrong ordering

```
Original:
       2
      / \
    14   11
   / \   / \
  7   8  5   3

Step 1: HEAPIFY at depth 1 (nodes 14 and 11)
        No changes needed (already larger than children)

Step 2: HEAPIFY at depth 0 (node 2)
       14        ← 2 percolated down
      / \
    8    11
   / \   / \
  7   2  5   3

Result: Valid heap!
```

### Why O(n)? (Surprisingly Fast!)

**Intuition:** Most nodes are near bottom, don't move far.

**Detailed Analysis:**

|Depth|# Nodes|Max swaps per node|Total work|
|---|---|---|---|
|h (leaves)|≈n/2|0|0|
|h-1|≈n/4|1|n/4|
|h-2|≈n/8|2|2n/8 = n/4|
|h-3|≈n/16|3|3n/16|
|...|...|...|...|
|0 (root)|1|h|h|

**Total work:**

```
n/4 + n/4 + 3n/16 + ... ≤ 2n = O(n)
```

**Key Insight:** Even though each HEAPIFY is O(log n), most calls happen on small subtrees!

## HEAP-EXTRACT-MAX

### What It Does

Removes the root (maximum element) and restores heap properties.

### Algorithm Strategy

1. Save root value (this is the max)
2. Replace root with **rightmost leaf** at deepest level
3. Remove that leaf
4. Call **HEAPIFY** on new root
5. Return saved maximum

### Pseudocode

```
HEAP-EXTRACT-MAX(heapRoot)
  input: valid heap
  output: maximum key
  
  max = heapRoot.key
  
  // Replace root with rightmost leaf
  node = rightmost leaf at depth height
  heapRoot.key = node.key
  
  // Remove leaf
  remove node from heap
  if node was only node at depth then
    height = height - 1
  end
  
  // Restore heap property
  HEAPIFY(heapRoot, heapRoot)
  
  return max
```

### Visual Example

```
Step 1: Original heap
       14
      / \
    8    11
   / \   / \
  7   2  5   3

Step 2: Save max (14), replace with rightmost leaf (3)
       3  ← Replaced with 3
      / \
    8    11
   / \   /
  7   2  5

Step 3: HEAPIFY from root
       11        ← 3 sank down
      / \
    8    5
   / \   /
  7   2  3

Result: New valid heap, return 14
```

### Why O(log n)?

- Replacement: O(1)
- HEAPIFY: O(log n)
- **Total:** O(log n)

## Priority Queue

### What is a Priority Queue?

A data structure that allows:

- **Insert** element with priority
- **Extract-Max** (or Extract-Min) — get highest priority element
- Fast access to maximum/minimum

### Heap Implementation

|Operation|Priority Queue|Heap Implementation|Complexity|
|---|---|---|---|
|**Insert**|Add element|HEAP-INSERT|O(log n)|
|**Extract-Max**|Remove max|HEAP-EXTRACT-MAX|O(log n)|
|**Peek-Max**|View max|Read root|O(1)|

### Real-World Uses

- **Task scheduling** - Run highest priority task first
- **Dijkstra's algorithm** - Find shortest path
- **Event simulation** - Process events by time
- **Huffman coding** - Build optimal encoding tree

## HEAPSORT

### Main Idea

Use a heap to sort an array:

1. **BUILD-HEAP** - Convert array to heap
2. Repeatedly **EXTRACT-MAX** and place at end

### Algorithm

```
HEAPSORT(A)
  input: array A[1..n]
  
  // Step 1: Build heap
  BUILD-HEAP(A)
  
  // Step 2: Extract max n-1 times
  for i from n down to 2
    temp = A[i]
    A[i] = A[1]       // Move root to end
    A[1] = temp
    
    heapsize = heapsize - 1
    HEAPIFY(A, 1)     // Restore heap
  end
```

### Visual Example

**Array:** `[3, 8, 4, 5, 6, 2, 11]`

```
Step 1: BUILD-HEAP
        11
       / \
      8   6
     / \  / \
    5  3 2  4

Array: [11, 8, 6, 5, 3, 2, 4]

Step 2: Extract max (11)
        8         | 11
       / \
      5   6
     / \  /
    4  3 2

Array: [8, 5, 6, 4, 3, 2 | 11]
                        ↑ sorted

Step 3: Extract max (8)
        6         | 8  11
       / \
      5   2
     / \
    4  3

Array: [6, 5, 2, 4, 3 | 8, 11]
                     ↑ sorted

Continue until array fully sorted...

Final: [2, 3, 4, 5, 6, 8, 11] ✓
```

### Complexity

|Phase|Operations|Complexity|
|---|---|---|
|**BUILD-HEAP**|Build heap|O(n)|
|**Extractions**|n × HEAPIFY|n × O(log n) = O(n log n)|
|**Total**||**O(n log n)**|

### HEAPSORT Properties

**Advantages:**

- ✅ **O(n log n)** worst case (guaranteed!)
- ✅ **In-place** - no extra memory needed
- ✅ Same complexity as MergeSort

**Disadvantages:**

- ❌ **Not stable** - equal elements may swap order
- ❌ Slower than QuickSort in practice (more swaps)

## Complexity Summary

### All Heap Operations

|Operation|Time Complexity|Space Complexity|
|---|---|---|
|**HEAP-INSERT**|O(log n)|O(1)|
|**HEAPIFY**|O(log n)|O(1)|
|**BUILD-HEAP**|**O(n)**|O(1)|
|**HEAP-EXTRACT-MAX**|O(log n)|O(1)|
|**HEAPSORT**|O(n log n)|O(1)|
|**PEEK-MAX**|O(1)|-|

### Key Insights

**Why is BUILD-HEAP O(n), not O(n log n)?**

- Most nodes are near bottom (don't move far)
- Mathematical series sums to O(n)
- Counterintuitive but proven!

**Why are other operations O(log n)?**

- Maximum path length = height = O(log n)
- Each operation follows one path

**Why is HEAPSORT O(n log n)?**

- BUILD-HEAP: O(n)
- n × EXTRACT-MAX: n × O(log n) = O(n log n)
- Dominated by extraction phase

## Key Takeaways

### Heap Properties

1. **Three properties** define a heap:
    - Parent ≥ children (max-heap)
    - All levels full except last
    - Last level left-aligned
    
2. **Max at root** - Largest element always accessible in O(1)
    
3. **Height is logarithmic** - h = ⌊log₂(n)⌋
    

### Heap Operations

4. **INSERT and EXTRACT** - Both O(log n)
    - Insert: bubble up
    - Extract: replace with leaf, sink down
    
5. **HEAPIFY** - Fix one violation in O(log n)
    
6. **BUILD-HEAP** - Create heap in **O(n)** (not O(n log n)!)
    

### HeapSort

7. **O(n log n) guaranteed** - No worst case like QuickSort's O(n²)
    
8. **In-place** - No extra memory like MergeSort
    
9. **Not stable** - Equal elements may change order
    

### Real World

10. **Hybrid algorithms win** - Production code uses combinations
    
11. **Timsort everywhere** - Python, Java objects, JavaScript
    
12. **HeapSort in Introsort** - C++ uses it as safety mechanism
