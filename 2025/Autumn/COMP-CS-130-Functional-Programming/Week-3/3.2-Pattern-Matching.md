## Core Concept

**Pattern matching** allows you to define separate function bodies for different input patterns. Instead of complex if-else chains, you specify patterns that data should conform to, and Haskell checks them from top to bottom until it finds a match.

**Key benefits:**

- Cleaner, more readable code
- Automatic data deconstruction
- Works with any data type (numbers, characters, lists, tuples)

## Basic Pattern Matching

### Simple Value Matching
```haskell
lucky :: (Integral a) => a -> String
lucky 7 = "LUCKY NUMBER SEVEN!"
lucky x = "Sorry, you're out of luck, pal!"
```

**How it works:**

- First pattern matches only if input is exactly 7
- Second pattern is a **catch-all** that matches anything and binds it to `x`
- Order matters - patterns checked from top to bottom

### Multiple Specific Patterns
```haskell
sayMe :: (Integral a) => a -> String
sayMe 1 = "One!"
sayMe 2 = "Two!"
sayMe 3 = "Three!"
sayMe 4 = "Four!"
sayMe 5 = "Five!"
sayMe x = "Not between 1 and 5"
```

**Critical rule:** Always put catch-all patterns last. If you put `sayMe x` first, it would catch everything and other patterns would never be reached.

## Recursive Pattern Matching

Pattern matching works perfectly with recursion:
```haskell
factorial :: (Integral a) => a -> a
factorial 0 = 1               -- Base case
factorial n = n * factorial (n - 1)  -- Recursive case
```

**Execution trace for factorial 3:**

1. factorial 3 → 3 * factorial 2
2. factorial 2 → 2 * factorial 1
3. factorial 1 → 1 * factorial 0
4. factorial 0 → 1 (base case matched)
5. Result: 3 * (2 * (1 * 1)) = 6

## Tuple Pattern Matching

Extract tuple components directly in function parameters:
```haskell
-- Old way using fst/snd
addVectors a b = (fst a + fst b, snd a + snd b)

-- Pattern matching way
addVectors :: (Num a) => (a, a) -> (a, a) -> (a, a)
addVectors (x1, y1) (x2, y2) = (x1 + x2, y1 + y2)
```

### Custom Triple Functions
```haskell
first :: (a, b, c) -> a
first (x, _, _) = x   -- Extract first element, ignore others

second :: (a, b, c) -> b
second (_, y, _) = y  -- Extract second element

third :: (a, b, c) -> c
third (_, _, z) = z   -- Extract third element
```

**The `_` wildcard** means "I don't care about this value" - used when you need to match the pattern but don't use certain parts.

## List Pattern Matching

### Understanding List Structure

Lists in Haskell are built using the `:` (cons) operator:

- `[1,2,3]` is actually `1:2:3:[]`
- `:` prepends an element to a list
- `[]` is the empty list

### Basic List Patterns
```haskell
head' :: [a] -> a
head' [] = error "Can't call head on an empty list!"
head' (x:_) = x  -- x is head, _ is tail (ignored)
```

**Pattern breakdown:**

- `[]` matches empty list
- `(x:_)` matches non-empty list, binds first element to x
- Parentheses required when matching multiple variables

### More Complex List Patterns
```haskell
tell :: (Show a) => [a] -> String
tell [] = "The list is empty"
tell (x:[]) = "The list has one element: " ++ show x
tell (x:y:[]) = "The list has two elements: " ++ show x ++ " and " ++ show y
tell (x:y:_) = "This list is long. The first two elements are: " ++ show x ++ " and " ++ show y
```

**Alternative notation:**

- `(x:[])` can be written as `[x]` (single element list)
- `(x:y:[])` can be written as `[x,y]` (two element list)
- `(x:y:_)` cannot use square brackets (matches 2+ elements)

### Recursive List Processing

#### Length Function
```haskell
length' :: (Num b) => [a] -> b
length' [] = 0                -- Base case: empty list
length' (_:xs) = 1 + length' xs  -- Recursive: 1 + length of tail
```

**Execution trace for `length' "ham"`:**

1. `length' "ham"` → `1 + length' "am"`
2. `length' "am"` → `1 + length' "m"`
3. `length' "m"` → `1 + length' ""`
4. `length' ""` → `0` (base case)
5. Result: `1 + (1 + (1 + 0)) = 3`

#### Sum Function
```haskell
sum' :: (Num a) => [a] -> a
sum' [] = 0           -- Base case: sum of empty list is 0
sum' (x:xs) = x + sum' xs  -- Recursive: head + sum of tail
```

### Advanced List Patterns

For matching multiple elements:
```haskell
-- Match first three elements plus rest
pattern x:y:z:zs  -- Matches lists with 3+ elements

-- Example usage
first3 :: [a] -> (a, a, a)
first3 (x:y:z:_) = (x, y, z)
first3 _ = error "List too short"
```

## As-Patterns (@)

**As-patterns** let you match a pattern while keeping reference to the whole thing:
```haskell
capital :: String -> String
capital "" = "Empty string, whoops!"
capital all@(x:xs) = "The first letter of " ++ all ++ " is " ++ [x]
```

**Why use `all@(x:xs)`?**

- `x` gets the first character
- `xs` gets the rest
- `all` keeps reference to the entire original string
- Avoids repeating the pattern in the function body

**Without as-pattern you'd need:**
```haskell
capital (x:xs) = "The first letter of " ++ (x:xs) ++ " is " ++ [x]  -- Repetitive!
```

## Pattern Matching in List Comprehensions

You can use pattern matching directly in list comprehensions:
```haskell
-- Extract and sum tuple pairs
xs = [(1,3), (4,3), (2,4), (5,3), (5,6), (3,1)]
[a+b | (a,b) <- xs]  -- Result: [4,7,6,8,11,4]
```

If pattern matching fails for an element, it's simply skipped.

## Important Rules and Limitations

### Pattern Order Matters

- Patterns checked from top to bottom
- First match wins
- Always put specific patterns before general ones
- Catch-all patterns go last

### Exhaustive Patterns

Always include a catch-all pattern to avoid runtime crashes:
```haskell
-- BAD: Non-exhaustive patterns
charName 'a' = "Albert"
charName 'b' = "Broseph"
-- What if someone calls charName 'x'? → Runtime error!

-- GOOD: Exhaustive patterns
charName 'a' = "Albert"
charName 'b' = "Broseph"
charName _ = "Unknown"  -- Catch-all prevents crashes
```

### What You Cannot Do

**Cannot use `++` in patterns:**
```haskell
-- This doesn't work:
someFunc (xs ++ ys) = ...  -- Error! Can't determine where to split
```

**Why:** Haskell can't figure out what should go in `xs` vs `ys` when matching against a list.

## Practical Tips

1. **Start with specific cases, end with general ones**
2. **Always include catch-all patterns** to prevent crashes
3. **Use _ for values you don't need** to make intent clear
4. **Parentheses are required** when matching multiple variables with `:`
5. **As-patterns (@) avoid repetition** when you need both parts and whole
6. **Pattern matching often pairs with recursion** for list processing

## Common Patterns

- `[]` - empty list
- `(x:xs)` - non-empty list (head and tail)
- `(x:_)` - non-empty list (only care about first element)
- `[x]` - exactly one element
- `[x,y]` - exactly two elements
- `(x:y:_)` - at least two elements
- `all@(x:xs)` - match pattern but keep reference to whole thing
