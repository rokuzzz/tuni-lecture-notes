## Core Type System Concepts

**What is a type?** A type is a label that every expression has, telling us which category of things that expression fits into.

**Static typing** means the type of every expression is known at compile time, leading to safer code. Type errors are caught before the program runs, not during execution.

**Type inference** allows the compiler to automatically deduce types without explicit declarations, though we can still specify them when needed.

### Checking Types in GHCI

Use `:t` command to examine types of expressions:
```haskell
ghci> :t 'a'           -- 'a' :: Char
ghci> :t True          -- True :: Bool
ghci> :t "HELLO!"      -- "HELLO!" :: [Char]
ghci> :t (True, 'a')   -- (True, 'a') :: (Bool, Char)
```

**Key notation:**

- `::` reads as "has type of"
- Types always start with capital letters
- `[Char]` means list of characters (a string)

## Basic Types

### Numeric Types

- `Int` - bounded integers (e.g., -2147483648 to 2147483647 on 32-bit machines)
- `Integer` - unbounded integers (can be arbitrarily large, but less efficient)
- `Float` - single-precision floating point numbers
- `Double` - double-precision floating point (more accurate than Float)

### Other Fundamental Types

- `Bool` - boolean type (True or False)
- `Char` - single character (in single quotes: 'a')
- `String` = `[Char]` - strings are lists of characters

### Composite Types

**Tuples** - fixed size, can contain mixed types:

- `(Bool, Char)` is different from `(Bool, Char, Int)`
- Each tuple length has its own distinct type
- Empty tuple `()` is both a type and its only value

### Function Types

Functions have types too. It's good practice to give functions explicit type declarations:
```haskell
-- Function taking one parameter
removeNonUppercase :: [Char] -> [Char]
removeNonUppercase st = [c | c <- st, c `elem` ['A'..'Z']]

-- Function taking multiple parameters
addThree :: Int -> Int -> Int -> Int
addThree x y z = x + y + z
```

**Function type syntax:**

- Parameters and return type separated by `->`
- Return type is the last item in the declaration
- No special distinction between parameters and return type

### Type Variables

**Type variables** (like `a`, `b`, `c`) represent "any type". They're written in lowercase, unlike concrete types.
```haskell
ghci> :t head
head :: [a] -> a  -- takes list of any type, returns element of same type

ghci> :t fst
fst :: (a, b) -> a  -- takes tuple of any two types, returns first element
```

**Polymorphic functions** are functions that have type variables, allowing them to work with multiple types.

## Typeclasses - The Interface System

**Typeclass** is like an interface that defines behavior. If a type is part of a typeclass, it supports and implements the behavior that typeclass describes.

### Class Constraints

**Syntax:** `(Typeclass a) => ...`
```haskell
(==) :: (Eq a) => a -> a -> Bool
```

This reads as: "equality function takes two values of the same type (which must be a member of Eq class) and returns Bool."

### Essential Typeclasses

#### Eq - Equality Testing

- **Operations:** `==` and `/=`
- **Members:** All standard types except IO and functions
- **Usage:** Required when you need to test for equality
```haskell
ghci> 5 == 5      -- True
ghci> 'a' /= 'b'  -- True
```

#### Ord - Ordering

- **Operations:** `>`, `<`, `>=`, `<=`, `compare`
- **Requirement:** Must also be member of Eq
- **Members:** All standard types except functions
```haskell
ghci> 5 > 3            -- True
ghci> "abc" < "xyz"    -- True
ghci> 5 `compare` 3    -- GT (Greater Than)
```

#### Show - String Representation

- **Operation:** `show` (converts to string)
- **Members:** All standard types except functions
```haskell
ghci> show 42    -- "42"
ghci> show True  -- "True"
```

#### Read - Parsing from Strings

- **Operation:** `read` (parses from string)
- **Challenge:** Often needs type annotation to resolve ambiguity
```haskell
ghci> read "42" :: Int   -- 42
ghci> read "True" :: Bool -- True
ghci> read "42"          -- ERROR: ambiguous type
```

#### Enum - Sequential Types

- **Operations:** `succ`, `pred`, list ranges
- **Members:** `()`, Bool, Char, Ordering, Int, Integer, Float, Double
```haskell
ghci> ['a'..'e']  -- "abcde"
ghci> [1..5]      -- [1,2,3,4,5]
ghci> succ 'B'    -- 'C'
```

#### Bounded - Types with Limits

- **Operations:** `minBound`, `maxBound`
- **Examples:**
```haskell
ghci> minBound :: Int   -- -2147483648
ghci> maxBound :: Bool  -- True
```

### Numeric Typeclass Hierarchy
```
Num (all numbers)
├── Integral (whole numbers only)
│   ├── Int
│   └── Integer
└── Fractional (supports division)
    └── Floating (floating point)
        ├── Float
        └── Double
```

**Key relationships:**

- `Num` requires Show and Eq
- `Ord` requires Eq
- `Integral` is subset of Num (Int, Integer)
- `Floating` is subset of Fractional (Float, Double)

#### Numeric Literals

Numbers are polymorphic constants:
```haskell
ghci> :t 20       -- 20 :: (Num t) => t
ghci> 20 :: Int   -- 20
ghci> 20 :: Float -- 20.0
```

#### Type Conversion: fromIntegral
```haskell
fromIntegral :: (Num b, Integral a) => a -> b
```

Converts integral numbers to any numeric type. Essential for mixing integer and floating point operations:
```haskell
-- This fails:
length [1,2,3] + 3.2  -- ERROR: Int + Float

-- This works:
fromIntegral (length [1,2,3]) + 3.2  -- 6.2
```

## Practical Tips

1. **Use :t in GHCI** to check types when uncertain
2. **Add type declarations** to functions (except very short ones)
3. **Understanding constraints** helps predict what operations are available
4. **Type variables** make functions more general and reusable
5. **fromIntegral** is your friend for numeric type conversions
