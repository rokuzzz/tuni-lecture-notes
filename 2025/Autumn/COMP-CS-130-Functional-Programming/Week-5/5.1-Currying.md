## Core Idea of Currying

**Currying** is a technique where a function that takes multiple arguments is transformed into a sequence of functions, each taking a single argument.

In Haskell, **every function officially takes only one parameter**. When we write a function that "takes multiple parameters," it's actually a chain of functions where each takes one parameter and returns the next function.

### Example with the max function
```haskell
max 4 5      -- returns 5
(max 4) 5    -- equivalent notation, returns 5
```

What happens:

1. `max 4` creates a function that takes a parameter and returns either 4 or that parameter (depending on which is bigger)
2. Then 5 is applied to that function
3. We get the result 5

## Types and Currying

Consider the type of the `max` function:
```haskell
max :: (Ord a) => a -> a -> a
```

This type can be read as:
```haskell
max :: (Ord a) => a -> (a -> a)
```

Meaning: "max takes an `a` and returns a function that takes an `a` and returns an `a`".

**Important:** The thing before the arrow `->` is the parameter the function takes. The thing after the arrow is what the function returns.

### Example with multThree
```haskell
multThree :: (Num a) => a -> a -> a -> a
multThree x y z = x * y * z
```

Full type with explicit parentheses:
```haskell
multThree :: (Num a) => a -> (a -> (a -> a))
```

Step-by-step application:
```haskell
multThree 3      -- returns a function of type a -> (a -> a)
multThree 3 5    -- returns a function of type a -> a
multThree 3 5 9  -- returns a concrete value: 135
```

## Partial Application

**Partial application** is calling a function with fewer parameters than it expects. The result is a new function that expects the remaining parameters.

### Partial Application Examples
```haskell
-- Creating specialized functions
let multTwoWithNine = multThree 9
multTwoWithNine 2 3  -- result: 54 (i.e., 9 * 2 * 3)

let multWithEighteen = multTwoWithNine 2
multWithEighteen 10  -- result: 180 (i.e., 9 * 2 * 10)
```

### Practical Example: compareWithHundred

Non-optimized version:
```haskell
compareWithHundred :: (Num a, Ord a) => a -> Ordering
compareWithHundred x = compare 100 x
```

Optimized version with partial application:
```haskell
compareWithHundred :: (Num a, Ord a) => a -> Ordering
compareWithHundred = compare 100
```

Why this works: `compare 100` returns a function of type `a -> Ordering` that compares its argument with 100. This is exactly the function we need!

## Sections

**Sections** are a way to partially apply infix operators (operators that are written between their arguments).

### Section Syntax

To create a section:

1. Wrap the operator in parentheses
2. Supply only one argument on one side
```haskell
(/10)  -- function that divides its argument by 10
(10/)  -- function that divides 10 by its argument
(+3)   -- function that adds 3 to its argument
```

### Section Usage Examples
```haskell
divideByTen :: (Floating a) => a -> a
divideByTen = (/10)

-- Usage:
divideByTen 200  -- result: 20.0

isUpperAlphanum :: Char -> Bool
isUpperAlphanum = (`elem` ['A'..'Z'])
-- Checks if a character is an uppercase letter
```

### Special Case: Minus

The section `(-4)` **doesn't work** as expected — it's just the number minus four.

To create a function that subtracts 4, use:
```haskell
(subtract 4)  -- correct: function that subtracts 4 from its argument
```

## Connection Between Number of Arrows and Parameters

**Rule:** The number of arrows `->` in a function's type shows the number of parameters (if you read the type from left to right up to the last `->`, which denotes the return value).

Examples:
```haskell
a -> a           -- 1 parameter, returns a
a -> a -> a      -- 2 parameters, returns a
a -> a -> a -> a -- 3 parameters, returns a
```

But remember: in reality, these are all single-parameter functions that return other functions!

## Key Points to Remember

1. In Haskell, all functions take only one parameter
2. Functions of "multiple parameters" are curried functions (chains of functions)
3. Partial application creates new functions "on the fly"
4. Sections allow partial application of infix operators
5. Number of arrows in the type = number of "visible" function parameters
