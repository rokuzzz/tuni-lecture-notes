## What are Higher-Order Functions?

**Higher-order function (HOF)** is a function that does at least one of the following:

- Takes one or more functions as parameters
- Returns a function as its result

Higher-order functions are fundamental to Haskell. They allow us to define computations by describing what things are, rather than specifying step-by-step instructions with loops and state changes.

## Writing Your Own HOFs
### applyTwice

Function that takes a function and applies it twice to a value:
```haskell
applyTwice :: (a -> a) -> a -> a
applyTwice f x = f (f x)
```

**Understanding the type:**

- `(a -> a)` - first parameter is a function that takes a and returns a
- `a` - second parameter is a value of type `a`
- `a` - return value is also of type `a`

The parentheses around `(a -> a)` are mandatory! Without them, the type would be read as `a -> a -> a -> a` (a function taking three separate `a` values).

**How it works:** The function body `f (f x)` applies function `f` to `x`, then applies `f` again to the result.

**Examples:**
```haskell
applyTwice (+3) 10              -- result: 16 (10 + 3 = 13, then 13 + 3 = 16)
applyTwice (++ " HAHA") "HEY"   -- result: "HEY HAHA HAHA"
applyTwice (*2) 5               -- result: 20 (5 * 2 = 10, then 10 * 2 = 20)
applyTwice (multThree 2 2) 9    -- result: 144 (9 * 4 = 36, then 36 * 4 = 144)
```

### zipWith'

Function that combines two lists element-by-element using a provided function:
```haskell
zipWith' :: (a -> b -> c) -> [a] -> [b] -> [c]
zipWith' _ [] _ = []
zipWith' _ _ [] = []
zipWith' f (x:xs) (y:ys) = f x y : zipWith' f xs ys
```

**Understanding the type:**

- `(a -> b -> c)` - first parameter is a function that takes `a` and `b`, returns `c`
- `[a]` - second parameter is a list of type `a`
- `[b]` - third parameter is a list of type `b`
- `[c]` - return value is a list of type `c`

Note: Using three different type variables (`a`, `b`, `c`) makes the function more flexible. The types can be the same or different.

**How it works:**

1. If either list is empty, return empty list (base cases)
2. Otherwise, apply function `f` to first elements of both lists
3. Prepend the result to recursive call on the tails of both lists

**Examples:**
```haskell
zipWith' (+) [4,2,5,6] [2,6,2,3]      -- [6,8,7,9]
zipWith' max [6,3,2,1] [7,3,1,5]      -- [7,3,2,5]
zipWith' (*) [2,3,4] [5,6]            -- [10,18] (stops at shorter list)
zipWith' (++) ["foo "] ["fighters"]   -- ["foo fighters"]
```

### flip'

Function that takes a function and returns a new function with the first two arguments flipped:

**Version 1 (with where):**
```haskell
flip' :: (a -> b -> c) -> (b -> a -> c)
flip' f = g
    where g x y = f y x
```

**Version 2 (simplified using currying):**
```haskell
flip' :: (a -> b -> c) -> b -> a -> c
flip' f y x = f x y
```

Both versions are equivalent. The second version takes advantage of [currying](5.1-Currying.md#core-idea-of-currying) - when we call `flip' f` without `y` and `x`, it returns a function waiting for those parameters.

**Understanding the type:** The parentheses in `(a -> b -> c)` are technically unnecessary due to right-associativity, but they make it clearer that we're taking a function as the first parameter.

**Examples:**
```haskell
flip' zip [1,2,3,4,5] "hello"              -- [('h',1),('e',2),('l',3),('l',4),('o',5)]
zipWith (flip' div) [2,2..] [10,8,6,4,2]   -- [5,4,3,2,1]
```

## Standard Higher-Order Functions

### Map

Applies a function to every element in a list:
```haskell
map :: (a -> b) -> [a] -> [b]
map _ [] = []
map f (x:xs) = f x : map f xs
```

**How it works:**

- Base case: empty list returns empty list
- Recursive case: apply function `f` to head `x`, prepend to result of mapping over tail `xs`

**Examples:**
```haskell
map (+3) [1,5,3,1,6]                   -- [4,8,6,4,9]
map (++ "!") ["BIFF", "BANG", "POW"]   -- ["BIFF!","BANG!","POW!"]
map (*2) [1,2,3,4]                     -- [2,4,6,8]
map fst [(1,2),(3,5),(6,3)]            -- [1,3,6]
```

**Special case - mapping with partially applied functions:**
```haskell
map (*) [0..]  -- creates a list of functions: [(0*), (1*), (2*), (3*), ...]

let listOfFuncs = map (*) [0..]
(listOfFuncs !! 4) 5  -- result: 20 (equivalent to 4 * 5)
```

### Filter

Keeps only elements that satisfy a predicate (a function returning Bool):
```haskell
filter :: (a -> Bool) -> [a] -> [a]
filter _ [] = []
filter p (x:xs)
    | p x       = x : filter p xs
    | otherwise = filter p xs
```

**How it works:**

- Base case: empty list returns empty list
- If predicate `p x` is True, include `x` in result and continue
- If predicate `p x` is False, skip `x` and continue

**Examples:**
```haskell
filter (>3) [1,5,3,2,1,6,4,3,2,1]     -- [5,6,4]
filter even [1..10]                   -- [2,4,6,8,10]
filter (`elem` ['a'..'z']) "u LaUgH aT mE"  -- "uagame"
filter (`notElem` ['0'..'9']) "xy765" -- "xy"
```

### takeWhile

Takes elements from the beginning of a list while a predicate is true, stops at the first element where predicate is false:
```haskell
takeWhile :: (a -> Bool) -> [a] -> [a]
```

**Examples:**
```haskell
takeWhile (/=' ') "elephants know how"  -- "elephants"
takeWhile (<10) [1,3,5,12,7,9]          -- [1,3,5] (stops at 12)
takeWhile (<100) [1..]                  -- [1,2,3,...,99]
```

**Key difference from filter:**

- `filter` checks every element in the list
- `takeWhile` stops as soon as predicate returns False

## Practical Examples

### Collatz Sequences

**The Collatz conjecture:** Start with any natural number. If even, divide by 2. If odd, multiply by 3 and add 1. Repeat. The sequence eventually reaches 1.
```haskell
chain :: (Integral a) => a -> [a]
chain 1 = [1]
chain n
    | even n = n : chain (n `div` 2)
    | odd n  = n : chain (n*3 + 1)
```

Example: `chain 13` produces `[13,40,20,10,5,16,8,4,2,1]`

**Counting long chains:**
```haskell
numLongChains :: Int
numLongChains = length (filter isLong (map chain [1..100]))
    where isLong xs = length xs > 15
```

Step-by-step:

1. `map chain [1..100]` - create Collatz sequences for numbers 1 to 100
2. `filter isLong (...)` - keep only sequences longer than 15 elements
3. `length (...)` - count how many sequences remain

### Working with Infinite Lists

Thanks to lazy evaluation, we can work with infinite lists:
```haskell
sum (takeWhile (<10000) (filter odd (map (^2) [1..])))
-- Result: 166650
```

What happens:

1. `[1..]` - infinite list of natural numbers
2. `map (^2)` - square each number (lazy, not computed immediately)
3. `filter odd` - keep only odd squares (lazy)
4. `takeWhile (<10000)` - take while less than 10,000 (stops the computation!)
5. `sum` - add them all up

The key: `takeWhile` stops the infinite computation when it encounters the first element ≥ 10,000. Only the necessary elements are ever computed.

## Key Points to Remember

1. HOFs take functions as parameters and/or return functions
2. Parentheses in types like `(a -> a)` indicate "this parameter is a function"
3. `map` transforms elements, `filter` selects elements, `takeWhile` stops at first failure
4. Using different type variables (`a`, `b`, `c`) makes functions more flexible
5. Lazy evaluation allows working with infinite lists when combined with functions like `takeWhile`
6. Partial application works perfectly with HOFs - you can create specialized functions to pass to HOFs
