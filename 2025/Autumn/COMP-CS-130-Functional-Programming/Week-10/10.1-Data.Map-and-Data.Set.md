
The `Data.Map` and `Data.Set` modules provide efficient data structures for key-value associations and unique collections. Both are implemented using balanced binary trees, making operations much faster than using lists for large datasets.

---

## Data.Map - Association Lists

**Association lists** (also called dictionaries) store key-value pairs where ordering doesn't matter. You want to retrieve values by their keys quickly.

### Why Use Maps?

**Lists of pairs** work for small datasets:
```haskell
phoneBook = [("Alice","555-1234"), ("Bob","555-5678"), ("Charlie","555-9012")]
```

But searching requires traversing the entire list - O(n) time complexity.

**Maps** use tree structure - O(log n) lookups, much faster for large datasets!

### Importing Data.Map

Always use **qualified import** to avoid name conflicts with Prelude:
```haskell
import qualified Data.Map as Map
```

Now use functions as `Map.fromList`, `Map.insert`, etc.

---

## Creating Maps

### fromList - Convert Association List to Map
```haskell
Map.fromList :: (Ord k) => [(k, v)] -> Map.Map k v

Map.fromList [("Alice","555-1234"), ("Bob","555-5678")]
-- fromList [("Alice","555-1234"),("Bob","555-5678")]
```

**Important:** Key type must be `Ord` (orderable) - Maps need to organize keys in tree structure.

**Duplicate keys:** Later values overwrite earlier ones:
```haskell
Map.fromList [(1,2), (3,4), (3,100), (5,5)]
-- fromList [(1,2),(3,100),(5,5)]  -- (3,4) was replaced by (3,100)
```

### empty - Create Empty Map
```haskell
Map.empty :: Map.Map k v

Map.empty  -- fromList []
```

### singleton - Single Key-Value Pair
```haskell
Map.singleton :: k -> v -> Map.Map k v

Map.singleton 3 9       -- fromList [(3,9)]
Map.singleton "key" 42  -- fromList [("key",42)]
```

---

## Looking Up Values

### lookup - Find Value by Key
```haskell
Map.lookup :: Ord k => k -> Map.Map k v -> Maybe v

m = Map.fromList [("Alice","555-1234"), ("Bob","555-5678")]
Map.lookup "Alice" m  -- Just "555-1234"
Map.lookup "Eve" m    -- Nothing
```

**Returns `Maybe`** - safe! No crashes on missing keys.

### member - Check if Key Exists
```haskell
Map.member :: Ord k => k -> Map.Map k v -> Bool

Map.member "Alice" m  -- True
Map.member "Eve" m    -- False
```

---

## Adding and Removing

### insert - Add or Update Key-Value
```haskell
Map.insert :: Ord k => k -> v -> Map.Map k v -> Map.Map k v

Map.insert 5 600 Map.empty                    -- fromList [(5,600)]
Map.insert 5 600 (Map.insert 4 200 Map.empty) -- fromList [(4,200),(5,600)]
```

**If key exists:** Value is updated (replaced).

### delete - Remove Key
```haskell
Map.delete :: Ord k => k -> Map.Map k v -> Map.Map k v

let m = Map.fromList [(3,100), (4,200), (5,600)]
Map.delete 4 m  -- fromList [(3,100),(5,600)]
```

---

## Map Operations

### size - Number of Key-Value Pairs
```haskell
Map.size Map.empty                                -- 0
Map.size $ Map.fromList [(2,4),(3,3),(4,2),(5,4)] -- 4
```

### null - Check if Empty
```haskell
Map.null Map.empty                     -- True
Map.null $ Map.fromList [(2,3),(5,5)]  -- False
```

### map - Transform All Values
```haskell
Map.map :: (a -> b) -> Map.Map k a -> Map.Map k b

Map.map (*100) $ Map.fromList [(1,1),(2,4),(3,9)]
-- fromList [(1,100),(2,400),(3,900)]
```

**Note:** Only values change, keys remain the same!

### filter - Keep Values Matching Predicate
```haskell
Map.filter :: (a -> Bool) -> Map.Map k a -> Map.Map k a

Map.filter isUpper $ Map.fromList [(1,'a'),(2,'A'),(3,'b'),(4,'B')]
-- fromList [(2,'A'),(4,'B')]
```

---

## Converting Maps

### toList - Map to Association List
```haskell
Map.toList :: Map.Map k a -> [(k, a)]

Map.toList $ Map.insert 9 2 $ Map.singleton 4 3
-- [(4,3),(9,2)]
```

### keys and elems - Extract Keys or Values
```haskell
Map.keys :: Map.Map k a -> [k]
Map.elems :: Map.Map k a -> [a]

m = Map.fromList [("a",1),("b",2),("c",3)]
Map.keys m   -- ["a","b","c"]
Map.elems m  -- [1,2,3]
```

## Handling Duplicates

### fromListWith - Custom Merge Function
```haskell
Map.fromListWith :: Ord k => (a -> a -> a) -> [(k,a)] -> Map.Map k a
```

**Use case:** When duplicate keys should combine values, not replace them.

**Example - Combine phone numbers:**
```haskell
phoneBook = 
    [("Alice","555-2938")
    ,("Alice","342-2492")
    ,("Bob","452-2928")
    ,("Bob","943-2929")
    ]

phoneBookToMap xs = Map.fromListWith (\new old -> new ++ ", " ++ old) xs

Map.lookup "Alice" $ phoneBookToMap phoneBook
-- Just "342-2492, 555-2938"
```

**How it works:**
- First occurrence: `("Alice","555-2938")` → inserted
- Second occurrence: `("Alice","342-2492")` → merges with existing using function
- Result: `"342-2492, 555-2938"`

**Other examples:**
```haskell
-- Keep maximum value for each key
Map.fromListWith max [(2,3),(2,5),(2,100),(3,29)]
-- fromList [(2,100),(3,29)]

-- Sum values for same key
Map.fromListWith (+) [(2,3),(2,5),(2,100),(3,29)]
-- fromList [(2,108),(3,29)]
```

### insertWith - Insert with Merge Function
```haskell
Map.insertWith :: Ord k => (a -> a -> a) -> k -> a -> Map.Map k a -> Map.Map k a

Map.insertWith (+) 3 100 $ Map.fromList [(3,4),(5,103)]
-- fromList [(3,104),(5,103)]  -- 3's value: 4 + 100 = 104
```

## Data.Set - Collections of Unique Elements

**Sets** store unique elements in sorted order. Like mathematical sets - no duplicates, efficient membership testing.

### Why Use Sets?

**Uniqueness guarantee:** Automatically removes duplicates
**Fast operations:** O(log n) for insert, delete, member (vs O(n) for lists)
**Sorted order:** Elements always kept in order

### Importing Data.Set
```haskell
import qualified Data.Set as Set
```

---

## Creating Sets

### fromList - List to Set
```haskell
Set.fromList :: Ord a => [a] -> Set.Set a

Set.fromList [5,3,5,1,3,9]  -- fromList [1,3,5,9]  (duplicates removed, sorted)
Set.fromList "hello world"  -- fromList " dehllorw"
```

**Note:** Elements must be `Ord` - Sets need to maintain sorted order.

### Set Operations Example

Finding common and unique characters between texts:
```haskell
text1 = "I just had an anime dream"
text2 = "The old man left his garbage"

let set1 = Set.fromList text1
let set2 = Set.fromList text2

-- Common characters
Set.intersection set1 set2  -- fromList " adefhilmnt"

-- Only in first text
Set.difference set1 set2    -- fromList "IJcjrsuwy"

-- Only in second text  
Set.difference set2 set2    -- fromList "Tbgo"

-- All unique characters from both
Set.union set1 set2         -- fromList " IJTabcdefghijlmnorstuw"
```

---

## Set Operations

### Basic Operations
```haskell
Set.null Set.empty                    -- True
Set.size $ Set.fromList [3,4,5,4,3]   -- 3 (duplicates don't count)
Set.singleton 9                       -- fromList [9]
Set.member 4 $ Set.fromList [3,4,5]   -- True
```

### Modifying Sets
```haskell
Set.insert 4 $ Set.fromList [1,3,8,9]     -- fromList [1,3,4,8,9]
Set.delete 4 $ Set.fromList [3,4,5,4,3]   -- fromList [3,5]
```

### Set Relations
```haskell
-- Subset: A is subset of B if all elements of A are in B
Set.fromList [2,3,4] `Set.isSubsetOf` Set.fromList [1,2,3,4,5]  -- True

-- Proper subset: subset but not equal
Set.fromList [1,2] `Set.isProperSubsetOf` Set.fromList [1,2,3]  -- True
Set.fromList [1,2] `Set.isProperSubsetOf` Set.fromList [1,2]    -- False
```

### Transforming Sets
```haskell
Set.filter odd $ Set.fromList [3,4,5,6,7,2]   -- fromList [3,5,7]
Set.map (+1) $ Set.fromList [3,4,5,6]         -- fromList [4,5,6,7]
```

## Practical Use Case: Remove Duplicates

**Problem:** Remove duplicates from a list.

**List approach (nub):**
```haskell
import Data.List (nub)
nub "HEY WHATS CRACKALACKIN"  -- "HEY WATSCRKLIN"
```
- Preserves original order
- O(n²) complexity - slow for large lists

**Set approach:**
```haskell
import qualified Data.Set as Set

setNub xs = Set.toList $ Set.fromList xs
setNub "HEY WHATS CRACKALACKIN"  -- " ACEHIKLNRSTWY"
```
- Does NOT preserve order (sorted instead)
- O(n log n) complexity - much faster for large lists!

**Trade-off:** Speed vs order preservation.

## Key Differences: Map vs Set

| Feature | Map | Set |
|---------|-----|-----|
| **Stores** | Key-value pairs | Unique elements |
| **Lookup** | By key → value | Membership test |
| **Use case** | Dictionaries, associations | Unique collections, deduplication |
| **Type requirement** | Keys must be `Ord` | Elements must be `Ord` |
| **Example** | Phone book, student grades | Valid usernames, visited URLs |

---

## When to Use What?

**Use Map when:**
- Need to associate values with keys
- Looking up data by identifier
- Examples: configuration settings, caches, indexes

**Use Set when:**
- Need unique elements only
- Testing membership (is X in the collection?)
- Set operations (union, intersection, difference)
- Examples: tags, categories, visited nodes in graph

**Use Lists when:**
- Order matters and duplicates are meaningful
- Small datasets (< 100 elements)
- Need to maintain insertion order

---

## Remember

- Both Map and Set use **qualified imports** to avoid name conflicts
- Both require `Ord` constraint on keys/elements (for tree structure)
- **O(log n)** operations - much faster than lists for large data
- Maps associate keys with values; Sets guarantee uniqueness
- `fromListWith` and `insertWith` provide flexible duplicate handling
- Sets automatically sort and deduplicate
