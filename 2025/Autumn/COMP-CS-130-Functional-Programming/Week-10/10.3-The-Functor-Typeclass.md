
**Functor** is a typeclass for things that can be mapped over. It's one of the most important typeclasses in Haskell, providing a unified interface for applying functions to values inside containers.

---

## What is a Functor?

Think of a **Functor** as a "container" or "computational context" that holds values, and you want to apply a function to the values inside without changing the container structure.

**Examples of functors:**
- Lists `[]` - container with multiple values
- `Maybe` - container with 0 or 1 value
- Trees - container with hierarchical values
- `Either a` - container that might have error or value

---

## The Functor Typeclass
```haskell
class Functor f where
    fmap :: (a -> b) -> f a -> f b
```

**What this means:**
- `f` is a **type constructor** (like `Maybe`, `[]`, `Tree`)
- `fmap` takes a function `(a -> b)` and applies it to values inside `f a`
- Returns a new container `f b` with transformed values
- **Container structure stays the same!**

**Compare to `map` for lists:**
```haskell
map :: (a -> b) -> [a] -> [b]     -- Only for lists
fmap :: (a -> b) -> f a -> f b    -- For any Functor!
```

`fmap` is the **generalized version** of `map`.

---

## Functor Laws

Every Functor must follow two laws to be predictable:

### Law 1: Identity
```haskell
fmap id = id
```

Mapping the identity function should not change anything.
```haskell
fmap id [1,2,3]      -- [1,2,3]
fmap id (Just 5)     -- Just 5
fmap id Nothing      -- Nothing
```

### Law 2: Composition
```haskell
fmap (f . g) = fmap f . fmap g
```

Mapping composed functions = composing mapped functions.
```haskell
fmap ((+1) . (*2)) [1,2,3]           -- [3,5,7]
(fmap (+1) . fmap (*2)) [1,2,3]      -- [3,5,7]  (same result!)
```

**Why laws matter:**
- Predictable behavior
- Compiler can optimize safely
- Reasoning about code becomes easier

## Functor Instances

### Lists as Functors
```haskell
instance Functor [] where
    fmap = map
```

For lists, `fmap` is just `map`!
```haskell
fmap (*2) [1,2,3]         -- [2,4,6]
fmap show [1,2,3]         -- ["1","2","3"]
fmap (++ "!") ["a","b"]   -- ["a!","b!"]
```

**Empty list:**
```haskell
fmap (*2) []              -- []
```

Structure preserved - empty list stays empty!

### Maybe as Functor
```haskell
instance Functor Maybe where
    fmap f (Just x) = Just (f x)
    fmap f Nothing  = Nothing
```

**How it works:**
- `Just x` - apply function to `x`, wrap in `Just`
- `Nothing` - stay `Nothing`
```haskell
fmap (*2) (Just 5)                -- Just 10
fmap (*2) Nothing                 -- Nothing
fmap show (Just 42)               -- Just "42"
fmap (++ " world") (Just "hello") -- Just "hello world"
```

**Key insight:** Function only applies if value exists!

### Tree as Functor
```haskell
data Tree a = EmptyTree | Node a (Tree a) (Tree a)

instance Functor Tree where
    fmap f EmptyTree = EmptyTree
    fmap f (Node x left right) = Node (f x) (fmap f left) (fmap f right)
```

**How it works:**
- Empty tree stays empty
- For each node: apply function to value, recursively map over subtrees
```haskell
tree = Node 5 (Node 3 EmptyTree EmptyTree) (Node 7 EmptyTree EmptyTree)

fmap (*2) tree
-- Node 10 (Node 6 EmptyTree EmptyTree) (Node 14 EmptyTree EmptyTree)
```

**Structure preserved:** Tree shape stays exactly the same!

### Either as Functor

`Either` has two type parameters, but Functor needs one. Solution: **partially apply** the first parameter!
```haskell
instance Functor (Either a) where
    fmap f (Right x) = Right (f x)
    fmap f (Left x)  = Left x
```

**How it works:**
- `Right x` - apply function to `x`
- `Left x` - leave unchanged (it's an error/failure case)
```haskell
fmap (*2) (Right 5)        -- Right 10
fmap (*2) (Left "error")   -- Left "error"
fmap show (Right 100)      -- Right "100"
fmap show (Left "error")   -- Left "error"
```

**Why only Right?**
- `Either a b` has first parameter for errors, second for values
- We fix the error type (`a`), transform the value type (`b`)
- Error cases should propagate unchanged!

## Understanding Type Constructors in Functor

### Why `f` Must Be Type Constructor
```haskell
class Functor f where
    fmap :: (a -> b) -> f a -> f b
                        ^^^    ^^^
                        f needs to take a type parameter
```

**`f` must be something that takes a type parameter:**

✅ **Valid Functors:**
```haskell
Maybe     -- Maybe Int, Maybe String, etc.
[]        -- [Int], [String], etc.
Tree      -- Tree Int, Tree String, etc.
Either a  -- Either String Int, Either Bool Char, etc.
```

❌ **NOT Valid Functors:**
```haskell
Int       -- Doesn't take type parameter
Bool      -- Doesn't take type parameter
String    -- Doesn't take type parameter (it's [Char])
```

### Partially Applying Type Constructors

`Either` has kind `* -> * -> *` (needs two type parameters).

**Problem:** Functor wants `* -> *` (one type parameter)

**Solution:** Fix the first parameter!
```haskell
-- Either alone: needs two parameters
Either :: * -> * -> *

-- Either String: needs one parameter  
Either String :: * -> *

-- Either String Int: concrete type
Either String Int :: *
```

**In instance:**
```haskell
instance Functor (Either a) where
                 ^^^^^^^^^^
                 fixed first parameter, second is free
```

Now `fmap` for `Either a` has type:
```haskell
fmap :: (b -> c) -> Either a b -> Either a c
```

## Map as Functor
```haskell
instance Functor (Map k) where
    fmap = Map.map
```

**Partially applied:** `Map k` (keys fixed, values free)
```haskell
phoneBook :: Map String Int
phoneBook = Map.fromList [("Alice", 123), ("Bob", 456)]

fmap (*10) phoneBook
-- Map.fromList [("Alice",1230),("Bob",4560)]

fmap show phoneBook  
-- Map.fromList [("Alice","123"),("Bob","456")]
```

**Keys never change, only values!**

## The Container Analogy

Think of Functors as **boxes** or **containers**:
```haskell
-- List: box with multiple compartments
[1,2,3]  -- three values in box
fmap (*2) [1,2,3]  -- [2,4,6]  (transform each, box stays)

-- Maybe: box with 0 or 1 item
Just 5   -- one value in box
Nothing  -- empty box
fmap (*2) (Just 5)   -- Just 10    (transform value, box stays)
fmap (*2) Nothing    -- Nothing    (empty box stays empty)

-- Either: box with error message or value
Right 10         -- box with value
Left "error"     -- box with error note
fmap (*2) (Right 10)      -- Right 20       (transform value)
fmap (*2) (Left "error")  -- Left "error"   (error stays)
```

**Key principle:** Box stays same type and shape, contents change!

## Functor vs Map

**What's the difference?**
```haskell
map :: (a -> b) -> [a] -> [b]           -- Only works on lists
fmap :: Functor f => (a -> b) -> f a -> f b  -- Works on any Functor
```

For lists, they're identical:
```haskell
map (*2) [1,2,3]   -- [2,4,6]
fmap (*2) [1,2,3]  -- [2,4,6]
```

But `fmap` works on **everything**:
```haskell
fmap (*2) (Just 5)               -- Just 10
fmap (*2) (Right 10)             -- Right 20
fmap (*2) (Node 5 EmptyTree EmptyTree)  -- Node 10 EmptyTree EmptyTree
```

## Using fmap

### Basic Usage
```haskell
fmap (+1) [1,2,3]                    -- [2,3,4]
fmap reverse ["abc", "def"]          -- ["cba","fed"]
fmap (++ "!") (Just "hello")         -- Just "hello!"
```

### Chaining fmap
```haskell
fmap (*2) (fmap (+1) [1,2,3])        -- [4,6,8]
-- Same as:
(fmap (*2) . fmap (+1)) [1,2,3]      -- [4,6,8]
-- Same as (by functor composition law):
fmap ((*2) . (+1)) [1,2,3]           -- [4,6,8]
```

### fmap with Different Types
```haskell
fmap length [[1,2,3], [4,5]]         -- [3,2]  (List Int -> List Int)
fmap length (Just "hello")           -- Just 5  (Maybe String -> Maybe Int)
fmap show [1,2,3]                    -- ["1","2","3"]  (Int -> String)
```

## Infix fmap: <$>

`fmap` has an infix operator: `<$>`
```haskell
(<$>) :: Functor f => (a -> b) -> f a -> f b
(<$>) = fmap
```

**Usage:**
```haskell
(*2) <$> [1,2,3]              -- [2,4,6]
(+1) <$> Just 5               -- Just 6
show <$> Right 100            -- Right "100"

-- Looks similar to $:
show $ 5                      -- "5"
show <$> Just 5               -- Just "5"
```

**Think of `<$>` as "apply function inside container"!**

## Practical Examples

### Validating and Transforming
```haskell
safeDiv :: Int -> Int -> Maybe Int
safeDiv _ 0 = Nothing
safeDiv x y = Just (x `div` y)

-- Transform result if it exists:
fmap (*2) (safeDiv 10 2)     -- Just 10  (5 * 2)
fmap (*2) (safeDiv 10 0)     -- Nothing
```

### Processing List of Maybes
```haskell
values :: [Maybe Int]
values = [Just 3, Nothing, Just 5, Just 7]

-- Double all values that exist:
fmap (fmap (*2)) values      -- [Just 6, Nothing, Just 10, Just 14]
```

**Why double `fmap`?**
- Outer `fmap` for the list
- Inner `fmap` for each Maybe

### Working with Either for Error Handling
```haskell
parseAge :: String -> Either String Int
parseAge s = case reads s of
    [(n, "")] | n >= 0 -> Right n
    _                  -> Left "Invalid age"

-- Process age if parsing succeeded:
fmap (+10) (parseAge "25")    -- Right 35
fmap (+10) (parseAge "xyz")   -- Left "Invalid age"
```

## Kinds - Type of Types

**Kind** is the "type of a type". It tells us how many type parameters something needs.

### Checking Kinds in GHCi
```haskell
ghci> :k Int
Int :: *                    -- concrete type

ghci> :k Maybe
Maybe :: * -> *             -- needs 1 type parameter

ghci> :k Either
Either :: * -> * -> *       -- needs 2 type parameters

ghci> :k Maybe Int
Maybe Int :: *              -- concrete type (parameter applied)

ghci> :k Either String
Either String :: * -> *     -- needs 1 more parameter
```

### Kind Notation

- `*` - concrete type (has values)
- `* -> *` - type constructor needing 1 parameter
- `* -> * -> *` - type constructor needing 2 parameters

**Think of it like function types, but for types!**
```haskell
-- Value level:
add :: Int -> Int -> Int

-- Type level:
Either :: * -> * -> *
```

### Why Kinds Matter for Functor
```haskell
class Functor f where
    fmap :: (a -> b) -> f a -> f b
```

`f` must have kind `* -> *` because:
- `f a` must be a concrete type (kind `*`)
- So `f` needs exactly one type parameter

**Valid for Functor:**
```haskell
Maybe :: * -> *        ✅
[] :: * -> *           ✅
Tree :: * -> *         ✅
Either a :: * -> *     ✅ (first param fixed)
Map k :: * -> *        ✅ (key param fixed)
```

**Not valid for Functor:**
```haskell
Int :: *               ❌ (no parameter)
Either :: * -> * -> *  ❌ (two parameters)
```

## Common Mistakes

### Mistake 1: Trying to Change Container Type
```haskell
-- WRONG: Trying to turn Maybe into List
fmap (\x -> [x]) (Just 5)  -- Just [5], NOT [5]!

-- Functor preserves structure!
```

### Mistake 2: Forgetting Structure Preservation
```haskell
-- These are DIFFERENT operations:
fmap length [[1,2,3], [4,5]]        -- [3,2] (map over list)
length [[1,2,3], [4,5]]             -- 2 (length of outer list)
```

### Mistake 3: Confusing fmap with >>= (Monad)
```haskell
-- fmap: transform values inside
fmap (+1) (Just 5)                  -- Just 6

-- (>>=): can change structure (that's Monad, different topic!)
Just 5 >>= (\x -> Just (x + 1))    -- Just 6
Just 5 >>= (\x -> Nothing)         -- Nothing (structure changed!)
```

## When to Use Functor

**Use fmap when:**
- Want to transform values inside container
- Container structure must stay the same
- Working with Maybe, Either, lists, trees, etc.

**Examples:**
- Transform successful computation result (Maybe, Either)
- Apply function to all list elements
- Update values in Map
- Modify tree node values

**Don't use fmap when:**
- Need to change container structure
- Want to flatten nested containers (that's Monad)
- Don't have a container (use regular function application)

---

## Remember

- **Functor = things you can map over**
- `fmap` applies function to values inside container
- **Container structure never changes**
- Works with `Maybe`, `[]`, `Tree`, `Either a`, `Map k`, etc.
- `fmap` for lists = `map`
- Functor needs type constructor with kind `* -> *`
- Two laws: identity and composition
- Use `<$>` as infix version of `fmap`
- **Kinds** describe how many type parameters needed
