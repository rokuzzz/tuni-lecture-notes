
Typeclasses define behavior that types can implement. While we've used standard typeclasses like `Eq`, `Ord`, and `Show`, Haskell lets you create your own to define custom behaviors.

---

## Quick Typeclass Recap

**Typeclass** = interface that defines one or more functions

**Instance** = implementation of that typeclass for a specific type
```haskell
-- Typeclass definition (interface)
class Eq a where
    (==) :: a -> a -> Bool

-- Instance (implementation for Int)
instance Eq Int where
    (==) = ... -- actual implementation
```

**Key difference from other topics:**
- `class` defines the interface (what functions must exist)
- `instance` provides implementation for specific type

---

## Creating the YesNo Typeclass

JavaScript lets you put almost anything in an `if` statement. Haskell requires strict `Bool` values. Let's implement JavaScript-like "truthiness" for fun!

### Class Declaration
```haskell
class YesNo a where
    yesno :: a -> Bool
```

**What this means:**
- Any type that wants to be `YesNo` must implement `yesno`
- `yesno` takes a value and returns `True` or `False`
- The type variable `a` must be a **concrete type** (actual type that values can have)

---

## Creating Instances

### Instance for Numbers

JavaScript treats 0 as false, everything else as true:
```haskell
instance YesNo Int where
    yesno 0 = False
    yesno _ = True
```

**How it works:**
- Pattern match on `0` → return `False`
- Pattern match on anything else (`_`) → return `True`

**Examples:**
```haskell
yesno (0 :: Int)   -- False
yesno (5 :: Int)   -- True
yesno (-3 :: Int)  -- True
```

### Instance for Lists

Empty lists are "falsy", non-empty lists are "truthy":
```haskell
instance YesNo [a] where
    yesno [] = False
    yesno _  = True
```

**Note:** Using type variable `a` makes this work for **any** list type - `[Int]`, `[String]`, `[[Bool]]`, etc.

**Examples:**
```haskell
yesno []           -- False
yesno [1,2,3]      -- True
yesno ""           -- False (String is [Char])
yesno "hello"      -- True
```

### Instance for Bool

Bool already represents truth, so just return the value itself:
```haskell
instance YesNo Bool where
    yesno = id
```

**What is `id`?** Identity function - returns its argument unchanged:
```haskell
id :: a -> a
id x = x
```

So `yesno True = True` and `yesno False = False`.

### Instance for Maybe

`Just` anything is truthy, `Nothing` is falsy:
```haskell
instance YesNo (Maybe a) where
    yesno (Just _) = True
    yesno Nothing  = False
```

**Important syntax note:**
- Write `(Maybe a)` not `(Maybe m)` or just `Maybe`
- `Maybe a` is a **concrete type** (can have values)
- `Maybe` alone is a **type constructor** (needs a parameter)

**Examples:**
```haskell
yesno (Just 0)      -- True  (even though content is 0!)
yesno (Just False)  -- True  (even though content is False!)
yesno Nothing       -- False
```

**Key insight:** We check the **container** (`Just` vs `Nothing`), not the **contents**!

### Instance for Custom Types

Let's say we have a `Tree` type:
```haskell
data Tree a = EmptyTree | Node a (Tree a) (Tree a)

instance YesNo (Tree a) where
    yesno EmptyTree = False
    yesno _         = True
```

Empty tree is falsy, any tree with nodes is truthy.

## Using the YesNo Typeclass

Now any type that's a `YesNo` can use the `yesno` function:
```haskell
yesno $ length []              -- False (length [] = 0)
yesno "haha"                   -- True  (non-empty string)
yesno ""                       -- False (empty string)
yesno (Just 0)                 -- True  (Just something)
yesno True                     -- True
yesno EmptyTree                -- False
yesno []                       -- False
yesno [0,0,0]                  -- True  (non-empty list)
```

**Type signature:**
```haskell
yesno :: (YesNo a) => a -> Bool
```

The `(YesNo a) =>` constraint means "type `a` must be an instance of `YesNo`".

---

## Creating Functions Using Typeclasses

Let's make a function that mimics `if-else` but works with YesNo values:
```haskell
yesnoIf :: (YesNo y) => y -> a -> a -> a
yesnoIf yesnoVal yesResult noResult = 
    if yesno yesnoVal then yesResult else noResult
```

**Type breakdown:**
- `(YesNo y) =>` - type `y` must be instance of `YesNo`
- `y` - the value to test
- `a` - result if truthy (first `a`)
- `a` - result if falsy (second `a`)
- `a` - return type (third `a`)

**Examples:**
```haskell
yesnoIf [] "YEAH!" "NO!"               -- "NO!"
yesnoIf [2,3,4] "YEAH!" "NO!"          -- "YEAH!"
yesnoIf True "YEAH!" "NO!"             -- "YEAH!"
yesnoIf (Just 500) "YEAH!" "NO!"       -- "YEAH!"
yesnoIf Nothing "YEAH!" "NO!"          -- "NO!"
```

## Type Constraints Explained

### What is `(YesNo y) =>`?

It's a **type constraint** (also called class constraint).
```haskell
yesnoIf :: (YesNo y) => y -> a -> a -> a
          ^^^^^^^^^^^
          constraint
```

**Reads as:** "Type `y` must be an instance of typeclass `YesNo`"

### Why is it needed?

Inside `yesnoIf`, we call `yesno yesnoVal`. This only works if `yesnoVal`'s type has a `yesno` function!
```haskell
yesnoIf yesnoVal yesResult noResult = 
    if yesno yesnoVal then ...
       ^^^^^
       This requires YesNo constraint!
```

### Examples of constraints you've seen:
```haskell
(==) :: (Eq a) => a -> a -> Bool           -- Must be Eq
max :: (Ord a) => a -> a -> a              -- Must be Ord
show :: (Show a) => a -> String            -- Must be Show
findKey :: (Eq k) => k -> [(k,v)] -> Maybe v  -- Key must be Eq
```

## Class vs Instance vs Constraint

**Three related but different concepts:**

### 1. Class Declaration
```haskell
class YesNo a where
    yesno :: a -> Bool
```
**Defines** the interface - what functions must exist.

### 2. Instance Declaration
```haskell
instance YesNo Int where
    yesno 0 = False
    yesno _ = True
```
**Implements** the interface for a specific type.

### 3. Type Constraint
```haskell
yesnoIf :: (YesNo y) => y -> a -> a -> a
```
**Requires** that a type is an instance of the typeclass.

## Key Rules for Instances

### Rule 1: Concrete Type in Instance

**Correct:**
```haskell
instance YesNo (Maybe a) where  -- Maybe a is concrete type
instance YesNo [a] where        -- [a] is concrete type
instance YesNo Int where        -- Int is concrete type
```

**Wrong:**
```haskell
instance YesNo Maybe where      -- Maybe needs a parameter!
instance YesNo [] where         -- [] needs a parameter!
```

### Rule 2: One Instance Per Type

You cannot create multiple instances of the same typeclass for the same type:
```haskell
-- This is NOT allowed:
instance YesNo Int where
    yesno 0 = False
    yesno _ = True

instance YesNo Int where       -- ERROR! Already exists
    yesno n = n > 0            -- Can't redefine
```

### Rule 3: Type Variables for Flexibility

Using type variables makes instances more general:
```haskell
instance YesNo [a] where       -- Works for ANY list type
    yesno [] = False
    yesno _  = True

-- This works for:
yesno [1,2,3]        -- [Int]
yesno ["a","b"]      -- [String]
yesno [[True]]       -- [[Bool]]
```

---

## Pattern Matching in Instances

Instances can use pattern matching just like regular functions:
```haskell
instance YesNo (Maybe a) where
    yesno (Just _) = True    -- Pattern: Just with any value
    yesno Nothing = False    -- Pattern: Nothing

instance YesNo Bool where
    yesno True = True        -- Pattern: True
    yesno False = False      -- Pattern: False
```

## Practical Example: Validating Input
```haskell
-- Custom type for user input
data UserInput = ValidInput String | EmptyInput

instance YesNo UserInput where
    yesno (ValidInput _) = True
    yesno EmptyInput = False

-- Function that only processes valid input
processIfValid :: UserInput -> String -> String
processIfValid input msg = 
    yesnoIf input msg "Error: Empty input"

-- Usage:
processIfValid (ValidInput "hello") "Processing..."  -- "Processing..."
processIfValid EmptyInput "Processing..."            -- "Error: Empty input"
```

## Common Mistakes

### Mistake 1: Wrong Type in Instance
```haskell
-- WRONG: Using type constructor instead of concrete type
instance YesNo Maybe where  -- Error! Maybe needs parameter

-- RIGHT:
instance YesNo (Maybe a) where
```

### Mistake 2: Forgetting Constraint in Function
```haskell
-- WRONG: No constraint, but using yesno
checkValue :: a -> Bool
checkValue x = yesno x  -- Error! No YesNo constraint

-- RIGHT:
checkValue :: (YesNo a) => a -> Bool
checkValue x = yesno x
```

### Mistake 3: Checking Contents Instead of Container
```haskell
-- For Maybe, we check the container, not the content:
yesno (Just 0)     -- True  (it's a Just!)
yesno (Just False) -- True  (it's a Just!)
yesno Nothing      -- False

-- NOT checking if the content is truthy!
```

## When to Create Custom Typeclasses?

**Good reasons:**
- Common behavior across different types
- Want to write functions that work with many types
- Building a library with consistent interface

**Probably don't need custom typeclass when:**
- Only one or two types will use it
- Behavior is too specific to your application
- Standard typeclasses (Eq, Ord, Show) already do what you need

---

## Remember

- **Class** = interface definition (what must exist)
- **Instance** = implementation for specific type (how it works)
- **Constraint** = requirement in function type (must be instance)
- Use **concrete types** in instances: `(Maybe a)` not `Maybe`
- Type variables make instances work for multiple types
- Pattern matching works in instances just like in functions
- One instance per type per typeclass - no duplicates!
