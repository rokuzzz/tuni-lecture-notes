## Guards - Conditional Logic

**Guards** test whether properties of values are true or false. They're like if-else chains but more readable when you have multiple conditions.

### Basic Guard Syntax

Guards use pipes (`|`) followed by boolean expressions:
```haskell
densityTell :: (RealFloat a) => a -> String
densityTell density
    | density < 1.2 = "Wow! You're going for a ride in the sky!"
    | density <= 1000.0 = "Have fun swimming, but watch out for sharks!"
    | otherwise = "If it's sink or swim, you're going to sink."
```

**Key points:**

- Guards are indicated by pipes (`|`) after function name and parameters
- Usually indented and aligned
- Evaluated from top to bottom until first `True` condition
- `otherwise` is defined as `otherwise = True` - catches everything
- **No `=` after function parameters before first guard**

### Multiple Parameters with Guards
```haskell
densityTell :: (RealFloat a) => a -> a -> String
densityTell mass volume
    | mass / volume < 1.2 = "Wow! You're going for a ride in the sky!"
    | mass / volume <= 1000.0 = "Have fun swimming, but watch out for sharks!"
    | otherwise = "If it's sink or swim, you're going to sink."
```

### Simple Examples
```haskell
max' :: (Ord a) => a -> a -> a
max' a b
    | a > b = a
    | otherwise = b

-- Using infix notation
myCompare :: (Ord a) => a -> a -> Ordering
a `myCompare` b
    | a > b = GT
    | a == b = EQ
    | otherwise = LT
```

### Guards vs Pattern Matching

**Guards check conditions, patterns check structure (see [Pattern Matching](../Week-3/3.2-Pattern-Matching.md)):

- Use guards for ranges, comparisons, mathematical conditions
- Use pattern matching for deconstructing data structures
- They can be combined in the same function

## Where - Binding Variables at Function End

**Where clauses** let you bind variables and functions at the end of a function definition, visible to all guards and the main function body.

### Basic Where Usage
```haskell
densityTell :: (RealFloat a) => a -> a -> String
densityTell mass volume
    | density < 1.2 = "Wow! You're going for a ride in the sky!"
    | density <= 1000.0 = "Have fun swimming, but watch out for sharks!"
    | otherwise = "If it's sink or swim, you're going to sink."
    where density = mass / volume
```

**Benefits:**

- Eliminates repetition (`mass / volume` calculated once)
- Improves readability by naming intermediate values
- Can improve performance (calculated only once)

### Multiple Where Bindings
```haskell
densityTell :: (RealFloat a) => a -> a -> String
densityTell mass volume
    | density < air = "Wow! You're going for a ride in the sky!"
    | density <= water = "Have fun swimming, but watch out for sharks!"
    | otherwise = "If it's sink or swim, you're going to sink."
    where density = mass / volume
          air = 1.2
          water = 1000.0
```

**Important:** All names in where clause must be aligned in a single column for Haskell to recognize them as part of the same block.

### Pattern Matching in Where
```haskell
-- Using tuples
where density = mass / volume
      (air, water) = (1.2, 1000.0)

-- Pattern matching lists
initials :: String -> String -> String
initials firstname lastname = [f] ++ ". " ++ [l] ++ "."
    where (f:_) = firstname
          (l:_) = lastname
```

### Functions in Where
```haskell
calcDensities :: (RealFloat a) => [(a, a)] -> [a]
calcDensities xs = [density m v | (m, v) <- xs]
    where density mass volume = mass / volume
```

**Where scope:**

- Names defined in where are only visible to that function
- Not shared across different patterns of the same function
- Can be nested (where clauses can have their own where clauses)

## Let - Binding Variables as Expressions

**Let expressions** bind variables anywhere and are expressions themselves, unlike where which is a syntactic construct.

### Basic Let Syntax
```haskell
cylinder :: (RealFloat a) => a -> a -> a
cylinder r h =
    let sideArea = 2 * pi * r * h
        topArea = pi * r ^ 2
    in  sideArea + 2 * topArea
```

**Form:** `let <bindings> in <expression>`

### Let vs Where Comparison

**Key difference:** Let puts bindings first, where puts them last.
```haskell
-- Let style
cylinder r h =
    let sideArea = 2 * pi * r * h
        topArea = pi * r ^ 2
    in  sideArea + 2 * topArea

-- Where style
cylinder r h = sideArea + 2 * topArea
    where sideArea = 2 * pi * r * h
          topArea = pi * r ^ 2
```

### Let as Expressions

Since let bindings are expressions, they can be used anywhere:
```haskell
-- Inside other expressions
4 * (let a = 9 in a + 1) + 2  -- Result: 42

-- In lists
[let square x = x * x in (square 5, square 3, square 2)]  -- [(25,9,4)]

-- Inline with semicolons
(let a = 100; b = 200; c = 300 in a*b*c, let foo="Hey "; bar = "there!" in foo ++ bar)
```

### Pattern Matching with Let
```haskell
(let (a,b,c) = (1,2,3) in a+b+c) * 100  -- 600
```

### Let in List Comprehensions
```haskell
calcDensities :: (RealFloat a) => [(a, a)] -> [a]
calcDensities xs = [density | (m, v) <- xs, let density = m / v]

-- Using let binding in conditions
calcDensities :: (RealFloat a) => [(a, a)] -> [a]
calcDensities xs = [density | (m, v) <- xs, let density = m / v, density < 1.2]
```

**Note:** In list comprehensions, `in` part is omitted because visibility is predefined.

### Let in GHCI
```haskell
-- Global definition (visible throughout session)
ghci> let zoot x y z = x * y + z
ghci> zoot 3 9 2  -- 29

-- Local definition
ghci> let boot x y z = x * y + z in boot 3 4 2  -- 14
ghci> boot  -- Error: Not in scope
```

## Case Expressions - Pattern Matching Anywhere

**Case expressions** allow pattern matching in the middle of expressions, not just in function definitions.

### Basic Case Syntax
```haskell
case expression of pattern -> result
                   pattern -> result
                   pattern -> result
                   ...
```

### Case vs Function Pattern Matching

These are equivalent:
```haskell
-- Function pattern matching
head' :: [a] -> a
head' [] = error "No head for empty lists!"
head' (x:_) = x

-- Case expression
head' :: [a] -> a
head' xs = case xs of []    -> error "No head for empty lists!"
                      (x:_) -> x
```

**Function pattern matching is syntactic sugar for case expressions.**

### Case in Expressions
```haskell
describeList :: [a] -> String
describeList xs = "The list is " ++ case xs of []  -> "empty."
                                                [x] -> "a singleton list."
                                                xs  -> "a longer list."
```

**Alternative using where:**
```haskell
describeList :: [a] -> String
describeList xs = "The list is " ++ what xs
    where what []  = "empty."
          what [x] = "a singleton list."
          what xs  = "a longer list."
```

### When to Use Case

Use case expressions when you need pattern matching:

- In the middle of an expression
- Inside let bindings
- In list comprehensions
- Anywhere you can't define a separate function

## When to Use Each Construct

### Use Guards When:

- Testing conditions or ranges
- Comparing values
- Multiple boolean checks
- Working with mathematical inequalities

### Use Where When:

- Need helper variables for entire function
- Want to "hide" implementation details at end
- Working with guards that share calculations
- Defining helper functions for one main function

### Use Let When:

- Need local variables for small expressions
- Working in list comprehensions
- Want to bind variables close to where they're used
- Need bindings inside expressions

### Use Case When:

- Need pattern matching inside expressions
- Can't define separate function patterns
- Want to pattern match in middle of calculation
- Working with complex nested expressions

### Practical Comparison Example

All these achieve similar results:
```haskell
-- Guards with where
classifyBMI :: (RealFloat a) => a -> a -> String
classifyBMI weight height
    | bmi < underweight = "Underweight"
    | bmi < normal      = "Normal"
    | bmi < overweight  = "Overweight"
    | otherwise         = "Obese"
    where bmi = weight / height ^ 2
          underweight = 18.5
          normal = 25.0
          overweight = 30.0

-- Let expression
classifyBMI :: (RealFloat a) => a -> a -> String
classifyBMI weight height =
    let bmi = weight / height ^ 2
        underweight = 18.5
        normal = 25.0
        overweight = 30.0
    in  if bmi < underweight then "Underweight"
        else if bmi < normal then "Normal"
        else if bmi < overweight then "Overweight"
        else "Obese"

-- Case with guards
classifyBMI :: (RealFloat a) => a -> a -> String
classifyBMI weight height =
    case weight / height ^ 2 of
        bmi | bmi < 18.5 -> "Underweight"
            | bmi < 25.0 -> "Normal"
            | bmi < 30.0 -> "Overweight"
            | otherwise  -> "Obese"
```

### Common Mistakes and Tips

**Where clause alignment:**
```haskell
-- Wrong - not aligned
where x = 1
    y = 2

-- Right - aligned
where x = 1
      y = 2
```

**Guards syntax:**
```haskell
-- Wrong - has equals after parameters
myFunc x y =
    | x > y = "bigger"

-- Right - no equals
myFunc x y
    | x > y = "bigger"
```

**Let vs Where choice:**

- Use **where** when you want to read the main logic first, then see helper definitions
- Use **let** when you want to see definitions first, then the main expression
- Both are functionally equivalent in most cases

**Case expressions:**

- Remember the `of` keyword: `case expr of`
- Patterns work the same as in function definitions
- Must be exhaustive or runtime error occurs
