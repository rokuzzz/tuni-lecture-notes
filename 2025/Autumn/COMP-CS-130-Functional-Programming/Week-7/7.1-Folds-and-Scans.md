## What are Folds?

**Folds are higher-order functions that reduce a list to a single value** by repeatedly applying a binary function. They encapsulate the common pattern of processing lists element by element with an accumulator.

A fold takes:
- A **binary function** (takes two parameters)
- A **starting value** (accumulator)
- A **list** to fold

## Core Fold Functions

### 1. foldl (Left Fold)

Processes list from **left to right**. Accumulator is the **first parameter** in the lambda.
```haskell
sum' :: (Num a) => [a] -> a
sum' xs = foldl (\acc x -> acc + x) 0 xs
-- Or shorter with currying:
sum' = foldl (+) 0

-- Example:
-- foldl (+) 0 [3,5,2,1]
-- = ((((0 + 3) + 5) + 2) + 1)
-- = 11
```

**How it works step by step:**
1. `acc = 0`, `x = 3` → `0 + 3 = 3`
2. `acc = 3`, `x = 5` → `3 + 5 = 8`
3. `acc = 8`, `x = 2` → `8 + 2 = 10`
4. `acc = 10`, `x = 1` → `10 + 1 = 11`

### 2. foldr (Right Fold)

Processes list from **right to left**. Current element is the **first parameter**, accumulator is **second**.
```haskell
map' :: (a -> b) -> [a] -> [b]
map' f xs = foldr (\x acc -> f x : acc) [] xs

-- Visualization:
-- foldr f z [3,4,5,6]
-- = f 3 (f 4 (f 5 (f 6 z)))
```

**Key difference:** `foldr` works with **infinite lists**, `foldl` doesn't!

### 3. foldl1 and foldr1

Same as `foldl` and `foldr`, but **assume first/last element as starting value**. No explicit starting value needed.
```haskell
sum = foldl1 (+)
maximum' = foldr1 (\x acc -> if x > acc then x else acc)
```

⚠️ **Warning:** Cause runtime errors on empty lists!

## Practical Examples

### elem' - Check if element exists
```haskell
elem' :: (Eq a) => a -> [a] -> Bool
elem' target list = foldl (\acc current -> 
    if current == target then True else acc) False list

-- Logic:
-- Start with False (assume not found)
-- If we find target → set acc to True
-- Once True, stays True (element found!)
```

### reverse' - Reverse a list
```haskell
reverse' :: [a] -> [a]
reverse' = foldl (\acc x -> x : acc) []
-- Or using flip:
reverse' = foldl (flip (:)) []

-- How it works:
-- [1,2,3] → [] → [1] → [2,1] → [3,2,1]
```

### filter' - Filter by predicate
```haskell
filter' :: (a -> Bool) -> [a] -> [a]
filter' p = foldr (\x acc -> if p x then x : acc else acc) []

-- Example:
-- filter' (> 3) [1,5,2,6]
-- Include 5 and 6, skip 1 and 2
```

## Why use `:` instead of `++`?

When building lists with `foldr`, we use `:` (cons) instead of `++` (append) because:
- **`:` is O(1)** - instant prepend
- **`++` is O(n)** - must traverse entire left list
```haskell
-- Efficient (foldr with :)
map' f xs = foldr (\x acc -> f x : acc) [] xs

-- Inefficient (foldl with ++)
map' f xs = foldl (\acc x -> acc ++ [f x]) [] xs
```

## Scans - Folds with History

**Scans are like folds, but return all intermediate accumulator states** in a list.
```haskell
-- fold returns only final result:
foldl (+) 0 [3,5,2,1]  -- 11

-- scan returns all intermediate steps:
scanl (+) 0 [3,5,2,1]  -- [0,3,8,10,11]
```

### Scan Variants
```haskell
scanl  :: (b -> a -> b) -> b -> [a] -> [b]  -- Left scan
scanr  :: (a -> b -> b) -> b -> [a] -> [b]  -- Right scan
scanl1 :: (a -> a -> a) -> [a] -> [a]       -- No starting value
scanr1 :: (a -> a -> a) -> [a] -> [a]       -- No starting value
```

### Practical Example: Sum of Square Roots

**Problem:** How many elements does it take for the sum of square roots of natural numbers to exceed 1000?
```haskell
sqrtSums :: Int
sqrtSums = length (takeWhile (<1000) (scanl1 (+) (map sqrt [1..]))) + 1

-- Breaking it down:
-- 1. map sqrt [1..]           → [1.0, 1.41, 1.73, 2.0, ...]
-- 2. scanl1 (+) (...)         → [1.0, 2.41, 4.14, 6.14, ...]
--                                (cumulative sums)
-- 3. takeWhile (<1000) (...)  → stop at first sum ≥ 1000
-- 4. length (...)             → count how many sums < 1000
-- 5. ... + 1                  → need one more to exceed 1000
```

**Result:** 131 elements needed

**Why `takeWhile` instead of `filter`?**
- `filter` doesn't work on infinite lists (tries to evaluate everything)
- `takeWhile` stops immediately when condition fails

## Visualization

### foldl vs foldr structure:
```haskell
-- foldl: accumulates from left
foldl g z [3,4,5,6]
= g (g (g (g z 3) 4) 5) 6

-- foldr: accumulates from right  
foldr f z [3,4,5,6]
= f 3 (f 4 (f 5 (f 6 z)))
```

### When to use which?

| Use Case | Choice | Why |
|----------|--------|-----|
| Building new list | `foldr` | `:` is efficient, works left-to-right naturally |
| Simple accumulation | `foldl` | More intuitive left-to-right |
| Infinite lists | `foldr` | Can stop early, `foldl` never terminates |
| Monitoring progress | `scan` | Need intermediate results |

## Remember

- **Fold** reduces list to single value
- **Scan** shows all intermediate steps
- `foldl` goes **left→right**, accumulator **first** in lambda
- `foldr` goes **right→left**, element **first** in lambda  
- Use `foldr` for **building lists** (`:` is faster than `++`)
- Use `foldr` for **infinite lists** (can terminate early)
- `foldl1`/`foldr1` assume first/last element as start (⚠️ fail on empty lists)
- **Any traversal that returns something = potential fold!**
