
## Introduction to Recursive Types

### Core Concept

**Recursive data types** are types where a constructor contains fields of the same type being defined. This creates structures that can reference themselves, allowing us to build data of arbitrary size.

**Key principle:** A value of a recursive type can contain other values of that same type, which in turn contain more values, and so on.

### Familiar Example: Lists

Lists in Haskell are actually recursive structures. The syntax `[5]` is syntactic sugar for `5:[]`:

```haskell
[5]           -- syntactic sugar
5:[]          -- actual structure

[4,5]         -- syntactic sugar  
4:(5:[])      -- actual structure
4:5:[]        -- without parentheses (: is right-associative)

[3,4,5,6]     -- syntactic sugar
3:4:5:6:[]    -- actual structure
```

**List definition conceptually:**

- A list is either **empty** (`[]`)
- OR an element joined with `:` to another list

This recursive definition is the foundation for building our own recursive types.

## Implementing Our Own List

### Basic Definition

```haskell
data List a = Empty | Cons a (List a) deriving (Show, Read, Eq, Ord)
```

**Breaking it down:**

- `List a` - our type, parameterized by `a`
- `Empty` - represents an empty list (like `[]`)
- `Cons a (List a)` - constructor that takes:
    - An element of type `a` (the head)
    - Another `List a` (the tail) ← **This is the recursion!**

**The name "Cons":** Short for "construct" - it's the traditional name for the list construction operator (like `:` in standard lists).

### Alternative: Record Syntax

```haskell
data List a = Empty | Cons { listHead :: a, listTail :: List a} 
    deriving (Show, Read, Eq, Ord)
```

**Benefits of record syntax:**

- Automatic accessor functions: `listHead` and `listTail`
- More readable - field names make purpose clear
- Useful when structures have many fields

### Using Our List

```haskell
ghci> Empty
Empty

ghci> 5 `Cons` Empty
Cons 5 Empty

ghci> 4 `Cons` (5 `Cons` Empty)
Cons 4 (Cons 5 Empty)

ghci> 3 `Cons` (4 `Cons` (5 `Cons` Empty))
Cons 3 (Cons 4 (Cons 5 Empty))
```

**Comparison with standard lists:**

- `[]` ↔ `Empty`
- `:` ↔ `Cons`
- `[1,2,3]` ↔ `Cons 1 (Cons 2 (Cons 3 Empty))`

## Infix Constructors and Operators

### Creating Infix Constructors

Constructors made of special characters are automatically infix:

```haskell
infixr 5 :-:
data List a = Empty | a :-: (List a) deriving (Show, Read, Eq, Ord)
```

**Now we can write:**

```haskell
3 :-: 4 :-: 5 :-: Empty
-- Instead of:
Cons 3 (Cons 4 (Cons 5 Empty))
```

### Understanding Fixity Declarations

**Syntax:** `infixr priority operator`

**Components:**

- `infixr` - right-associative (or `infixl` for left-associative)
- `5` - priority level (0-9, higher = binds tighter)
- `:-:` - the operator name

### Associativity Examples

**Right-associative (`infixr`):**

```haskell
3 :-: 4 :-: 5 :-: Empty
-- Groups as:
3 :-: (4 :-: (5 :-: Empty))
```

**Left-associative (`infixl`):**

```haskell
4 * 3 * 2
-- Groups as:
(4 * 3) * 2
```

### Priority Examples

```haskell
infixl 7 *    -- multiplication, priority 7
infixl 6 +    -- addition, priority 6

5 * 4 + 3
-- Evaluates as: (5 * 4) + 3
-- Because * has higher priority (7 > 6)
```

**Why `infixr 5` for `:-:`?**

- Matches the priority of the standard `:` operator
- Right-associative because we build lists from right to left
- Priority 5 works well with other common operators

## Functions for Custom Lists

### Concatenation Function (.++)

```haskell
infixr 5 .++
(.++) :: List a -> List a -> List a
Empty .++ ys = ys                      -- Base case
(x :-: xs) .++ ys = x :-: (xs .++ ys)  -- Recursive case
```

**How it works:**

1. **Base case:** If first list is empty, return second list
    
    ```haskell
    Empty .++ [6,7] = [6,7]
    ```
    
2. **Recursive case:** Take head of first list, recursively concatenate tail with second list
    
    ```haskell
    (3 :-: 4 :-: Empty) .++ (6 :-: 7 :-: Empty)
    → 3 :-: ((4 :-: Empty) .++ (6 :-: 7 :-: Empty))
    → 3 :-: (4 :-: (Empty .++ (6 :-: 7 :-: Empty)))
    → 3 :-: (4 :-: (6 :-: 7 :-: Empty))
    ```
    

### Pattern Matching on Constructors

```haskell
(x :-: xs) .++ ys = x :-: (xs .++ ys)
```

**Why this works:**

- Pattern matching works on **constructors**
- `:-:` is a constructor for our list type
- We can match on it just like `:` for standard lists
- `x` binds to the head
- `xs` binds to the tail

**Key insight:** Pattern matching is fundamentally about matching constructors, not just deconstructing data.

## Binary Search Tree

### What is a Binary Search Tree?

A **Binary Search Tree (BST)** is a tree structure where:

- Each node has **at most two children** (left and right)
- All elements in the **left subtree** are **smaller** than the node
- All elements in the **right subtree** are **larger** than the node

**Efficiency:**

- Search: O(log n) on average vs O(n) for lists
- Insert: O(log n) on average vs O(n) for lists

### Tree Definition

```haskell
data Tree a = EmptyTree | Node a (Tree a) (Tree a) deriving (Show, Read, Eq)
```

**Components:**

- `EmptyTree` - represents no tree (base case for recursion)
- `Node a (Tree a) (Tree a)` - contains:
    - A value of type `a`
    - Left subtree (Tree a)
    - Right subtree (Tree a)

### Helper Function: Singleton

Creates a tree with just one node:

```haskell
singleton :: a -> Tree a
singleton x = Node x EmptyTree EmptyTree
```

**Visualization:**

```
singleton 5 creates:
    5
   / \
  ∅   ∅
```

### Inserting into a Tree

```haskell
treeInsert :: (Ord a) => a -> Tree a -> Tree a
treeInsert x EmptyTree = singleton x
treeInsert x (Node a left right)
    | x == a = Node a left right              -- Element already exists
    | x < a  = Node a (treeInsert x left) right   -- Insert left
    | x > a  = Node a left (treeInsert x right)   -- Insert right
```

**Step-by-step explanation:**

1. **Base case:** `treeInsert x EmptyTree = singleton x`
    - If tree is empty, create a new single-node tree
    - This is where recursion stops
    
2. **Element already exists:** `x == a`
    - Return tree unchanged
    - No duplicates in BST
    
3. **Element is smaller:** `x < a`
    - Create new tree with:
        - Same value `a` at root
        - **New left subtree** (result of inserting into left)
        - **Same right subtree**
        
4. **Element is larger:** `x > a`
    - Create new tree with:
        - Same value `a` at root
        - **Same left subtree**
        - **New right subtree** (result of inserting into right)

**Example: Inserting 4 into a tree**

```
Initial tree:
    5
   / \
  3   7

After treeInsert 4:
    5
   / \
  3   7
   \
    4
```

**Trace:**

```haskell
treeInsert 4 (Node 5 (Node 3 Empty Empty) (Node 7 Empty Empty))
-- 4 < 5, go left
→ Node 5 (treeInsert 4 (Node 3 Empty Empty)) (Node 7 Empty Empty)
-- 4 > 3, go right
→ Node 5 (Node 3 Empty (treeInsert 4 Empty)) (Node 7 Empty Empty)
-- Hit Empty, create singleton
→ Node 5 (Node 3 Empty (Node 4 Empty Empty)) (Node 7 Empty Empty)
```

### Searching in a Tree

```haskell
treeElem :: (Ord a) => a -> Tree a -> Bool
treeElem x EmptyTree = False
treeElem x (Node a left right)
    | x == a = True                 -- Found it!
    | x < a  = treeElem x left      -- Search left
    | x > a  = treeElem x right     -- Search right
```

**Logic:**

1. Empty tree → element not found
2. Element equals root → found!
3. Element less than root → must be in left subtree
4. Element greater than root → must be in right subtree

**Why BST is efficient:**

- Each comparison eliminates half the remaining tree
- Much faster than checking every element in a list

### Building a Tree from a List

Using `foldr` to build a tree:

```haskell
let nums = [8,6,4,1,7,3,5]
let numsTree = foldr treeInsert EmptyTree nums
```

**Result:**

```
       5
      / \
     3   7
    / \   \
   1   4   8
        \
         6
```

**Why `foldr`?**

- Processes list from right to left
- Starts with empty tree
- Inserts each element one by one
- Final tree structure depends on insertion order

## Important Concepts Review

### Immutability in Trees

**Key difference from imperative languages:**

- In C++/Java: modify existing nodes
- In Haskell: create new trees

```haskell
-- We don't modify:
node.left = newValue  -- Not possible in Haskell!

-- We create new:
Node a newLeft right  -- New tree with modified subtree
```

**Efficiency through sharing:**

- Unchanged subtrees are reused (not copied)
- Only modified path creates new nodes
- Lazy evaluation helps performance

### Pattern Matching Rules

**Important points:**

1. Patterns are checked **top to bottom**
2. First match wins
3. Always include catch-all patterns to avoid runtime errors
4. Can't use `++` in patterns (Haskell can't determine split point)

### Type Variables

```haskell
data List a = Empty | Cons a (List a)
data Tree a = EmptyTree | Node a (Tree a) (Tree a)
```

**The `a` means:**

- Can hold any type: `List Int`, `List String`, `List Char`
- Same `a` throughout means all elements same type
- **Polymorphism** - one definition works for many types

## Common Patterns

### Recursive Structure Pattern

```haskell
data RecursiveType = BaseCase | RecursiveCase ... (RecursiveType) ...
```

**Always has:**

1. **Base case** - stops recursion (Empty, EmptyTree)
2. **Recursive case** - contains the type itself (Cons, Node)

### Recursive Function Pattern

```haskell
function BaseCase = baseResult
function (RecursiveCase x xs) = x `combine` function xs
```

**Components:**

1. Base case handling
2. Deconstruct recursive structure
3. Process current element
4. Recursive call on smaller structure
5. Combine results

## Practical Tips

### When to Use Recursive Types

**Use recursive data structures when:**

- Dealing with arbitrary-sized collections
- Need hierarchical data (trees, nested structures)
- Want efficient search/insert operations
- Building parsers or compilers (AST trees)

### Common Mistakes

❌ **Forgetting base cases:**

```haskell
-- Missing Empty case - will crash!
badLength (x:xs) = 1 + badLength xs
```

✅ **Always handle base cases:**

```haskell
goodLength [] = 0
goodLength (x:xs) = 1 + goodLength xs
```

❌ **Wrong pattern for guards:**

```haskell
-- Wrong: has = after parameters
myFunc x y =
    | x > y = "bigger"
```

✅ **Correct: no = before guards:**

```haskell
myFunc x y
    | x > y = "bigger"
    | otherwise = "smaller"
```

### Debugging Tips

1. **Test base cases first** - ensure they work before recursive cases
2. **Use GHCi** - test small examples interactively
3. **Draw pictures** - visualize tree structures
4. **Trace execution** - follow recursion step by step
5. **Start simple** - test with small inputs first

## Summary

**Key takeaways:**

1. **Recursive types reference themselves** - enabling structures of arbitrary size
2. **Lists are recursive** - `[1,2,3]` is really `1:(2:(3:[]))`
3. **Infix constructors** - made from special characters, make syntax cleaner
4. **Pattern matching on constructors** - fundamental to working with recursive types
5. **BST offers efficiency** - O(log n) operations vs O(n) for lists
6. **Immutability** - we create new structures, not modify existing ones
7. **Always handle base cases** - prevents infinite recursion

**Remember:**

- Base case stops recursion
- Recursive case moves toward base case
- Pattern matching deconstructs data
- Guards test conditions
- Immutability means creating, not modifying
