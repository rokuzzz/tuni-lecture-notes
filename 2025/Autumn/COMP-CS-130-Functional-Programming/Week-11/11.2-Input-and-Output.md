
## Introduction: The Problem of Purity

### The Challenge

Haskell is a **purely functional language**:

- Functions have no side effects
- Same input → same output (always)
- Values are immutable

**But how do we do I/O?**

- Printing to screen = side effect
- Reading user input = different result each time
- These violate purity!

### Haskell's Solution: IO Actions

**Don't perform I/O directly. Instead, describe what I/O to perform.**

```haskell
putStrLn :: String -> IO ()
```

**Read as:** "putStrLn takes a String and returns a **description** of an I/O action"

**Think of it like a recipe:**

- `putStrLn "hello"` → creates a recipe (doesn't cook yet!)
- `main = putStrLn "hello"` → executes the recipe

---

## Hello World

```haskell
main = putStrLn "hello, world"
```

**Compile and run:**

```bash
$ ghc --make helloworld
$ ./helloworld
hello, world
```

### Understanding Types

```haskell
ghci> :t putStrLn
putStrLn :: String -> IO ()

ghci> :t putStrLn "hello"
putStrLn "hello" :: IO ()
```

**Breaking it down:**

- `String ->` - takes a String as parameter
- `IO ()` - returns an I/O action
- `()` - empty tuple (like void in other languages)

**Important:** `putStrLn` doesn't print! It creates an I/O action that, when executed, will print.

## The `main` Function

```haskell
main :: IO something
main = putStrLn "hello"
```

**Rules:**

- Every program must have `main`
- `main` must have type `IO something`
- Only I/O actions in `main` (or called from `main`) are performed
- Program execution starts at `main`

---

## The `do` Notation

```haskell
main = do  
    putStrLn "Hello, what's your name?"  
    name <- getLine  
    putStrLn ("Hey " ++ name ++ ", you rock!")
```

**What `do` does:**

- Glues multiple I/O actions into one
- Creates sequential execution
- Each line is an I/O action

**Type of do block = type of last action:**

```haskell
main = do
    putStrLn "Hello"  -- last action: IO ()
    -- Therefore, main :: IO ()
```

---

## The `<-` Operator: Extracting from IO

```haskell
name <- getLine
```

**What happens:**

1. `getLine` has type `IO String` (I/O action containing a String)
2. `<-` **extracts** the String from the I/O action
3. `name` has type `String` (pure value!)

### Important Distinction

```haskell
getLine :: IO String        -- I/O action
name <- getLine             -- name :: String (pure!)
```

**Analogy:**

- `getLine` is a box with a gift inside
- `<-` opens the box and takes out the gift
- `name` is the gift (not the box!)

### Common Mistake

```haskell
-- ❌ WRONG:
nameTag = "Hello, my name is " ++ getLine

-- Why wrong?
-- "Hello..." :: String
-- getLine :: IO String
-- Can't concatenate String with IO String!

-- ✅ CORRECT:
main = do
    name <- getLine  -- extract String from IO
    let nameTag = "Hello, my name is " ++ name
    putStrLn nameTag
```

## The `return` Function

**⚠️ WARNING:** `return` in Haskell is **COMPLETELY DIFFERENT** from return in C/Java/Python!

```haskell
return :: a -> IO a
```

**What `return` does:**

- Takes a pure value
- **Wraps** it in an I/O action
- Does **NOT** stop execution!

### Comparison: Imperative vs Functional

**Python (stops execution):**

```python
def foo():
    return 5
    print("Never printed")  # ← NOT EXECUTED
```

**Haskell (does NOT stop):**

```haskell
main = do
    return ()
    putStrLn "Hello"  -- ← EXECUTED!
```

### Why Use `return`?

#### Reason 1: Satisfy type requirements

```haskell
getUserAge :: IO Int    -- Must return IO Int
getUserAge = do
    putStrLn "Enter age:"
    line <- getLine
    return (read line)  -- ✅ Wraps Int in IO Int
```

**Without `return`:**

```haskell
getUserAge :: IO Int
getUserAge = do
    putStrLn "Enter age:"
    line <- getLine
    read line          -- ❌ Type: Int, need: IO Int
```

#### Reason 2: Create "empty" I/O action

```haskell
main = do  
    line <- getLine  
    if null line  
        then return ()      -- Need an I/O action here
        else putStrLn line
```

**Why needed:** In `if-then-else` inside `do` blocks, both branches must be I/O actions.

## `let` vs `<-` in `do` Blocks

### When to Use Each

```haskell
main = do
    name <- getLine              -- ← Use <- for I/O actions
    let upper = map toUpper name -- ← Use let for pure expressions
    putStrLn upper
```

**Rules:**

- `<-` - extract result from I/O action
- `let` - bind pure expressions to names (no `in` needed in do blocks!)

### Example

```haskell
import Data.Char

main = do
    putStrLn "Enter your name:"
    firstName <- getLine                    -- <- for I/O
    putStrLn "Enter your last name:"
    lastName <- getLine                     -- <- for I/O
    let bigFirst = map toUpper firstName    -- let for pure
        bigLast = map toUpper lastName      -- let for pure
    putStrLn $ "Hello " ++ bigFirst ++ " " ++ bigLast
```

## Control Flow in I/O

### `if-then-else` in `do` Blocks

```haskell
main = do
    line <- getLine
    if null line
        then putStrLn "Empty!"        -- Must be I/O action
        else putStrLn $ "You said: " ++ line  -- Must be I/O action
```

**Important:** Both branches must have the same I/O type!

### Recursion in I/O

```haskell
main = do
    line <- getLine
    if null line
        then return ()
        else do
            putStrLn $ reverseWords line
            main  -- ← Recursive call!
```

**Key point:** `main` is itself an I/O action, so we can call it recursively!

## Essential I/O Functions

### Output Functions

#### `putStrLn` - Print with newline

```haskell
putStrLn :: String -> IO ()

main = do
    putStrLn "Hello"
    putStrLn "World"
-- Output:
-- Hello
-- World
```

#### `putStr` - Print without newline

```haskell
putStr :: String -> IO ()

main = do
    putStr "Hello "
    putStr "World"
-- Output: Hello World
```

#### `print` - Print any showable type

```haskell
print :: Show a => a -> IO ()

main = do
    print 42           -- "42"
    print [1,2,3]      -- "[1,2,3]"
    print True         -- "True"
```

**Equivalent to:** `print = putStrLn . show`

#### `putChar` - Print single character

```haskell
putChar :: Char -> IO ()

main = do
    putChar 'H'
    putChar 'i'
-- Output: Hi
```

### Input Functions

#### `getLine` - Read a line

```haskell
getLine :: IO String

main = do
    line <- getLine
    putStrLn $ "You said: " ++ line
```

#### `getChar` - Read a character

```haskell
getChar :: IO Char

main = do
    c <- getChar
    putChar c
```

**Note:** Due to buffering, `getChar` waits for Enter key.

## Utility Functions

### `when` - Conditional I/O

```haskell
when :: Bool -> IO () -> IO ()
```

**Instead of:**

```haskell
if condition
    then doSomething
    else return ()
```

**Use:**

```haskell
import Control.Monad

when condition doSomething
```

**Example:**

```haskell
main = do
    c <- getChar
    when (c /= ' ') $ do
        putChar c
        main
```

### `sequence` - Execute list of I/O actions

```haskell
sequence :: [IO a] -> IO [a]
```

**Example:**

```haskell
-- Verbose:
main = do
    a <- getLine
    b <- getLine
    c <- getLine
    print [a,b,c]

-- Concise:
main = do
    lines <- sequence [getLine, getLine, getLine]
    print lines
```

### `mapM` and `mapM_` - Map then sequence

```haskell
mapM :: (a -> IO b) -> [a] -> IO [b]    -- Keep results
mapM_ :: (a -> IO b) -> [a] -> IO ()    -- Discard results
```

**Example:**

```haskell
-- Print numbers 1-5
mapM_ print [1,2,3,4,5]

-- Same as:
sequence_ (map print [1,2,3,4,5])
```

**When to use:**

- `mapM` - when you need the results
- `mapM_` - when you don't care about results (more efficient)

### `forM` - mapM with flipped parameters

```haskell
forM :: [a] -> (a -> IO b) -> IO [b]
```

**Useful for readable loops:**

```haskell
import Control.Monad

main = do
    colors <- forM [1,2,3,4] $ \n -> do
        putStrLn $ "Color for number " ++ show n ++ "?"
        getLine
    putStrLn "Your colors:"
    mapM_ putStrLn colors
```

### `forever` - Infinite loop

```haskell
forever :: IO a -> IO b
```

**Example:**

```haskell
import Control.Monad
import Data.Char

main = forever $ do
    putStr "Input: "
    line <- getLine
    putStrLn $ map toUpper line
```

## Common Patterns

### Pattern 1: Read, Process, Print

```haskell
main = do
    input <- getLine                    -- Read
    let result = process input          -- Process (pure!)
    putStrLn result                     -- Print

process :: String -> String
process = map toUpper
```

### Pattern 2: Loop until condition

```haskell
main = do
    line <- getLine
    if null line
        then return ()                  -- Stop
        else do
            putStrLn $ reverse line
            main                        -- Continue
```

### Pattern 3: Collect multiple inputs

```haskell
main = do
    inputs <- forM [1..3] $ \i -> do
        putStrLn $ "Enter #" ++ show i
        getLine
    print inputs
```

## Important Concepts Review

### IO Actions are Values

```haskell
-- IO actions are just values
action1 :: IO ()
action1 = putStrLn "Hello"

action2 :: IO String
action2 = getLine

-- Can be passed to functions
performTwice :: IO a -> IO ()
performTwice action = do
    action
    action
```

### Type of `do` Block

**The type of a `do` block is determined by its last expression:**

```haskell
example1 :: IO ()
example1 = do
    putStrLn "Hello"
    putStrLn "World"  -- last: IO ()
    -- Block type: IO ()

example2 :: IO String
example2 = do
    putStrLn "Name?"
    getLine           -- last: IO String
    -- Block type: IO String

example3 :: IO Int
example3 = do
    line <- getLine
    return (read line)  -- last: IO Int
    -- Block type: IO Int
```

### Extracting vs Wrapping

```haskell
-- Extracting (IO → pure):
name <- getLine      -- IO String → String

-- Wrapping (pure → IO):
return 42            -- Int → IO Int
```

## Summary

**Key takeaways:**

1. **I/O actions are descriptions** - they don't perform I/O, they describe what to do
2. **`main` is special** - only I/O actions in `main` are executed
3. **`do` notation** - glues multiple I/O actions into one
4. **`<-` extracts** - takes value out of I/O action
5. **`return` wraps** - puts value into I/O action (doesn't stop execution!)
6. **`let` for pure** - use for non-I/O expressions in do blocks
7. **Type of do block** - determined by last expression
8. **Two worlds** - keep I/O and pure code separated

**Remember:**

- I/O actions are values
- `return` ≠ return in other languages
- `<-` extracts, `return` wraps
- Keep I/O minimal, logic pure
- Think "recipe" not "execution"
